## Round 1 (2026-09-29)

### Restated request and scope

Sectile Desktop still offers Gemini CLI and Cursor CLI as AI engine choices in
its settings, although the desktop no longer supports them as engines; those
choices must disappear from the desktop. Out of scope: the Cursor *editor*
(the "Open in editor" choice, #535), which is unrelated to AI engines, and any
change to the web app.

### Verified findings

Files read: `desktop/src/execution-fields.mjs`, `desktop/src/engines.mjs`,
`desktop/src/command-preview.mjs`, `desktop/src/editors.mjs`,
`desktop/src/main.js` (engine editor, execution defaults panel),
`internal/agentconfig/workstation.go`, `internal/agentconfig/engines.go`,
`internal/agentconfig/validation.go`, `internal/agent/agent_desktop_settings.go`,
`internal/runner/runner.go`.

- The engine editor's provider select already offers only AGY, Claude and
  Codex (`PROVIDERS` in `desktop/src/execution-fields.mjs`). A stored provider
  outside that list is added to the select rather than replaced.
- Gemini and Cursor still reach the desktop through three places:
  1. **Model lists** (Execution defaults): one row per provider the agent
     ships a list for. The agent's `DefaultProviderModels`
     (`internal/agentconfig/workstation.go`) still ships lists for `gemini`
     and `cursor`, and `workstationViewOf`
     (`internal/agent/agent_desktop_settings.go`) sends one row per shipped
     provider, so the desktop shows a `gemini` and a `cursor` row. This is the
     "models option" of the ticket.
  2. **Initialization provider** select (`desktop/src/main.js`): hard-coded
     `agy, claude, codex, cursor, gemini, vibe`.
  3. `KNOWN_COMMANDS` (`desktop/src/main.js`) still suggests a `gemini --model`
     command template.
- The agent keeps Gemini and Cursor as runnable providers: runner branches,
  MCP file locations, validation, the command preview and the engine icon
  letters. Removing them from the desktop does not require removing them from
  the agent.
- `DefaultProviderModels` also serves launches: a gemini or cursor engine that
  already exists on a workstation gets its model list from it.

### Reversible choices resolved from the code

- The Cursor editor entry in `desktop/src/editors.mjs` stays: it opens a
  worktree, it is not an engine.
- A workstation that already stores a custom gemini or cursor model list, or
  an engine with such a provider, keeps seeing it, following the existing
  `PROVIDERS` rule ("added to the select rather than silently replaced").
- The engine icon letters (`Ge`, `Cu`) and the command preview stay, since
  they render stored engines.

### Dependencies

None: no migration, no server change, no third party.

### Open product questions

1. **Scope of the removal.** (a) Desktop only: stop shipping gemini and
   cursor model lists to the desktop and drop them from the desktop selects,
   while the agent can still run an existing gemini or cursor engine;
   (b) drop Gemini and Cursor support entirely (agent runner, validation,
   MCP setup, web types). **Recommended: (a).**
2. **Vibe in the initialization provider select.** The select also offers
   `vibe`, which is not an engine choice either. (a) Remove only gemini and
   cursor, as the ticket says; (b) align the select on the engine providers
   (agy, claude, codex). **Recommended: (b).**

## Round 2 - answers from the owner (2026-09-29)

### Answers

1. **Scope: full removal (b).** Gemini CLI and Cursor CLI stop being AI
   providers of Sectile everywhere, not only on the desktop.
2. **Initialization provider: aligned on agy, claude, codex (b).**

### Reversed assumptions

- Round 1 recommended a desktop-only removal and kept the agent able to run
  an existing gemini or cursor engine. That is reversed: the agent, its
  validation, its launch paths and the web lose both providers.
- Round 1 kept showing a stored gemini or cursor model list or engine. With
  the providers gone, such stored values can no longer be shown or run; what
  happens to them is question 3 below.

### Settled decisions

- Removed providers: `gemini` and `cursor`, in the agent (engine catalogue,
  validation, `DefaultProviderModels`, runner and console launch lines, model
  flags, MCP registration targets), the desktop (model lists, initialization
  select, `KNOWN_COMMANDS`, command preview, engine icon letters) and the web
  (the `AIProvider` type, the command template, the MCP configuration list in
  `shared/mcpConfig.mjs`).
- Kept, because they are not the Gemini CLI or Cursor CLI provider:
  - the Cursor **editor** ("Open in editor", #535);
  - every `~/.gemini/...` path used by Antigravity (`agy` lives under
    `~/.gemini/config`), and the `.gemini` skill directories that serve it;
  - model names containing `gemini` offered for `agy`;
  - the retirement list `checkoutMCPFiles`, which only removes what earlier
    releases wrote: `.gemini/settings.json` and `.cursor/mcp.json` stay in it
    so an old checkout is still cleaned.
- The initialization provider select offers `agy`, `claude` and `codex`,
  matching the engine editor's `PROVIDERS`.

### New dependencies

- A workstation's `settings.json` and the server's project records can still
  name `gemini` or `cursor` (engine provider, project `aiProvider`, stored
  model lists, MCP connection targets). Validation that refuses them would
  make those files unreadable unless they are migrated first.
- `docs/contracts/server-agent-v1.md` lists `cursor` and `gemini` among the
  accepted providers and has to follow.

### Open product questions

3. **Stored gemini or cursor settings on an existing workstation.**
   (a) The agent drops them when it loads its settings: a gemini or cursor
   engine is removed as if the owner had removed it (its projects fall back
   to the workstation default engine, its tasks to their project default),
   stored gemini/cursor model lists and MCP connections are discarded, and
   the agent logs what it dropped; (b) the agent turns such an engine into a
   `custom` engine keeping its command line, so it still runs;
   (c) the agent refuses the settings and asks the owner to fix them.
   **Recommended: (a).**
4. **Vibe.** The initialization select loses `vibe`, but the agent still
   knows `vibe` as an engine provider (runner, catalogue). (a) Vibe stays a
   supported provider, only the select changes; (b) Vibe is removed like
   Gemini and Cursor. **Recommended: (a)**, since the ticket does not name it.

## Round 3 - answers from the owner (2026-09-29)

### Answers

3. **Stored gemini, cursor (and now vibe) settings: dropped on load (a).**
4. **Vibe: removed too (b).**

### Reversed assumptions

- Round 2 recommended keeping Vibe as a supported provider. Reversed: Vibe
  (Mistral Vibe CLI) is removed like Gemini and Cursor.

### Settled scope

The providers Sectile supports after this ticket are `agy`, `claude`,
`codex` and `custom`. `gemini`, `cursor` and `vibe` are removed:

- **Agent**: engine catalogue (`engineProviders`, provider display names),
  validation, `DefaultProviderModels`, model flags, runner and console launch
  lines (autonomous and interactive), spec-framework provider mapping, MCP
  registration targets and migrations, `sectile agent init --provider`
  examples and the runtime error message that lists the supported engines.
- **Desktop**: model lists (they follow the agent's shipped lists), the
  initialization provider select (now `agy`, `claude`, `codex`),
  `KNOWN_COMMANDS`, the command preview and the engine icon letters.
- **Web**: the `AIProvider` type, the command template and the MCP
  configuration list in `shared/mcpConfig.mjs`.
- **Docs**: `docs/contracts/server-agent-v1.md`, the READMEs where they list
  providers, and one `CHANGELOG.md` line under `Removed`.

Stored values on an existing workstation are dropped when the agent loads its
settings, as if the owner had removed them: a gemini, cursor or vibe engine
disappears (its projects fall back to the workstation default engine, its
tasks to their project default engine), stored model lists and MCP
connections for those providers are discarded, and the agent logs what it
dropped. A project whose server-side provider names one of them resolves like
a project with no engine, to the workstation default engine (reversible
technical choice, same rule).

Kept: the Cursor editor (#535); Antigravity's `~/.gemini/...` paths and the
`.gemini` skill directories; `gemini-*` model names offered for `agy`; the
retirement list `checkoutMCPFiles` (including `.gemini/settings.json`,
`.cursor/mcp.json`, `.vibe/config.toml`) so old checkouts are still cleaned.

### Open product questions

None, subject to the owner's confirmation that this scope is right.
