# Clarification report: #904 - We should be able to have a form to ask question with proposal to the user

Ticket: https://github.com/sebastienferry/sectile/issues/904 (no description, parent: macro)

## Round 1 - initial analysis (2026-11-15)

An earlier Round 1 was written on 2026-11-15 but never committed (Git refused the
index lock) and its file is not in this worktree. Only its summary was published as
a ticket comment. This section rebuilds it from that summary and a fresh reading of
the code; the three open questions are the same.

### Restatement

When an agent needs a decision from the owner, Sectile should present the question
as a form with proposed answers (choices, a recommended option, a free answer)
rather than as plain text, and send the selected answer back to the agent.
Out of scope: changing how a skill decides what to ask, and any tracker-side form
(GitHub/Jira) for unattended runs, unless the owner brings it into scope.

### What already exists

- Native Desktop conversations already render such a form:
  - Tauri: `desktop-tauri/src/components/QuestionForm.tsx`, wired in
    `desktop-tauri/src/components/ProjectPrompt.tsx:381-384` for an `AskUserQuestion`
    approval (radio / checkbox options with descriptions, "Other answer" free text,
    secret answers, "Skip request", 16 KB bound).
  - Electron: `desktop/src/conversation.js:290,318-` (`questionForm`).
  - Agent side: `internal/agent/agent_conversation_approvals.go:103-325` (Claude
    `AskUserQuestion` answers, validated by `checkAnswers`) and
    `internal/agent/agent_codex_conversation.go:98-100,905` (Codex
    `requestUserInput`, mapped to the same approval).
- `report_waiting` (`internal/taskmcp/server.go:106`, `internal/agentmcp/mcp.go`)
  only flags a run as waiting: it carries no question and no proposed answers.
- Related #879 proposes displaying the waiting question; it does not provide answers.

### Ambiguities (worst first)

1. **Which surface lacks the form.** Native conversations have it. Runs launched in
   a terminal (`SECTILE_REMOTE_MODE`, the Claude/Codex CLI in a native terminal, as
   this very run) ask in the terminal, and the board/web only see "waiting". Reading
   A (extend to terminal-launched runs, via a question payload on `report_waiting`
   or a new MCP tool, answered from Desktop/web) and reading B (polish the existing
   native form) lead to entirely different code.
2. **Answer controls.** Single/multiple choice, a highlighted recommended option,
   free text, per-question skip: which are required.
3. **Submission, skip and resumption.** Whether the answer goes back to a live
   session only, or is also stored (on the run, or as a ticket comment) so that a
   later run or an unattended run can resume from it.

### Critical dependencies

- A terminal-launched CLI cannot receive an answer from Desktop unless the agent
  polls for it (a blocking MCP tool call that waits for the answer); the Claude CLI
  MCP call timeout bounds how long such a call can wait.
- #879 (waiting-question display) overlaps reading A; the two should share one
  question payload.
- The web app (`web/src`) has no question form today.

### Technical choices resolved from the code

- Reuse the existing question shape (`questions[] { question, header, options[]
  { label, description }, multiSelect }`) and the existing `QuestionForm`
  component rather than a new schema.
- Keep the 16 KB answer bound and the "do not echo secret answers" rule.
- Runtime UI strings stay in the language the surface speaks (English in
  desktop-tauri today).

### Open product questions (owner)

1. Which surfaces and execution modes must show the form? Recommended: terminal-launched
   (remote) skill runs answered from the Desktop task view, sharing #879's payload.
2. Which answer controls are required? Recommended: the existing set (single/multi
   choice, option descriptions, free answer) plus a marked "(Recommended)" option.
3. What happens on submission, skip and resumption? Recommended: the answer is
   returned to the waiting agent and also recorded on the run's activity; skip
   returns "skipped" to the agent; no ticket comment.
