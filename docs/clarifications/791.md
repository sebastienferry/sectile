# Clarification #791 - Desktop: merge requests in a drop-down list

Ticket: https://github.com/sebastienferry/sectile/issues/791

## Round 1 - initial report (2026-10-07)

### Request

When a task holds pull requests or merge requests in several repositories,
Sectile Desktop shows them as a row of buttons side by side in the console
toolbar; it should instead show one control that opens a drop-down list of
them. Out of scope: the web client, the server and its `prLinks` model, how
pull request states are fetched, and the single-pull-request case, which keeps
its current button.

### Where "side by side" happens today

| Surface | Today | Affected |
| --- | --- | --- |
| Console toolbar | primary button `PR #79`, then one button per other repository (`repo PR #12`) | yes, this is the reported layout |
| Sidebar run row | one state icon, then a passive `+N` badge whose tooltip lists the others | to decide (Q1) |
| Tickets table | same icon + `+N` badge | to decide (Q1) |

### Ambiguities, worst first

1. **Which surfaces change.** The toolbar is the only place where pull
   requests sit side by side. The sidebar and tickets table already collapse to
   one icon and a `+N` badge, but that badge is not clickable: the other pull
   requests can only be read in its tooltip, not opened. Turning the badge into
   a drop-down is a different change in two more places. (Q1)
2. **Click behaviour of the control.** A split control (the primary pull
   request stays a one-click button, a chevron next to it opens the list) keeps
   today's fastest path; a single button that always opens the list costs one
   more click for the common case. (Q2)
3. **What the list contains.** `repositoryPullRequests` keeps only the current
   pull request of each repository. A task can also hold superseded pull
   requests on the same repository (a follow-up after a merged one). Listing
   them all changes the data shown, not only the layout. (Q3)

### Critical dependencies

None. The change is confined to the desktop renderer: no server, API,
migration or tracker change. `desktop/tests/pr-repositories.ui.cjs` must be
rewritten, since it asserts the side-by-side buttons; the desktop UI tests
need a `vite build` first and run unsandboxed.

### Technical choices settled from the code

- **Threshold:** the drop-down appears as soon as the task has two or more
  pull requests to show; a single one keeps today's button unchanged.
- **Widget:** a custom menu, not a native `<select>`. The execution history
  uses a `<select>`, but an `<option>` cannot carry the coloured state icon
  every pull request shows today. The toolbar already has the pattern to reuse:
  the `#worktree-folders` chevron (`aria-haspopup="menu"`, `aria-expanded`)
  with its `role="menu"` `.folder-menu`, with the same keyboard and
  outside-click closing.
- **Menu entries:** each entry keeps what a button shows today: the state icon
  and colour from `renderPullRequestIndicator`, the repository name for the
  non-primary repositories, the `PR #n` / `MR !n` label, the state in the
  tooltip. Choosing an entry opens it through `api.openPR`, as the buttons do.
- **Order:** primary repository first, then the others in the order
  `repositoryPullRequests` returns, as today.
- **Label of the chevron:** carries the count of the other pull requests
  (`+2`), so the toolbar still says there are more without listing them.

### Open product questions (owner)

1. **Q1 - Surfaces.** Recommended: **the console toolbar only**; the sidebar and
   tickets table keep their compact `+N` badge with its tooltip. Alternative:
   also make that `+N` badge open the same drop-down in the sidebar and the
   tickets table.
2. **Q2 - Click behaviour.** Recommended: **split control**: the primary pull
   request remains a one-click button, a `+N` chevron next to it opens the
   list of all of them (primary included). Alternative: a single button that
   always opens the list.
3. **Q3 - Contents.** Recommended: **the current pull request of each
   repository**, as shown today. Alternative: every pull request the task ever
   held, superseded ones included.
