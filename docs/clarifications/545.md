# Clarification: #545 Global and project config full page

## Round 1 - initial analysis (2026-09-26)

### Requested outcome

The desktop application must open both the workstation-wide Settings view and a
project's configuration view as full-page application surfaces instead of
modal dialogs. Each surface must offer a back button that returns to the main
desktop page.

This change does not alter the settings categories, editable fields, saved
values, server calls, validation, or project-disconnection behavior. It also
does not make unrelated dialogs full-page views.

### Existing implementation reviewed

- `desktop/src/main.js`: `showDialog()` manages the shared modal lifecycle;
  `openSettings()` builds the workstation settings interface; `openProject()`
  builds the project configuration interface.
- `desktop/src/style.css`: dialog dimensions, the shared settings layout, and
  the project configuration footer are currently modal-scoped.
- `desktop/README.md`: documents the two settings surfaces and their existing
  behavior.

### Settled decisions

1. The global Settings view and Project configuration view are the only
   surfaces that move from the shared modal dialog to a full-page view.
2. Entering either view replaces the main desktop content for that view; it is
   not a maximized modal dialog.
3. A visible, keyboard-accessible back button returns to the normal main
   desktop page. It replaces the modal close affordance for these two views.
4. Existing settings categories, selected-default behavior, asynchronous data
   loading, controls, save actions, and responsive layout continue to work in
   the full-page surface.
5. Project configuration continues to keep its save action available only for
   categories that persist local configuration; server and deployment panels
   remain read-only/action panels as today.
6. Other dialogs retain the current modal behavior and close control.

### Dependencies and risks

- No migration, remote API, or third-party dependency is required.
- The implementation must preserve dialog cleanup semantics for the unrelated
  modal flows and avoid rendering late asynchronous results into a view that
  has already been left.
- The desktop navigation state must restore the normal main view without
  losing the selected project or active task state.

### Acceptance baseline

- Opening Settings shows its existing categories in a full-page view and a
  back button returns to the main desktop page.
- Opening Project settings shows its existing categories in a full-page view
  and a back button returns to the main desktop page.
- Settings and project configuration retain their current save, validation,
  responsive-layout, and asynchronous-loading behavior.
- Existing non-settings dialogs continue to open and close as modal dialogs.

### Open questions

None. The ticket defines the product direction, and all remaining choices are
reversible implementation details governed by the existing desktop UI
conventions.
