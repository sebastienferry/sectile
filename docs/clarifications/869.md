### Existing neighboring behavior

The project context menu already offers Project prompt, disabled without a mapped path. Its dialog selects a named catalogue engine (including provider, model and project-default indication), defaults to the project engine and launches through launchConsole. The chosen engine applies to this launch only. The agent uses the mapped checkout and project folders, creating a taskless console or a supported structured conversation according to the existing view preference. The global PROJECTS plus button currently adds a remote project.

### Ambiguities, highest impact first

1. Does project prompt mean opening the existing interactive session, or composing and submitting an initial instruction before launch? These require different UI and potentially different launch contracts.
2. Does the plus belong on every project row, or at a global location with project selection? These require different project selection and button behavior.

### Recommended reversible technical choices

- Reuse openAgentConsole, the workstation engine catalogue, existing IPC and agent launch contract.
- Interpret agent profile as an existing named engine configuration, rather than adding a new profile concept.
- Keep the current project default preselection and launch-only override; retain existing console/conversation preference.
- Retain the Project prompt context-menu action and existing missing-path restriction.
- Follow existing accessible project-row action and keyboard-focus conventions.
- Add a user-facing changelog entry when implementing the shortcut; no production code is changed in clarification.

These recommendations are proposals, not owner-confirmed acceptance criteria.

### Critical dependencies

A mapped local project checkout, a reachable local agent and available engine configuration are required by the existing launch path. Catalogue support has a legacy provider-selector fallback in the current dialog. No new service, schema migration, third-party API or infrastructure change is indicated by the proposed reuse.

### Essential owner questions

Alternative: a global button with project selection, or a change to how profile defaults are stored.
2. Should launch open an empty interactive console/conversation where instructions are entered afterwards? Recommended: yes, reuse the current flow. Alternative: add a prompt text field before launch and submit that instruction automatically.

## Round 2 - answers from the owner (2026-10-26)

### Settled decisions

- Add a plus button next to each project, opening the project-session launch dialog.
- The selection applies only to the new session.
- The user enters their request in the console/conversation after launch; no initial-request composer is required.
- A profile represents a preconfigured agent whose prompt is stored in the project's repository.

### Reversed assumption and code impact

Round 1 incorrectly equated an agent profile with a workstation engine configuration. A repository agent prompt is a separate concept from the CLI provider/model catalogue. The existing openAgentConsole flow and desktopConsole endpoint select an engine but do not carry a repository agent-profile selection. Reuse therefore needs to be reassessed during specification; this is more than a shortcut to the current engine selector.

A targeted search in internal, desktop/src and docs found no existing repository agent-profile registry to reuse. This does not establish a required storage format.

### Proposed technical baseline

Keep engine selection and agent instructions distinct. Discover named prompt files in a project-owned repository directory; choose the exact path and format during technical specification, following any established project convention identified there. Load the selected prompt into the new session as its agent instructions while preserving applicable repository instructions. Do not change the project's default configuration for a single-session selection.

### Essential remaining product question

Should this ticket only discover/select prompts already written in repository files (recommended), or must Desktop also provide creation/editing of those agent prompts? This changes the feature scope and acceptance criteria.

## Round 3 - answers from the owner (2026-10-26)

### Settled scope

- Add a plus button beside each Desktop project to open the project-session launch dialog.
- Allow selecting a project agent profile for the new session only.
- An agent profile is a preconfigured agent with its prompt stored in the project's repository, distinct from the workstation engine/provider/model configuration.
- Allow creating an agent profile directly in Desktop and saving its prompt in the project's repository, making it available for selection.
- Start the session with the selected agent instructions loaded. The user types their task/request afterwards in the console/conversation; no initial-request composer is required.
- Do not change the project's default profile or engine as a side effect of a single-session selection.

### Scope boundaries and technical choices

Direct creation is now in scope, reversing Round 1's proposed exclusion. Editing/deleting existing profiles, automatically committing or pushing profile files, and creating a task are not included in the agreed request. Exact repository location, file format, name validation and provider-specific loading are technical specification decisions. Creation must write into the selected project's repository and report save failures without claiming success.

### Dependencies and verification baseline

Implementation must connect repository profile discovery and creation to Desktop and load the chosen prompt through supported console/conversation launch paths. Reusing the current engine picker alone is insufficient. Preserve applicable repository instructions, existing project-folder context and launch error reporting. A missing checkout or failed save must not produce a falsely successful profile creation. Include a user-facing changelog entry when implementing.
