## Round 1 — analysis (2026-09-22)

### Restated request and scope

`make build` prints a block of `npm warn ERESOLVE` lines during `cd web && npm ci`,
reporting that `@emoji-mart/react@1.1.1` wants `react@"^16.8 || ^17 || ^18"` while the
project is on `react@19.2.8`; this ticket is about removing that condition from the
build output at its cause. Out of scope: upgrading or downgrading React, changing which
icons the UI shows, the `desktop/` and Dockerfile install steps unless question 3 opens
them, and the unrelated stray root `package-lock.json` noted under *Dependencies*.

### Files read

- `Makefile` (`build-all` → `build-server` → `web-deps`, `web/node_modules/.install-stamp` rule, line 29)
- `web/package.json` (dependencies, `engines.node >= 22.18.0`)
- `web/package-lock.json` (`node_modules/@lobehub/icons`, `node_modules/@lobehub/ui`, `node_modules/@emoji-mart/react`, root `packages[""]`)
- `web/src/components/ApiKeys.tsx`, `MCPEngineConfig.tsx`, `ProfileModal.tsx`, `ProjectModal.tsx` (every `@lobehub` import in the tree)
- `node_modules/@lobehub/icons/package.json`, `es/index.js`, `es/Claude/components/*.js` (installed copy, main checkout)
- `Dockerfile` (line 14, `npm ci --no-audit --no-fund`)
- `AGENTS.md` (§4 — the two `package-lock.json` files a release bumps)

### Verified findings

1. **Reproduced, and it is not an error.** On `feat/344` with node 26.9.0 / npm 11.13.0,
   `npm ci --dry-run` in `web/` emits the reported block verbatim and **exits 0**
   (`added 518 packages`). Every line the ticket pastes is prefixed `npm warn`; there is
   no `npm error` and `make build` does not fail. The defect is build-output noise and
   an unused dependency tree, not a broken build.

2. **The full cause chain.** `@lobehub/icons@5.18.0` — a direct dependency of
   `web/package.json` — declares the **non-optional** peers `@lobehub/ui@^5.0.0` and
   `antd@^6.1.1` (`peerDependenciesMeta: null`). npm 7+ installs non-optional peers
   automatically, so `@lobehub/ui@5.48.0` enters the tree marked `"peer": true`. Its own
   *dependency* `@emoji-mart/react@^1.1.1` declares `peer react@"^16.8 || ^17 || ^18"`,
   which cannot be satisfied by `react@19.2.8`. npm overrides the peer and warns. Nothing
   in `web/src` asks for any of it.

3. **None of it reaches the bundle.** `@lobehub/icons/es/index.js` re-exports only
   `./features`, `./hooks/useFillId`, `./icons` and `./toc`. `@lobehub/ui` is imported
   exclusively from `es/components/*` (`Dashboard`, `Editor`, `DownloadButton`,
   `DocsPreview`…), which the barrel never re-exports, and from the `.mdx` doc files.
   The import chain of an icon the project actually uses (`es/Claude/components/*.js`)
   reaches only `react`, `../../features/*` and `../style`. `@emoji-mart/react` is
   reachable only through `@lobehub/ui`, so it is dead weight in `node_modules` and
   absent from the vite output.

4. **What the noise costs.** `web/src` imports exactly four icons — `Antigravity`,
   `Claude`, `OpenAI`, `Cursor` — across four files. Satisfying the icons package's peer
   declaration pulls `@lobehub/ui` with `antd`, `@ant-design/*`, `emoji-mart`,
   `@splinetool/runtime`, `leva`, `shiki`, `katex` and `beautiful-mermaid`, a large share
   of the 518 installed packages, for zero bundled bytes.

5. **The Makefile is not implicated.** The `web/node_modules/.install-stamp` rule and the
   `web-deps` prerequisite behave as documented; they simply relay npm's output.

### Dependencies and constraints

- Behaviour is npm's, not the repo's: automatic installation of non-optional peers is
  npm ≥ 7. `legacy-peer-deps` and `strict-peer-deps` are both `false` here (defaults).
- Node 26.9.0 against `engines.node >= 22.18.0` is satisfied and is not a factor.
- `Dockerfile:14` runs the same `npm ci` with `--no-audit --no-fund`, which does not
  suppress ERESOLVE — the image build carries the identical warnings.
- The repository has no `.github/workflows/`; the build is driven by the Makefile,
  the Dockerfile and `.gitlab-ci.yml`.
- Any change to `web/package.json` requires regenerating `web/package-lock.json`, whose
  `version` field AGENTS.md §4 ties to the release procedure — it must stay at `0.1.0`.
- Unrelated, reported not fixed: the repository root holds a `package-lock.json` named
  `taskflow` with zero packages and no matching `package.json`. Nothing installs from it.

### Reversible technical decisions (taken here)

- **Not `legacy-peer-deps=true` in an `.npmrc`.** It silences peer resolution for the
  whole project and would hide a future genuine conflict. Suppressing the symptom
  repository-wide is the wrong shape for a warning whose cause is identified.
- **Not a Makefile-only `--loglevel=error`.** `Dockerfile:14` would keep printing the
  block, so the noise would only move.
- **Keep the `.install-stamp` incremental mechanism unchanged**; it is not part of the
  defect.
- If the fix edits `web/package.json`, regenerate the lockfile with `npm install` (not by
  hand) and leave the manifest `version` untouched.

### Open product questions

1. **What does "fixed" mean here?** The build already succeeds. Is the deliverable
   (a) a silent `npm ci`, (b) an actually smaller dependency tree, or (c) both?
   *Recommendation: (c) — remove the unused peer tree, which makes the warning disappear
   as a consequence rather than as a mask.*

2. **Which mechanism?** Four candidates, each a different change:
   (i) an `overrides` entry in `web/package.json` relaxing `@emoji-mart/react`'s react
   peer; (ii) dropping `@lobehub/icons` and vendoring the four SVG icons the UI uses;
   (iii) pinning an older `@lobehub/icons` whose peers are optional; (iv) accepting the
   warning and closing the ticket as won't-fix.
   *Recommendation: (ii) — four icons do not justify a peer tree of that size, and it is
   the only option that removes the cause instead of annotating it. (i) is the fallback
   if vendoring the icons is unacceptable.*

3. **Blast radius.** Fix `web/` only, or also audit `cd desktop && npm ci` (Makefile:33)
   and the Dockerfile install for the same class of warning?
   *Recommendation: fix `web/` in this ticket, and report any `desktop/` finding as a
   separate issue rather than widening this one.*

4. **Should a genuine ERESOLVE conflict fail the build in future?** Adding
   `--strict-peer-deps` to the `npm ci` invocations would turn overridden peers into hard
   errors, so the next occurrence stops the build instead of scrolling past.
   *Recommendation: not in this ticket — it is a policy change that can break the build on
   an unrelated upgrade, and it deserves its own decision.*

5. **Visual regression tolerance.** If question 2 resolves to vendoring, the four brand
   icons would be local SVG components instead of `@lobehub/icons` renderings. Is a
   pixel-level difference acceptable, or must the marks be reproduced exactly?
   *Recommendation: exact marks, copied from the package's own SVG output, so nothing
   visible changes.*
