### Reversible technical choices (settled from the code)

1. **No defensive guard in `epicColorsEnabled`.** Its parameter is typed
   `readonly Pick<Project, ...>[]`, the real provider always supplies an array,
   and a guard would hide an incomplete mock instead of failing loudly. Nothing
   a user sees changes, so no changelog entry.
2. **The fixture gives `projects: [{ id: 'p', epicColors: true }]`** and a
   matching `currentProject`, and one fixture task gets a `parentKey`, so the
   test also asserts that the epic bar is drawn on that row only. This covers
   the #388 code path the fixture now traverses rather than just silencing it.
