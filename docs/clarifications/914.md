# Clarification #914 - Tauri: inline composer queue strip with edit-back action and single-line context tray

Ticket: https://github.com/sebastienferry/sectile/issues/914

## Round 1 - initial analysis (2026-11-17)

### Restated request

In Sectile Desktop (Tauri), queued follow-up messages move from the standalone
`QueuedMessages` block above the status strip into a strip at the top of the bordered
`.composer-box`, which gains an **Edit** action that takes a queued message out of the
queue and puts its text back into the composer; with more than one queued message the
strip shows a count and expands into the full list. The folders the conversation uses
are also shown as compact single-row pills at the top of the composer box, with a
`+N more` / `Show less` toggle when they overflow.

Out of scope: the Electron desktop (`desktop/`) and the web client; "steer now"
(claudian's immediate-steering action); any change to how the queue is dispatched,
paused or persisted; adding or detaching folders from the pills (the existing folder
popover keeps that role).

### Ambiguities (worst first)

1. **"Per-turn context items" do not exist in the Tauri client.** There is no file,
   image or selection attachment per turn; the only context is folders (working folder,
   folders attached to the project, configured context repositories and specification
   folders). Reading A: the tray shows those folders, built generically so a future
   per-turn item slots in. Reading B: build a per-turn attachment feature as well.
   Product question Q2.
2. **Edit when the composer already holds a draft.** Replace it (loses typed text),
   merge with it (claudian's behaviour) or disable Edit while a draft exists.
   Product question Q1.
3. **Turn options of a queued message.** Each queued item keeps the model/effort
   options chosen when it was queued. On Edit, either restore them into the turn
   settings with the text, or drop them and let the current settings apply on resend.
   Product question Q3.
4. **Read-only conversations.** A stopped conversation renders no composer box, yet its
   queue can still hold unsent messages ("Not sent: this conversation is stopped").
   Resolved technically below.
5. **Collapsed strip content with more than one item.** Resolved technically below.

### Dependencies

- None on the agent, the server or migrations: the queue is client state in
  `conversation-controller.ts`, and folder data already comes from `useFolders` and the
  run's `folders`.
- Layout measurement needs `ResizeObserver`; tests run in jsdom, where layout is not
  computed, so the overflow logic must be testable with stubbed geometry
  (`offsetTop` / `getBoundingClientRect`), as claudian's tray does.

### Technical choices resolved from the code and conventions

- **Edit is a new controller method** (`withdrawQueued(id)`) built on `remove()`: it
  refuses a `sending` item exactly like Remove, works on `queued` and `failed` items,
  and lets `settle()` drop the pause when the queue empties. The composer focuses the
  textarea after restoring.
- **Collapsed strip** (any count): `Queued` tag, the single-line truncated preview of the
  head item (the next one to be sent, CSS ellipsis rather than a 40-character cut), its
  status when not plain `queued` (`Sending…`, `Failed: …`), and Edit / Remove icon
  buttons acting on the head item. With `> 1` items, a count and a chevron toggle open
  the full list inside the strip, each row keeping position, status, Copy, Edit and
  Remove. Copy stays available on the head item too, so nothing the current block
  offers is lost.
- **Pause, resume and failure** move into the strip header unchanged: the
  `Queue paused · <reason>` status and the Resume button stay visible collapsed or
  expanded.
- **Read-only conversations** keep the current standalone queue block (count, "Not sent:
  this conversation is stopped", Copy), without Edit and Remove, since there is no
  composer to edit into.
- **Context tray** appears in both composers (new conversation and conversation), above
  the textarea and below the queue strip. It lists the same entries as the folder
  popover (Working folder first, then attached, context and specification folders), as
  24 px pills showing the folder name, full path in the tooltip, click copies the path.
  The existing folder button in the footer stays for "Add folder", Finder and the full
  list. The tray is hidden when there is only the working folder, so a conversation
  with no extra context gets no extra row.
- **Overflow**: rows measured from the pills' positions after render and on resize
  (`ResizeObserver`); pills past the first row are hidden and a `+N more` button shows;
  expanded, the button reads `Show less`. The tray re-collapses when its entries change.
- **Visible strings** stay in English, as the Tauri UI already is.
- **CHANGELOG**: user-visible, so one `Added`/`Changed` line under `[Unreleased]`.

### Product questions (owner: Sébastien Ferry)

- **Q1 - Edit with a non-empty draft.** Recommended: merge - the queued text is appended
  after the current draft, separated by a blank line, so nothing typed is lost.
  Alternatives: replace the draft; disable Edit while the draft is not empty.
- **Q2 - Scope of "per-turn context items".** Recommended: folders only (working,
  attached, context, specification), with a tray generic enough for future per-turn
  items. Alternative: also build per-turn file/image attachments in this ticket.
- **Q3 - Turn options on Edit.** Recommended: restore the queued item's model/effort
  options into the turn settings along with the text, so resending reproduces what was
  queued. Alternative: restore the text only and keep the current settings.

## Round 2 - answers from the owner (2026-11-17)

Answers given interactively by Sébastien Ferry; every recommended option was chosen.

### Settled decisions

- **Q1 - Edit with a non-empty draft: merge.** The queued text is appended after the
  current draft, separated by a blank line; an empty draft simply receives the text.
  Nothing typed is lost, and Edit stays enabled whatever the draft holds.
- **Q2 - Context tray scope: folders only.** The tray shows the working, attached,
  context and specification folders. No per-turn file, image or selection attachment is
  built here; the tray takes a generic list of items (label, icon, tooltip, action) so a
  future per-turn item can join it without reworking the layout. The ticket's "per-turn
  context items" acceptance wording is read as "context folders".
- **Q3 - Turn options on Edit: text and options.** Edit restores the queued item's
  `options` (model, effort and the other turn settings it carried) into the composer's
  turn settings along with the text, so queueing it again reproduces what was queued.
  When Edit merges into a non-empty draft, the restored item's options still replace the
  current turn settings.

### Reversed assumptions

None. The Round 1 technical choices stand unchanged.

### New ambiguities or dependencies

None surfaced.

### Settled scope (summary for the specification)

1. Queue strip inside the top of `.composer-box` (conversation composer): `Queued` tag,
   single-line preview of the head item, its status, Copy / Edit / Remove; with `> 1`
   items a count and an expand/collapse toggle listing every item with position, status,
   Copy, Edit, Remove; pause reason and Resume in the strip header.
2. Edit = `withdrawQueued(id)`: refused on `sending`, allowed on `queued` and `failed`,
   merges text into the draft, restores turn options, focuses the textarea; the pause
   drops once the queue is empty.
3. Read-only conversations keep the standalone queue block, Copy only.
4. Context tray in both composers: 24 px folder pills, one row by default, `+N more` /
   `Show less` overflow toggle measured on render and resize, re-collapses on change;
   hidden when only the working folder exists; the footer folder popover stays.
5. Tests: unit tests on `withdrawQueued` and merge/options restoration; UI tests on
   edit-back, multi-item expand/collapse with pause/resume and failure, and tray
   overflow with stubbed geometry. One CHANGELOG line under `[Unreleased]`.
