## Round 1 - initial report (2026-09-29)

### Restated request and scope

While a ticket is being created from the quick-add dialog, its submit button
reads "Création CLI...". The ticket asks why, and asks for a label that says
what is actually happening, in both interface languages. Out of scope: any other
wording in the dialog, the other creation paths (they show no such label), and
any change to how a ticket is created.

### Why the button says "Création CLI"

- The label is hard-coded at `web/src/components/QuickAddModal.tsx:538`, shown
  only while `isSubmitting` is true. `git blame` and `git log -S` place it in
  the initial commit (`56eb340b`, 2026-08-23), and nothing has touched it since.
- No CLI is involved. `handleSubmit` calls `createTask` in
  `web/src/context/AppContext.tsx:2244`, which sends `POST /api/tasks` to the
  server (`cmd/server/main.go:283`); the server creates the ticket through the
  project tracker's API. No `gh`, `glab` or `acli` command is run for it.
- "CLI" is therefore a leftover from an early prototype, and the string also
  bypasses the locale files: an English interface shows it in French.

### Files read

- `web/src/components/QuickAddModal.tsx` (submit handler and footer)
- `web/src/context/AppContext.tsx` (`createTask`)
- `web/src/locales/translations.ts` (`taskModal` and `quickAdd` types and the
  French and English values)
- `web/src/locales/projectSettings.ts`, `web/src/locales/taskDetail.ts` and
  `web/src/locales/signIn.ts`, for how in-progress labels are worded elsewhere
- `cmd/server/main.go` (the `/api/tasks` route)

The desktop app has no quick-add dialog of its own (`git grep QuickAddModal`
finds only `web/src`), so the fix is web-only.

### Ambiguities

None that change the code: the only choice is the wording of the in-progress
label, settled below.

### Dependencies

None: no API, migration or tracker change.

### Resolved technical choices

1. The label moves into the locale files as a new key `quickAdd.creating`, in
   the `Translations` type and in both the French and English values, and
   `QuickAddModal.tsx` reads it from `t`. It belongs to `quickAdd` rather than
   `taskModal` because only this dialog uses it.
2. Wording, settled by the owner: **`'Création…'`** in French and
   **`'Creating…'`** in English. The tracker is not named: the success toast
   already says where the ticket landed. This reverses the round's first
   proposal, `'Création de la tâche…'` / `'Creating the task…'`.
3. The fix is visible to users, so it adds a `Fixed` line under
   `## [Unreleased]` in `CHANGELOG.md`.

### Open questions

None. The owner answered the only question, the wording of the in-progress
label, with "Création…" (choice 2), adding "but with translation": the
label must go through the locale files in both languages, as choice 1 already
provides, never as a hard-coded French string. This settles the clarification.
