# Clarification #916 - Tauri: / and $ command/skill autocomplete, inline command chips, and ! shell indicator

Ticket: https://github.com/sebastienferry/sectile/issues/916
Branch: `feat/916`

## Round 1 - initial analysis (2026-11-17)

### Request

The Sectile Desktop (Tauri) conversation composer gains three things the
Electron client and the local agent already support underneath: a floating
`/` (Claude, Antigravity, Codex built-ins) and `$` (Codex skills) completion
menu fed by the conversation snapshot's `commands`, an inline chip for a
completed command or skill token that deletes atomically on `Backspace`, and a
visual shell-mode indicator when the draft starts with `!`. Out of scope: the
local agent and its command discovery (already done), the Rust bridge, the
Electron client (`desktop/`), the web UI, the project "Free prompt" composer
that exists before a conversation (it has no snapshot, hence no commands), the
Supervisor composer, and `@` file mentions.

### Ambiguities (worst first)

1. **Chip rendering technology.** A `<textarea>` cannot hold inline elements.
   Real chips (monospace badge, skill icon, atomic range) need a rich editor:
   CodeMirror 6 as in the reference, or a hand-written `contenteditable`. A
   textarea with a mirrored highlight layer keeps the native input but can only
   colour the token in place (same glyph widths: no icon, no padding, no
   monospace switch). The readings lead to different dependencies, tests and
   visuals. → open question Q1.
2. **Where a token triggers completion and chips.** Anywhere after whitespace,
   or only as the first token of the message. → settled below (first token).
3. **Which tokens become chips.** Any `/word` or only a known command. →
   settled below (known only).

### Critical dependencies

- None on the server or the agent: `commands` is already in every snapshot of
  Claude, Codex and Antigravity conversations, and `!` is already executed by
  the agent (also when the message was queued).
- Claude's list arrives after the CLI `initialize` response and Codex's after
  its `skills/list` probe: the list may be empty for the first seconds.
- Q1 option A adds `@codemirror/state`, `@codemirror/view` and
  `@codemirror/commands` (MIT) to `desktop-tauri`, which regenerates
  `THIRD_PARTY_NOTICES_JS.md` and deserves an ADR in `desktop-tauri/docs/adrs`.

### Settled technical choices (reversible, from code and conventions)

- **First token only.** `/` and `$` open the menu only when the token being
  typed is the first token of the draft (leading whitespace allowed), and only
  that token becomes a chip. The agent interprets nothing else: Claude and
  Antigravity read a slash command only at the start, and `codexSkillInput`
  attaches a skill only for the first field. Same rule as the Electron client.
- **Filtering per trigger.** `/` lists entries whose name does not start with
  `$` (Codex: only `/mcp`); `$` lists entries whose name starts with `$`. A
  conversation whose list is empty, or a query with no match, shows no menu.
- **Ranking.** Exact name → name prefix → name substring → description
  substring, case-insensitive, stable within a tier; the matched part of the
  name (or of the description in the last tier) is wrapped in a `<mark>` in the
  accent colour. Up to 50 results, scrollable list; `argumentHint` is shown
  next to the name when present.
- **Keyboard.** While the menu is open: `ArrowDown`/`ArrowUp` cycle,
  `Enter` (without Shift) and `Tab` insert the active entry followed by a
  space, `Escape` closes the menu and does **not** interrupt a busy turn (the
  existing `Escape`-to-interrupt applies only when the menu is closed).
  Hover sets the active entry, click inserts it, blur closes the menu. While
  composing (IME), keys pass through.
- **Accessibility.** The input is a `combobox` with `aria-autocomplete="list"`,
  `aria-expanded`, `aria-controls` on a `role="listbox"`, options with
  `role="option"`/`aria-selected`, and `aria-activedescendant` on the input.
- **Positioning.** The menu is anchored to the composer box, opens above it and
  flips below when there is not enough room above in the viewport.
- **Chips only for known names.** A first token becomes a chip when it matches
  a command of the snapshot exactly and is followed by whitespace, or when it
  was inserted from the menu. An unknown `/word` stays plain text. Commands use
  a monospace badge, `$` skills a badge with a skill icon.
- **Plain-text submission.** What is sent, queued and stored stays the exact
  draft string (`/name args`, `$skill args`); chips are presentation only. The
  32 000-character limit is unchanged.
- **Shell indicator.** When the trimmed draft starts with `!`, the composer box
  gets a distinct accent border and a `Shell` badge with the terminal icon in
  its footer, the placeholder/`aria-description` say the command runs in this
  conversation's folder and that the agent sees its output with the next
  message. The indicator also shows while queueing. No completion menu in
  shell mode.
- **Data plumbing.** `ConversationSnapshot` gains
  `commands?: {name: string; description?: string; argumentHint?: string}[] | null`;
  matching and ranking live in a pure module under `desktop-tauri/src/domain/`
  covered by `node --test`, the UI behaviour by Vitest UI tests.
- **Docs.** `desktop-tauri/README.md` and `desktop-tauri/CHANGELOG.md` gain a
  line; the root `CHANGELOG.md` `[Unreleased]` gains one user-facing line.

### Open product questions

**Q1 - How faithful must the inline chips be?** (owner: @sebastienferry)

- **A (recommended): real chips with CodeMirror 6**, as in the claudian
  reference. The composer becomes a CodeMirror editor: true inline badges
  (monospace for commands, icon for skills), atomic deletion, no layout drift.
  Cost: three MIT dependencies (bundle size to measure), an ADR, and the UI tests
  that type into the textarea move to a shared helper.
- **B: textarea with a highlight layer.** The native textarea stays; a
  mirrored layer behind it colours the token (background and rounded outline)
  without changing glyph widths. No dependency, smallest change, but no skill
  icon and no monospace badge: it reads as a highlighted word, not a chip.
  Atomic `Backspace` is handled in `onKeyDown`.
- **C: hand-written `contenteditable`.** Real chips without a dependency, but
  caret, selection, IME, undo and paste must be rebuilt by hand; highest
  regression risk.

## Round 2 - answers from the owner (2026-11-17)

### Answers

- **Q1 - chip fidelity:** option **A**, real chips with CodeMirror 6.

### Settled decisions

- The Tauri conversation composer becomes a CodeMirror 6 editor
  (`@codemirror/state`, `@codemirror/view`, `@codemirror/commands`, MIT),
  following the claudian `ComposerEditor` approach: a decoration turns the known
  first token into a non-editable widget chip once whitespace follows it (or
  once it is inserted from the menu), with a monospace badge for `/` commands
  and a skill icon badge for `$` skills; a `Backspace` keymap right after a chip
  deletes the whole token range.
- The editor keeps the composer contract: accessible name `Next message`,
  `role="combobox"` with the listbox attributes of Round 1, 32 000-character
  limit enforced by a transaction filter, `Enter` sends or queues,
  `Shift+Enter` inserts a newline, `Escape` closes the menu first and only then
  interrupts a busy turn, the field is read-only for archived conversations,
  and the controlled `draft` string remains the single source of what is sent.
- An ADR in `desktop-tauri/docs/adrs` records the editor choice (rejected:
  textarea highlight layer, hand-written `contenteditable`), and
  `THIRD_PARTY_NOTICES_JS.md` is regenerated with `npm run licenses:javascript`.
- The UI tests that type into the textarea move to a shared helper that drives
  the editor; jsdom gaps in CodeMirror (layout measurement) are stubbed in the
  Vitest setup rather than worked around in production code.
- Every Round 1 settled choice stands; no assumption is reversed.
