### Ambiguities, worst first

1. The title says New task, but creation and editing share a page. Applying changes only during creation versus throughout the shared page produces different fields after creation and when reopening a task.
2. Type options differ between web creation and editing. A fixed shared list versus tracker-specific discovery requires different UI and agent contracts.

### Recommended baseline and reversible technical choices

- Apply all three changes in both creation and editing.
- Remove the Assignee control and its form requests without clearing an existing task's assignee or removing assignment elsewhere.
- Field order: Project, Tracker where applicable, Title, Issue type, Priority, Description, Pull requests.
- Use native selects consistent with the desktop form. Priority choices: Urgent, High, Medium, Low; creation default: Medium.
- Use one type list in both modes: Default, Story, Bug, Task, Improvement, Technical debt. Creation default: Default (empty type), leaving the existing server/tracker default behavior in charge.
- Preserve a loaded custom type as an additional option so an unrelated save cannot change it.
- Send chosen type and priority in the initial creation request; extend the agent's explicit edit allowlist and send only changed fields on edit.
- Keep PR ordering, validation and follow-up-save behavior; preserve form values and report tracker failures.
- Keep this desktop surface's existing English runtime language.
- Add a user-facing changelog entry during implementation. No production code or technical specification is written during clarification.

### Critical dependencies and verification expectations
