# Clarification Report — Ticket #440

**Ticket**: `#440` (`gh-8b726529-6cf4-48cb-91e1-cdb93ccf491c-440`)
**Title**: PR discovery re-attaches links a user detached while it was running
**Date**: 2026-10-14
**Mode**: Autonomous (`pickup-issues` batch)

## 1. Context & Codebase Analysis

1. **Current Behavior (`internal/db/prdiscovery.go:68-77, 134-216`)**:
   - `pullRequestDiscoveryGate` checks `d.pullRequestLinksDetached(task.ID)` before calling the forge (`discoverTaskPullRequests`).
   - While the forge call is in flight (with `d.mu` released), a user can detach the task's pull request links (`UpdateTask` with empty `PrLinks`, setting `pr_links_detached = 1`).
   - When the forge call returns, `applyDiscoveredPullRequests` locks the task row (`d.lockTaskUnsafe(tx, task.ID)`) and re-reads `locked.PrLinks` and `locked.BranchName`, but does not re-read `pr_links_detached`, so it re-attaches the links and resets `pr_links_detached = 0`.

## 2. Decisions Recorded

1. **Re-read `pr_links_detached` Inside the Locked Transaction (`internal/db/prdiscovery.go`)**:
   - Add `force bool` parameter to `applyDiscoveredPullRequests(task *models.Task, found []models.TaskPullRequest, force bool)`.
   - Pass `force` from `rediscoverPullRequests`, `true` from `discoverAndApply`, and `false` from `discoverSecondaryPullRequests` (and existing non-forced test call sites).
   - Inside `applyDiscoveredPullRequests`'s transaction, after `lockTaskUnsafe(tx, task.ID)`, when `!force`, query `SELECT pr_links_detached FROM tasks WHERE id = ?` on `tx`. When `detached != 0`, return `nil` immediately without attaching any links or resetting `pr_links_detached`.
2. **Test and Concurrency Audit Documentation (`internal/db/prdiscovery_test.go`, `docs/db-concurrency-audit.md`)**:
   - Add a test in `internal/db/prdiscovery_test.go` that detaches a task's links inside `prDiscoveryLookup` (between the gate check and `applyDiscoveredPullRequests`) and verifies that automatic discovery (`force = false`) writes nothing and preserves `pr_links_detached = 1`, whereas forced discovery (`force = true` / `discoverAndApply`) still attaches the discovered link.
   - Update the `applyDiscoveredPullRequests` row in `docs/db-concurrency-audit.md`.
