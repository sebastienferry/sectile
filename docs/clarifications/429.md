## Restated request and scope

The desktop app lets the user pick a saved board view, as well as a project, when
choosing which tasks to browse. The view's tasks open in the Tickets pane, and each
row keeps its own project's skills and settings. A view can carry a repository, so
that work launched from the view runs, and is verified, in that repository.

Out of scope: managing views from the desktop (create, rename, delete), quick add
from a view, and an agent console on a view repository.

## Settled decisions (owner-confirmed, rounds 1 to 4)

1. **Chooser.** The desktop task-list chooser offers the user's saved views next
   to the projects. A view's tasks open in the Tickets pane, and each row uses its
   own project's skills and settings. The sidebar stays grouped by project.
2. **Local repository of a view.** Each view can have an optional local
   repository, stored on the workstation only. For launches made from the view it
   wins over the project mapping, and relaunches reuse the recorded root.
3. **Repository of a view on the web.** A view gains an optional Git repository
   (a remote URL). That takes a migration, an API change and a `BoardViewModal`
   field. When the local directory's `origin` does not match it, the desktop warns
   but accepts the directory.
4. **Pull request discovery.** The sync must discover a task's PR or MR in the
   repository of the view it was launched from (the owner's note).
5. **Degradation.** Against an older server or agent, with the shared token, or
   with no views, the desktop shows projects only.

## Settled technical choices (from the specification summary)

- Launch root order for a launch from a view: the view's directory, then the
  workstation checkout of the view's repository, then the project's usual
  resolution.
- A launch from a view with a repository records that repository on the task. It
  is accepted as stage evidence (the foreign path of #392), including on mono-repo
  projects, and sync discovery searches it: GitHub through the server, GitLab
  through the local agent of the user who launched.

## Adjustments after #456 (2026-09-25)

#456 ("run each task of a multi-repo project in its own repositories") merged after
the lost specification was written. The specification is rewritten against it:

- Migration numbers restart after 22, the last one on `main`.
- `tasks.repository` (the #456 pin) must be one of the project's repositories, and
  a mono-repo project ignores it. A view repository can be any repository, so it
  is stored in a column of its own rather than reusing the pin.
- The workstation checkout of a view's repository is looked up through the #456
  repository mappings (`Overrides.Repositories`), which replace "the agent's own
  checkout when its origin matches".
