# Clarification of #633: Roadmap | Let a person decide an epic's readiness

Ticket: https://github.com/sebastienferry/sectile/issues/633 (parent M-11, Roadmap).
Report path: `docs/clarifications/633.md`, committed on `feat/633`.

## Round 1 (2026-09-30)

### Request

An epic gets a readiness level of its own, idea, shaping or ready, that a
person decides from the roadmap. Until somebody decides, Sectile suggests a
level deduced from what the epic carries (its framing, its slicing, its
stories). The level becomes a third grouping axis of the roadmap next to the
priority and the quarter of #628, and dropping an epic on a readiness section
sets that level.

Out of scope: replacing or removing the maturity derived from the child
tickets (it answers another question and stays), a readiness filter or sort
in the toolbar, a per-project name for the label prefix and any tracker custom
field (#635, which will cover this axis with the others), writing the level on
another project's epic (#632), and a dedicated ideation view.

### Ambiguities, worst first

1. **Two "ready" badges on one row.** The derived maturity already shows
   "Prête" / "Ready" when every ticket is past specification. A readiness level
   called "Prête" / "Ready" next to it would show the same word for two
   different judgements, one computed and one decided. Taskativ avoided it
   because its derived badge never shows the word; Sectile's does. Question 1.
2. **Where the level is set and shown.** Taskativ puts three chips on both the
   condensed and the expanded row. Sectile's rows already carry the horizon
   chips, and the condensed row was made to fit on one line. A single badge on
   the row with the controls in the panel reads differently from three chips
   everywhere. Question 2.
3. **Undecided epics once grouped by readiness.** Either they get their own
   "not decided" section (Taskativ), or they sit in the section of their
   suggestion, marked as suggested. The first keeps "nobody decided" visible,
   the second makes the grouping useful from the first day. Question 3.
4. **Written to the tracker or not.** #627 writes the priority and the quarter
   as Jira labels and keeps them in Sectile elsewhere. The readiness can follow
   it, or stay in Sectile everywhere, which adds no label to the epic tickets.
   Question 4.

### Technical choices settled from existing code

- **Levels and keys.** `idea`, `shaping`, `ready`, empty when nobody decided.
  An empty value is not `idea`: that difference is what lets the suggestion
  show. In the code the concept is `readiness`, because `maturity` names the
  derived one.
- **Storage.** Local first, like the horizon, the priority and the quarter:
  stored on the macro, shown at once, then mirrored if question 4 says so.
- **Label.** `readiness:idea`, `readiness:shaping`, `readiness:ready`, exclusive,
  lowercase, single colon. Case is ignored on read, an unknown value is
  ignored, and when two levels are on the epic the most advanced wins (an epic
  somebody judged ready is not demoted). Setting a level removes the others.
- **Suggestion.** Computed in the web app from the row, never stored:
  1. the epic has at least one child ticket: `ready` (stories exist, so it
     left ideation);
  2. the epic has a framing (non-empty description) and a slicing whose every
     line is ticked or already has a story: `ready`;
  3. a framing, or at least one slicing line: `shaping`;
  4. nothing: `idea`.
  Taskativ also reads template sections; Sectile has none since #426 left the
  template fields out, so the signal is dropped. A description imported from
  the tracker counts as a framing, since the panel edits the same field.
- **Setting it.** Clicking a level decides it, clicking the decided level
  again clears it, through the panel's save path (`saveAxes` widened). The
  suggestion is highlighted with a `?` and a tooltip saying nobody decided,
  like the horizon's.
- **Grouping.** A third option, "readiness", in #628's axis select. Sections in
  funnel order, idea, shaping, ready, each always shown with its count, even at
  0, because an empty section is a drop target. The drop sets the level of the
  section; epics already at it are skipped, and the report is #628's. Folding
  is remembered per axis and value (`readiness:ready`), as #628 does.
- **Another project's epic.** The level stays in Sectile and queues nothing,
  like the priority and the quarter today.
- **Strings.** Every new string in French and English. `CHANGELOG.md` gets one
  `Added` line under `[Unreleased]`.

### Product questions

1. **Names beside the derived maturity.** Recommended: the readiness levels
   read "Idée / En cadrage / Prête" and "Idea / Shaping / Ready"; the derived
   badge keeps its values but is prefixed so it reads as the tickets' stage
   ("Tickets : Spécifiés", "Tickets: Specified"), with a tooltip saying it is
   the stage the least advanced open ticket has reached.
2. **Where it is set and shown.** Recommended: one badge on the expanded and
   the condensed row, showing the decided level or the suggestion with a `?`;
   the three chips live in the panel next to the priority; the drop on a
   section is the other way to set it. No chips on the rows.
3. **Undecided epics in the readiness grouping.** Recommended: a "not decided"
   section after the three levels, shown only when it holds an epic, each row
   showing its suggestion with a `?`; dropping an epic on it clears its level.
4. **Tracker write.** Recommended: as #627, a `readiness:*` label on Jira
   epics through the queued push and the pending pushes; stored in Sectile
   only on GitHub milestones, GitLab and local projects, and the panel says so.
