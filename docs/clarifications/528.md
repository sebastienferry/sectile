# Clarification #528 - Web i18n: project settings and tracker column configuration

Batch #526 to #534; shared decisions D1 to D9 are in `docs/clarifications/526.md`.

## Round 1 (2026-09-26)

### Request

Project settings mix French and English in every tab (General, Tracker,
Agentic workflow, Skills & SDD), in the provider descriptions, the repository
form, optional views, execution policy, the column editor and the deletion and
validation feedback. Everything must follow one language, and the provider
descriptions must describe the HTTP API integration instead of the stale "via
the GitHub CLI" claims.

Out of scope: repository URLs, tracker settings and workflow mappings (values,
not labels), which translation never alters.

### Code read

`ProjectModal.tsx`, `BoardColumnsEditor.tsx`, `lib/trackers.ts`,
`lib/optionalViews.ts`, `tests/projectModalExecution.test.mjs`,
`tests/optional-views.browser.mjs`, `tests/spec-artifacts-option.browser.mjs`;
`internal/tracker` to confirm that GitHub, GitLab and Jira are reached over
their HTTP APIs.

### Ambiguities

1. Provider copy: the rewrite describes what Sectile does today (HTTP API,
   labels for workflow stages, background sync) at about the same length.
2. The Spec Kit and OpenSpec descriptions name their own CLIs (`specify`,
   `openspec`), which is accurate: only translated.

### Decisions

Strings go to the `projectSettings` namespace (D1); shared controls reuse
existing keys where they match exactly.

### Product questions

None open. Exit condition met.
