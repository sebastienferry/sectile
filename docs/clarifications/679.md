### Request

A Jira project stores how its ticket priority scheme maps to Sectile's four
levels, discovered at sync and on demand, each line sure, guessed or hand-set;
the Tracker tab shows and corrects it, and a priority update whose level has
only guessed lines is refused before any write, while a creation goes out
without the priority and says so. Out of scope: GitHub, GitLab and local
projects, the read path (the rank fallback stays), and the epic axis custom
fields (part C of #635, still behind the owner's confirmation gate G1).

(`docs/clarifications/635.md`, rounds 1 and 2) and specified in
`specs/635-epic-axes-tracker-fields/` (spec FR-B1 to FR-B10, US6 to US9; plan
"Part B"; tasks B1 to B11). This round only checks that baseline against
`main` at `67cd7edb` and settles what moved since.

### Drift since the #635 plan

1. **Migration number.** The plan says 40; `main` is at 46 and the open
   `feat/732` claims 47. Settled below.
2. **OAuth since #654.** A Jira connection through an Atlassian grant never
   holds the admin scope `/rest/api/3/priority/search` needs (ADR 0044);
   `readJiraPriorities` already reads the bare `/rest/api/3/priority` list
   for such a client. The plan's "create screen, else the site list" keeps
   working through that path; nothing to change.
3. **Sync gating.** The project sync now runs its describing steps (teams,
   board) only when `describesProject` holds, not on every incremental
   background poll. Settled below.
4. **Language of new strings.** The plan asks for a French refresh note and
   "French and English strings". Since 2026-10-05 the owner's convention is
   that new user-facing server strings are written in English, web labels in
   both locale catalogs, existing French strings left as they are. Settled
   below.
5. **Line numbers.** `UpdateTaskBy` moved from `db.go:2791` to `:2831`;
   every other anchor of the plan still exists under the same name. The write
   entry points are unchanged: web update handler, MCP `update_task`, and the
   bulk action and chips through the web update.

### Technical choices settled from existing code

- **Migration number.** The next free number on `main` when the branch is
  rebased for review, today 47, 48 if `feat/732` merges first. Name stays
  `projects.priority_mapping`, `TEXT NOT NULL DEFAULT '{}'`.
- **Discovery at sync.** Runs under the same `describesProject` guard as the
  board step, Jira only, as a numbered step of the sync summary; an
  incremental background poll does not rediscover. FR-B2's "each sync" reads
  as each describing sync.
- **On-demand refresh bypasses the 10-minute in-memory scheme cache**, so a
  person who just changed the Jira scheme sees it at once.
- **Scheme source.** The create screen of the project (as
  `jiraCreatePriorities` reads it), else the site list through
  `readJiraPriorities`, which already handles the OAuth case.
- **Strings.** The refusal sentence, the creation notice and the refresh note
  are new and written in English; the web table labels go in both locale
  catalogs; neighbouring French sync steps are not translated.
- **Refresh endpoint rights.** Same gate as the `board-columns` sub-action.
