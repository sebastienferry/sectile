# #71 — Local-agent log visibility

## Request and scope

Expose the existing local-agent diagnostic log in the desktop application so users can diagnose connection and launch failures. Remote web access, execution-console changes, CLI stdout capture, log rotation, and centralized log storage are outside this change.

## Evidence

- Verified TaskFlow task `gh-9dc93da8-0cb4-4fd5-af38-663433d960ff-71`, https://github.com/sebastienferry/taskflow/issues/71, title “Be able to see the local-agent logs”; description is empty and no comments were returned.
- Read `desktop/electron/main.cjs`, `desktop/electron/preload.cjs`, `desktop/src/main.js`, `desktop/src/style.css`, `desktop/README.md`, `desktop/tests/disconnect.ui.cjs`, `desktop/tests/pr-display.ui.cjs`, `cmd/server/agent.go`, `Makefile`, and `openspec/config.yaml`.
- Desktop launches append both agent stdout and stderr to `agent.log` under Electron user data. Existing errors tell users to locate that file manually. CLI agents do not necessarily write to this file.
- The desktop has a persistent agent toolbar and reusable dialogs. Reading the desktop-owned file through Electron IPC does not require the agent or server to be online.
- No project MEMORY.md was found. Existing generated skill/configuration changes predate this work and are preserved.

## Ambiguities and decisions

1. Desktop versus web viewing changes the data path and acceptance criteria. The user was asked for a preference; the stated default is desktop, following existing agent controls and local log ownership.
2. Continuous streaming versus a snapshot: use an initial snapshot and explicit Refresh, consistent with the existing worktree inspector. Automatic streaming is deferred.
3. Log size: read at most the latest 256 KiB and visibly identify truncation. Do not load the entire append-only file.
4. Source identity: identify the desktop-owned file and explain that agents started elsewhere may log to their original terminal. Never imply this file necessarily belongs to a separately connected agent.

## Critical dependencies

Existing Electron filesystem access and local desktop test dependencies are sufficient. No migration, external service, or server protocol change is required. The live project specifies OpenSpec, branch `feat/71`, and draft PR creation at the specified stage.

## Questions

1. Optional: where should logs be viewed? Recommended and default: desktop app. Web or both would require a different specification.

## Settled assumptions

Add an always-available Agent logs control, including offline/setup states. Show log text literally in a read-only, scrollable view with source path, bounded-tail notice, Refresh, and missing/empty/read-error states. Refresh replaces stale content and does not change execution selection or lifecycle. This is diagnostic visibility only; no deletion, upload, or arbitrary file browsing is introduced.
