# Clarification #778 - Desktop: Claude Settings

Ticket: https://github.com/sebastienferry/sectile/issues/778
Branch: `feat/778`

## Round 1 (2026-10-06)

### Request

The "Claude settings" entry of the Desktop settings navigation draws a generic
shield-with-a-check icon; it should draw the Claude logo instead, the mark #777
introduced in `desktop/src/claude-mark.mjs` next to "Conversation permission
mode". Out of scope: the content of the Claude settings panel, its label, the
web app, and every other settings category's icon.

### What was read

- `desktop/src/main.js`: `SETTINGS_CATEGORIES` and `PROJECT_SETTINGS_CATEGORIES`
  (lines 1762-1778), both holding a `Sandbox` category labelled
  "Claude settings" with the same shield icon; the five places that render a
  category tab (`configurationNavigation` at 1803, `openSettings` at 1973 and
  1986, the project settings page at 2359 and 2386), all building
  `<svg fill="none" stroke="currentColor" stroke-width="1.6">` + `category.icon`;
  the conversation mode row (2042) that already prepends `claudeMark(document)`.
- `desktop/src/claude-mark.mjs`: `CLAUDE_MARK_PATH` and `claudeMark()`, a filled
  path in `currentColor`, kept identical to `web/src/components/icons/Claude.tsx`
  by `desktop/tests/claude-mark.test.mjs`.
- `desktop/src/style.css`: `.settings-nav svg` sizes nav icons to 15 px;
  `.setting-name .claude-mark` sizes the in-row mark to 14 px.

### Ambiguities, worst first

1. **Which "Claude settings" tab.** Two exist: the workstation one (General
   group) and the per-project one (under each project). Changing only one would
   show two icons for one label. Recommended: both.
2. **Colour.** The mark can follow the text colour like every other nav icon
   (grey, accent when selected), or carry Claude's brand orange. Recommended:
   `currentColor`, as #777 and the web app already draw it; an orange icon would
   be the only coloured one in the navigation.

### Dependencies

None: no server, agent, migration or API change. Desktop only.

### Technical choices settled (reversible)

- The nav icons are stroked outlines while the Claude mark is a filled shape:
  the tab must render the mark filled, without the 1.6 stroke, or it reads as a
  bold blob. A category gets a way to name the mark (for example a `mark` field
  or rendering through `claudeMark()`) instead of carrying the path inline, so
  the path keeps one source and the test that compares it with the web copy
  still covers it.
- All five tab-rendering sites go through that same path, so the workstation
  tab, the project tab and the configuration page navigation agree.
- The mark keeps the 15 px nav icon size; it may need a slightly smaller
  optical size to match the weight of the outline icons, to be judged on screen.
- The shield icon is not reused anywhere else and disappears.
- Changelog: a one-line `Changed` entry under `[Unreleased]`, since the change
  is visible.

### Open questions for the owner

1. Apply the Claude logo to both "Claude settings" tabs, workstation and
   project? Recommended: yes.
2. Draw it in the text colour like the other nav icons (recommended), or in
   Claude's orange?

Report committed on `feat/778`.

## Round 2 - answers from the owner (2026-10-06)

Answers given interactively.

### Settled

1. **Both tabs.** The workstation "Claude settings" tab (General group) and the
   per-project one both draw the Claude logo; the shield icon goes away.
2. **Claude orange**, not the text colour. This reverses the round 1
   recommendation (`currentColor`).
3. **The conversation mode row mark turns orange too.** The logo #777 placed
   next to "Conversation permission mode" takes the same colour, so Desktop
   settings render the Claude logo one way only.

### Consequences (technical, reversible)

- The orange is Claude's brand colour, `#D97757` (the colour @lobehub/icons
  ships for Claude, the source of the vendored path). It lives in one place,
  a CSS rule on `.claude-mark` (a variable such as `--claude-brand`), not as a
  `fill` attribute, so `claudeMark()` keeps drawing in `currentColor` and the
  path stays identical to the web copy.
- The tab icon stays orange in every state (idle, hover, selected): the
  selected state is still shown by the tab background and label colour.
- The same orange is used in the light and dark themes; it reads on both
  backgrounds, so no per-theme variant is planned.
- The web app's Claude icon is unchanged (out of scope).

### Open questions

None. Report committed on `feat/778`.
