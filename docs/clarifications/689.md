# Clarification #689 - Add a folder from a free console or a native-terminal discussion

## Round 1 (2026-10-02)

### Request

Offer the "Add folder…" action of #676 in the two places it is still missing:
the free "Project prompt" PTY console, and a ticket discussion detached to the
native terminal, with the same outcome as a running ticket discussion (`/add-dir`
typed for Claude Code, attached for the next launch otherwise). Out of scope, as
in #676: the web app, detaching a folder, and a folder visible to one session
only.

### Code read

- `internal/agent/agent_run_folders.go`: `desktopRunFolder` accepts a
  conversation or a running `discuss` PTY run, attaches through `attachFolder`,
  and types `/add-dir` through `typeAddDir` when the run's `interactiveProvider`
  is `claude`. A run with `ExternalTerminal` set has its provider blanked, so it
  answers `next-launch`. A free console is refused with 409 ("A folder is added
  from a conversation or a running ticket discussion").
- `internal/agent/agent_console.go`: `desktopConsole` launches the free console
  in a Sectile PTY (`launchConsole`, `runInPty`), with `--add-dir` for the
  project's folders and `SECTILE_REPOSITORIES` (#676). The run carries
  `Kind = "console"` and `Provider`, but no `interactiveProvider`. Its Claude
  "conversation" view is already covered by #676.
- `internal/agent/agent_desktop.go` (detach, around line 1190) and
  `internal/agent/terminal_launcher.go`: detaching only sets `ExternalTerminal`
  and opens a native terminal that runs `sectile-agent attach --session <id>`.
  The PTY stays owned by the agent's terminal manager.
- `internal/agent/agent_desktop.go` (`desktopTasksTerminalExternal`): opens a
  native terminal on a bare shell session, with no engine started. The desktop
  never calls it (`desktop/src/main.js` only calls `detachToNativeTerminal`).
- `internal/terminal/run.go` (`WaitQuiet`) and `internal/agentattach/attach.go`.
- `desktop/src/run-folders.mjs` (`offersRunFolder`, `runFolderOutcome`) and
  `desktop/src/main.js` (toolbar `#add-run-folder`, `#detach-terminal`,
  `#native-terminal-badge`, `freeConsole`, the `run-folders` capability check).
- `docs/clarifications/676.md`, Rounds 1 to 3.

### Finding that changes the ticket's premise

The ticket says Sectile "cannot write into" a native-terminal discussion. The
code says otherwise: the native terminal is only an attach client of a PTY the
agent still owns, so `SendInput` reaches the Claude session exactly as it does
for an in-app discussion. `next-launch` for a detached discussion is a choice
made in #676 (`provider = ""` with the comment "Sectile no longer types into
it"), not a technical limit. The only native-terminal path where Sectile could
not know what runs is `desktopTasksTerminalExternal`, which opens a bare shell
and is not reachable from the desktop.

### Ambiguities, worst first

1. **Detached discussion: type or not.** Typing `/add-dir` into a session the
   user now watches in another window (a) keeps #676's outcome everywhere, but
   writes into a terminal the user may be typing in; attaching only (b) is safe
   but leaves the running session blind to the folder; hiding the button (c)
   sends the user back to the project settings. Each reading leads to different
   code and a different status line. This is the product question below.
2. **Free console with another engine** (Codex, Antigravity, a custom template):
   the folder can only be attached. A free console is never relaunched as such:
   "Relaunch" or a new "Project prompt" starts with `--add-dir` for it. The
   status line must say that, not "at its next launch" of a discussion.
3. **Free console detached to the native terminal**: the detach button is
   offered on consoles too, so the answer to question 1 applies to it as well.

### Dependencies

- No migration, no server change: everything stays on the agent and the
  desktop, as in #676.
- Capability: an agent that serves `run-folders` but not this change refuses a
  console with 409. A new desktop must not show the button against it, so the
  agent advertises a new capability for consoles (and for detached runs if they
  start typing), and the desktop checks it.
- `WaitQuiet` watches only output; a detached terminal echoes typing as output,
  so a user typing in the native terminal delays the line, but a draft left
  untouched for a second would be submitted together with it. The in-app
  discussion shares this risk; it is smaller there because the user is clicking
  in Sectile, not typing.

### Reversible choices settled from the code

- **Console provider:** a free console records its engine the way a discussion
  does (`liveProvider` on the resolved config, so an engine template whose
  provider is Claude counts as Claude), and `/add-dir` is typed only for Claude
  Code, through the existing `typeAddDir`.
- **Endpoint:** `POST /desktop/run-folder` accepts a running PTY run of kind
  `console` with a session; same checks, same answer shape, same refusals.
- **Desktop:** `offersRunFolder` admits a running free console with a session,
  in the same toolbar slot; the button stays hidden for a read-only or ended run.
- **Status line for a console that is not typed into:** "Attached <path>: a new
  Project prompt or a relaunch sees it". The exact wording is left to the
  specification.
- **Capability:** a new capability string next to `run-folders`; the name is a
  specification detail.
- **`desktopTasksTerminalExternal`:** untouched; it opens a shell, there is no
  engine to type into.
- **Changelog:** the change is visible to users; the pull request adds a line
  under `## [Unreleased]`.

### Product question

1. **What does "Add folder…" do on a discussion (or console) detached to the
   native terminal?**
   - (a) **Recommended:** the same as in Sectile. The button stays in the
     Sectile toolbar of the detached run; for Claude Code, `/add-dir <path>` is
     typed into the session, which the native terminal shows at once; the status
     line says it was typed into the session in <terminal name>. Another engine
     gets `next-launch`.
   - (b) The button is offered, the folder is only attached, and the status line
     says the session sees it at its next launch.
   - (c) No button on a detached run.
