# Clarification #532 - Web i18n: activity, synchronization and operation feedback

Batch #526 to #534; shared decisions D1 to D9 are in `docs/clarifications/526.md`.

## Round 1 (2026-09-26)

### Request

Operational feedback mixes languages: connection banners and toasts, the
Activities view ("Créée à", "Durée totale", running and empty-output
messages), the Sync view, and the global notifications composed in
`AppContext.tsx` with a translated title and a French body. Application-owned
messages must be bilingual, live updates included; raw external errors,
command output, AI results and historical free text stay as diagnostic
content.

### Code read

`ActivitiesView.tsx`, `SyncView.tsx`, `DegradedReadBanner.tsx`,
`ToastContainer.tsx`, `AppContext.tsx` (notifications and operations),
`lib/apiRead.ts`; server side, the activity `action`, `summary` and `steps`
templates of `internal/handlers/handlers.go` and `internal/db/db.go` (about 45
French templates such as `Exécution de %s sur l'agent local`,
`Tâche ciblée : %s - %s`, `Synchronisation Jira (%s) en file d'attente`).

### Ambiguities

1. How to localize server-generated activity text. Reading A: the server
   stores message identifiers and parameters (API and storage change, plus a
   fallback for every activity already persisted). Reading B: the web
   recognizes the known server templates and renders them in the viewer's
   locale, with the raw text as fallback. Settled: B (D7). It needs no API or
   storage change, covers persisted activities by construction, and leaves the
   server wording (French, per AGENTS.md) untouched. Recorded in ADR 0035 with
   the conditions to move to A.
2. Unknown text (agent output, external errors, custom command lines) is shown
   verbatim, never guessed.

### Dependencies

None outside the web client.

### Decisions

Strings go to the `operations` namespace (D1); the template catalog lives in
`web/src/lib/activityText.ts` with its own tests.

### Product questions

None open. Exit condition met.
