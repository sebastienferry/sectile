## Round 1 (2026-10-07)

### Restated request and scope

The Changes view of a Sectile Desktop execution always inspects the run's primary checkout, even when the run works in several folders (other repositories' worktrees, context checkouts, the specifications worktree, attached folders). The request is to let the Changes view inspect the folder the person selects among the run's folders. Out of scope: changing what the diff computes inside one folder (baseline, limits, Markdown rendering), the web client, and diffs that combine several folders into one view.

### Files read and existing behavior

- `desktop/src/gitDiff.js`: the Changes panel. `refresh()` calls `api.gitDiff(runId)` with the run ID only; nothing names a folder.
- `desktop/electron/preload.cjs` and `desktop/electron/main.cjs` (`git-diff` handler): forward the run ID to `GET /desktop/git-diff?id=<runId>` on the local agent, gated by the `git-diff` capability.
- `internal/agent/agent_diff.go` (`desktopGitDiff`): resolves the run and inspects `run.desktop.Directory` on `run.desktop.Branch`, checked against `run.root`. This is the only folder it can inspect.
- `internal/runner/worktree_diff.go` (`InspectWorktree`, `identity`, `baseline`): refuses a checkout whose current branch differs from the expected branch, or whose Git common directory differs from the expected repository root; the baseline is the merge-base with `origin/HEAD` (falling back to `origin/main`, `origin/master`, `main`, `master`).
- `internal/agent/agent_run_folder_list.go` (`runFolders`) and `internal/agent/agent_desktop.go` (`desktopRun.Folders`): every run already carries its folder list (path, name, role `primary`/`changed`/`context`/`spec`/`local`, attached flag), primary first, since #762.
- `desktop/src/folder-menu.mjs` and the folders menu in `desktop/src/main.js` (`#worktree-folders`): the chevron next to the toolbar path lists those folders, but an item only **copies** its path. There is no notion of a "selected folder" in the desktop today.

### Ambiguities, worst first

1. **What "the currently selected folder" is.** No selection exists: the folders menu copies a path and the toolbar always shows the primary directory. Either the Changes panel gets its own folder selector, or the toolbar folders menu becomes a selector (changing #762's copy behavior and the path shown in the toolbar), or both stay in sync. Each leads to different UI code.
2. **Which folders can be inspected, and against what.** The primary checkout is checked against the run's branch. A changed repository's worktree is on the task branch of its own repository; the specifications worktree is on its own branch; a context checkout is usually on the default branch (so only uncommitted or unpushed local edits would show); an attached folder may not be a Git repository at all. Offering all of them or only the task-branch worktrees changes the acceptance criteria.

### Critical dependencies

- **Local agent API.** `/desktop/git-diff` must accept a folder in addition to the run ID. The agent must accept only a path listed in the run's own folders, never an arbitrary path from the renderer. A new capability string lets an older agent keep today's behavior, the selector being hidden then.
- **Identity check.** `identity()` compares the checkout to the run's branch and repository root. For a non-primary folder, the expected branch and repository come from the folder itself (its current branch, its own Git common directory), not from the run.
- Runs launched without a folder map, and runs from an older agent, have no `folders`: they keep a single, implicit primary folder.
- No database migration, no server change: everything is between the desktop and the local agent.

### Reversible technical choices settled from conventions

- The run's primary folder stays the default selection, so a single-folder run looks exactly as today.
- The selection is remembered per execution while Desktop runs and forgotten on restart, as the panel already forgets its result when another execution is selected.
- The diff context line already names the inspected directory and branch; it keeps doing so for the selected folder.
- A folder the agent cannot inspect (not a Git repository, no default branch, missing) shows the agent's existing error text in the panel, without hiding the folder from the list.
- New user-facing strings are written in English, like the rest of the Changes panel.
- The change is visible to users, so the pull request adds a `CHANGELOG.md` line under `[Unreleased]`.

### Product questions for the owner

1. **Where is the folder chosen?**
   - (a) **Recommended:** a folder selector in the Changes panel toolbar, next to Refresh, listing the run's folders with their role. The toolbar folders menu keeps copying paths (#762).
   - (b) The toolbar folders menu becomes a selector: choosing a folder changes the toolbar path and the Changes view; copying moves to the path button only.
2. **Which folders does the selector offer?**
   - (a) **Recommended:** every folder of the run (primary, changed, specifications, context, attached). Each is compared with its own default branch; a context checkout therefore shows its local uncommitted or unpushed changes, and a folder that is not a Git repository says so.
   - (b) Only the folders where the task writes on a branch: primary, changed repositories, specifications.

## Round 2 - answers from the owner (2026-10-07)

### Answers

1. **Where is the folder chosen?** Option (b): the toolbar folders menu (the chevron next to the path, #762) becomes the folder selector. This reverses the Round 1 recommendation (a selector inside the Changes panel).
2. **Which folders are offered?** Option (a), as recommended: every folder of the run (primary, changed, specifications, context, attached), each compared with its own default branch.
3. **Follow-up: does "Open in editor" follow the selection?** Yes, as recommended: the whole toolbar speaks of one folder at a time.

The owner confirmed the clarification is satisfactory.

### Settled scope

- Choosing a folder in the chevron menu **selects** it instead of copying its path. The selected item is marked in the menu (menu items become a single-choice list).
- The selected folder drives, together:
  - the path shown in the toolbar (`#directory`);
  - the copy action, which stays on the path button only (`#worktree`, "Copy this path");
  - "Open in editor", which opens the selected folder;
  - the Changes view, which inspects the selected folder and refreshes when the selection changes while it is open.
- The primary folder is selected by default. The selection is remembered per execution while Desktop runs, forgotten on restart, and falls back to primary when the selected folder leaves the run's folder list.
- A run with one folder, without a folder map, or served by an older agent shows no chevron and behaves exactly as today.
- Every folder is offered. A folder that cannot be inspected (not a Git repository, missing, no default branch) stays selectable; the Changes view shows the agent's error for it, and the path and editor still work.

### Reversed assumptions

- Round 1 assumed the toolbar menu keeps copying paths (#762) and the Changes panel gets its own selector. Both are reversed: the menu selects, and copying a non-primary path means selecting it then clicking the path.

### New dependencies from the answers

- `/desktop/open-editor` (`internal/agent/agent_desktop.go`, `desktop/electron/main.cjs`) takes only a `runId` today, like `/desktop/git-diff`. Both gain an optional folder, which the agent accepts only when it is one of the run's own folders; no folder means the primary, so older desktops keep working.
- One new agent capability announces both; without it, the desktop keeps today's behavior (chevron copies, editor and Changes use the primary folder).
- For a non-primary folder, the diff's identity check uses the folder's own current branch and Git common directory instead of the run's branch and root.
