## Round 1 — analysis (2026-09-23)

### Restated request and scope

When a user edits a project's AI settings and saves, the autonomous (headless) CLI command must
be persisted and shown again on reopening, exactly like the interactive CLI command already is,
in the web project settings and in the desktop app. Out of scope: changing how the two commands
are resolved at launch (`{mode:...}` marker, provider defaults, workstation precedence), the
deployment-wide settings screen (already persists both), and any new command field.

### Verified findings

1. **Root cause (web, server side).** `UpdateProject` applies `req.AICommandTemplate` to the
   stored project (`internal/db/db.go:6123`) but has **no counterpart for
   `req.AICommandTemplateAutonomous`**. The request field exists (`models.go:393`), the web
   sends it (`ProjectModal.tsx:381`), the column is written by the `UPDATE` (6199), but the
   value written is always the one already stored. Result: the autonomous command is saved on
   project *creation* (`CreateProject` inserts `aiCmdAutonomous`) and silently dropped on every
   *edit*. This matches the report exactly ("interactive saved, autonomous not").
2. **Web payload cannot clear either command.** `ProjectModal.tsx:380–381` sends `undefined`
   when a field is empty (or when "custom agent" is off), so the server keeps the stored value.
   Emptying a command therefore never reverts it to the provider default. `aiModel` (384) was
   already fixed to always send, including empty, for this exact reason.
3. **Desktop local override path looks correct in code.** The desktop form posts both commands
   (`main.js:1256` → `/desktop/projects`), `agent_desktop.go` stores both in `commands` /
   `commandsAutonomous`, `WriteSettings` keeps both keys, `ApplyOverrides` reads both back, and
   the `GET` returns `aiCommandTemplateAutonomous`. The desktop field is prefilled from the
   *server* value when no local override exists, so finding 1 alone makes the desktop show an
   empty/old autonomous command. Whether the desktop local override is also lost could not be
   reproduced from code reading — see Q1.
4. **Deployment settings are fine.** `UpdateSettings` persists `aiCommandTemplateAutonomous`
   (3515, 3688) and the handler honours an explicit clear (`handlers.go:2737`).

### Ambiguities (worst first)

1. Is the desktop symptom the same bug (inherited server value never saved) or a second one
   (local override lost)? The first needs no desktop change; the second needs a desktop/agent fix.
2. What an empty field means on save in web project settings: "keep stored value" (today) or
   "clear it" (fall back to the interactive command / provider default).

### Dependencies

- No migration: the `ai_command_template_autonomous` column already exists and is read/written.
- Values lost by earlier edits cannot be recovered; users re-enter them once after the fix.
- No third-party or cross-service dependency.

### Reversible technical choices (settled from existing code)

- Fix in `UpdateProject`: apply `req.AICommandTemplateAutonomous` when non-nil, mirroring the
  interactive field.
- Add a regression test in the `internal/db` tests: create a project, update both commands,
  read back, assert both persisted.
- Keep the resolution rules (`ApplyOverrides`, `EffectiveCommandTemplate`) unchanged.

### Open product questions (owner: @sebastienferry)

- **Q1 — Desktop scope.** On the desktop, which save loses the autonomous command: the project's
  *local* settings (desktop "Autonomous CLI command (headless)" field, a workstation override), or
  only the value inherited from the server? *Recommendation:* treat it as the same root cause
  (fix the server; the desktop then shows the saved value) and only open a desktop fix if a
  local override still disappears after that — please give the steps if you already saw it.
- **Q2 — Clearing a command.** In web project settings, should emptying the interactive and/or
  autonomous field and saving clear the stored value (autonomous empty → the interactive command
  serves headless launches; both empty → provider defaults), and should turning "custom agent"
  off clear both? *Recommendation:* yes to both, always sending the two fields like `aiModel`,
  so what the form shows is what is stored.
