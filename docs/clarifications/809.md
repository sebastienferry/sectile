## Round 1 (2026-10-09)

### Restated request and scope

In the web UI's Roadmap and Timeline views, a macro (epic) key should be shown the way a ticket key is shown in the ticket detail: a link to the macro on its tracker, with a copy button next to it that copies the key. Out of scope: the Sectile Desktop app, which does not render the roadmap or the timeline; the ticket views (board, list, ticket detail), where the parent key already has a link and a copy button; and any server, API or data change.

The key is an `<a target="_blank">` followed by an `ExternalLink` icon. When there is no URL, it is a plain `<span>`. A separate `Copy` icon button next to it copies the key alone through `copyText` (`web/src/lib/clipboard.ts:18`). The icon turns into a check for 2 s, a toast confirms, and a failure shows an error toast. The parent (macro) key in the same header already follows this pattern, plus a "open in roadmap" button. ### Ambiguities, worst first

1. **The Timeline shows no macro ID today.** "Everywhere we have the macro IDs in the … timeline modules" matches nothing there: only the macro title chip. Reading (a) adds the macro key, with its link and copy button, to the Timeline's ticket rows. Reading (b) leaves the Timeline untouched. (a) also needs a URL the Timeline does not load: either derive it from the key, as `trackerUrlForKey` does in the ticket detail (Jira `/browse/KEY` only), or load the project's macros to read `externalUrl`. See Q1.
2. **What the new copy button copies.** "Just like for issues" means the key alone, for example `PE-123`. The panel's existing "Copier" copies the URL, or `KEY: title`. Two copy buttons in the same header with different payloads would confuse. See Q2.
3. **Which Roadmap places.** The rows (expanded and condensed) and the panel header are clear. The attach-candidate list shows a macro key inside a `<button>`, where a link cannot be nested, and the seed modal shows the key of a macro that is being set up. See Q3.

### Reversible technical choices resolved from existing conventions

- The key renders exactly like the ticket detail: an `<a href target="_blank" rel="noreferrer">` with an `ExternalLink` icon when the macro has an `externalUrl`. Without one (local `M-<n>`, GitLab), it stays a plain span. The copy button is shown in both cases, since copying the key still makes sense.
- The link URL is `MacroMeta.externalUrl`, which the server already computes. No URL is guessed for macros that have none.
- Inside a roadmap row, a click on the link or the copy button calls `stopPropagation` and does not start a drag, so it neither selects the row, multi-picks it, nor moves it. A click anywhere else on the row behaves as today.
- The copy goes through `copyText` (`web/src/lib/clipboard.ts`) with the same check icon, success toast and failure toast as the ticket key.
- The link-plus-copy rendering is extracted into one small shared component. Today it is written inline in `TaskDetailModal`, and this ticket would add a second and third copy. Whether `TaskDetailModal` itself moves to the shared component is left to the specification.
- Tooltips reuse the existing `openRemoteTitle` and `td.header.copyKey` strings where they fit, in both locales. Any new string is added in English and French, like the rest of `planning.ts`.
- A CHANGELOG line under `## [Unreleased]` → `Added` is required, since the change is visible to users.

### Critical dependencies and validation expectations

- No server, API, migration, tracker or other repository is involved. The change is limited to `web/src`.
- Validation: unit or browser tests showing that the row key links to `externalUrl` and has no link without one; that the copy button copies the key alone; that a click on either does not select or pick the row; and, if Q1 is (a), the Timeline rendering.

### Product questions

1. **Q1: Timeline.** Recommended: (a) add the macro key with its link and copy button in front of the existing `parentTitle` chip on the Timeline's ticket rows, with the URL read from the project's macros (Jira, GitHub milestone). A macro without a URL gets the copy button only. Alternative: (b) leave the Timeline out, since it shows no macro ID today.
2. **Q2: Panel copy button.** Recommended: the new copy button next to the key copies the key alone, like tickets. The existing "Copier" button, which copies the link or `KEY: title`, stays as is, and the "Lien" button is removed because the key now carries the link. Alternatives: keep all three, or also remove "Copier".
3. **Q3: Roadmap places.** Recommended: the expanded row, the condensed row and the panel header. The attach-candidate list (a clickable button already) and the axes seed modal stay plain. Alternative: also treat those two.
4. **Q4: Baseline.** Is this clarification satisfactory, with the desktop app out of scope?

None. Round 1 left the Timeline open, and Q1 now brings it into scope.

### Newly resolved technical point

- The Timeline loads only `Task` objects. It gets macro URLs from the existing `fetchProjectMacros` (`web/src/context/AppContext.tsx:2898`, `GET /projects/{id}/macros`), which returns `MacroMeta.externalUrl`. It fetches once for each project shown and builds a key-to-URL map. No new endpoint is needed. URLs are never derived from the key alone, so a macro the server gives no URL keeps the copy button only. How the fetch is cached and refreshed is left to the specification.
