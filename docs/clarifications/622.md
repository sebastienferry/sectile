# Clarification #622 - Remove the description from the card view

Ticket: https://github.com/sebastienferry/sectile/issues/622

## Round 1 (2026-09-29)

### Restatement

The board card (`TaskCard`) stops rendering the two-line truncated description
under the title, whatever the board density, so a card shows the key, title,
badges and links only. Out of scope: the task detail panel, which keeps the full
description, the description field itself (stored, synchronised and editable as
today), and any change to how descriptions are written or fetched.

The ticket body is empty; this reading comes from its title alone.

### Code read

- `web/src/components/TaskCard.tsx:970-975`: the block
  `{task.description && <p className="... line-clamp-2 ...">}`, rendered on the
  standard and comfortable densities. The condensed card (compact density) already
  hides it.
- `web/src/components/ListView.tsx:586-590`: the list view shows a one-line
  description under the title when rows are not condensed and the task has no
  latest activity. This is the neighbouring surface the question below is about.
- `web/tests/condensed-card.browser.mjs:23,36-37`: asserts the description is
  hidden on the condensed card and **shown** on the standard and comfortable
  densities (line 36). That second assertion must be inverted by the change.
- `web/tests/pr-state.browser.mjs`, `web/tests/card-model-menu.browser.mjs`:
  fixtures carry a description but assert nothing about it; unaffected.

### Ambiguities, worst first

1. **Which surfaces.** "Card view" names the board card. The list view also shows
   a description excerpt. Removing it from the board only, or from both, leads to
   different code. See question 1.
2. **Removal or setting.** The description could be removed outright or put
   behind a display setting (like the density setting). A setting adds a stored
   key, a settings UI entry and translations. See question 2.

### Dependencies

None: front-end only, no API, migration, tracker or desktop-specific change (the
desktop app renders the same web bundle).

### Technical choices settled from the code

- Delete the JSX block rather than hide it with CSS, so nothing is rendered or
  read by screen readers.
- Update `condensed-card.browser.mjs` so every density asserts the description is
  absent.
- `CHANGELOG.md`: one `Changed` line under `[Unreleased]`, since the change is
  visible to users.

### Open product questions (owner: Sébastien Ferry)

1. Is the list view's one-line description removed too, or only the board card's?
   **Recommended: board card only**, as the title says; the list view is a denser
   reading surface where the excerpt helps scanning.
2. Is the description removed outright, or made optional through a display
   setting? **Recommended: removed outright**; the detail panel still shows it.
