# Clarification #496 - Atomic answer to a run wait

Ticket: https://github.com/sebastienferry/sectile/issues/496
Branch: `feat/496`

## Round 1 (2026-09-27)

### Request

An answer from a run console must clear only the wait whose timestamp the agent received, even when another server instance records a new question during the answer. This change is limited to the answer's database operation and its regression coverage; it does not change how waits are declared, shown, or resumed by MCP calls.

### Existing behavior and files read

- `internal/db/remoterun.go`: `AnswerRemoteRunWait` reads `waiting_since` and then clears a wait in a separate update that does not compare the timestamp. `setRemoteRunWaiting` and `ResumeWaits` already use conditional updates for their respective state changes.
- `internal/db/waitingsession_test.go`: SQLite tests cover an older answer arriving after a new mark, but not a mark arriving between an answer's read and update.
- `internal/db/postgres_waiting_test.go` and `internal/db/postgres_concurrency_test.go`: PostgreSQL tests use two stores on one database to represent independent server instances.
- `internal/db/dialect_sqlite.go` and `internal/db/dialect_postgres.go`: both engines bind Go timestamps, with PostgreSQL retaining microsecond precision.
- `.agents/MEMORY.md`: the waiting mark is the server's source of truth, and the agent receives a copy through the run protocol.

### Decisions and dependencies

- The supplied `waitingSince` is the identity of the answered wait. The clear must include it in the update predicate with the existing owner, agent-run, running-status, and empty-reason restrictions.
- A mismatched or absent mark is a no-op. Only a successful clear sends a wait-change notification.
- Keep SQLite behavior and the existing time round trip through JSON. Verify timestamp equality against both database engines.
- No schema migration, protocol change, or change to the attached infrastructure repository is needed. PostgreSQL regression execution depends on a reachable test PostgreSQL database.

### Open product questions

None. The ticket specifies the atomic behavior and existing ownership and UI rules remain in effect. The clarification exit condition is met.
