# Clarification #862: Restore the rule: every action a user performs uses their own tracker credential

## Round 1 (2026-10-22)

Report: `docs/clarifications/862.md` on `feat/862` (worktree `.tasks/worktrees/issue-862`, created from `origin/main` at `e9e618bb`). Not pushed (`pushStageCommits` off). No pull request at this stage (`prCreationStage` is `implemented`).

### Restated request and scope

Every action a user performs, through the web UI, the desktop app or MCP, agents working for them during a skill run included, uses that user's own tracker credential; only the asynchronous synchronisation and jobs nobody launched use the server token. This reverts the credential routing #855 introduced (ADR 0058) while keeping its OAuth connection, its credential checks and its typed missing-server-credential error.

Out of scope: the OAuth connection itself (kept as shipped), the provider app registration (#860), signing in to Sectile.

### Settled by the owner (ticket description, 2026-10-22)

- A write a user causes uses their own credential on every provider, whatever its kind; without one it is refused (ADR 0029). A managed run's post-back writes as its launcher.
- A read made for a user uses their credential first and the server token when they have none (option a).
- The server token serves the synchronisation and unattended jobs only.

### Ambiguities, resolved

1. **Jira reads without a personal credential.** Before #855 they were refused; option (a) says the server token answers. Resolved by the owner's decision: every provider falls back the same way.
2. **A personal credential sealed and locked on a read.** Resolved from ADR 0018 and the pre-#855 code: the read is refused, never answered under another identity's token. Absence falls back; a locked credential does not.
3. **ProjectsV2 board statuses.** They are a read, so they go through the person's GitHub grant first: the consent asks for `read:project` again, and the scope pin test lists it.

### Reversible technical choices

- Remove, not disable: `WithServiceCredential`, `ForRead`, `trackerOpRoutes` and the route tests, the `ServiceCredential` fields, the skill-run detection, the service marks and `stageMoveOnly`. Reads go back through `ForActingUser` with the server fallback (`trackerAs`, `trackerClientAs`, the adapters).
- Keep: the OAuth port; the checks (Administration checks the server credential only, the personal Verify the caller's own only); `MissingServerCredentialError` with its 503 code, now raised for unattended writes and the sync; the up-front server-credential check for unattended writes.
- Tests asserting #855's routing are reverted to the pre-#855 assertions where they existed, and rewritten otherwise.
- ADR 0059 supersedes ADR 0058's routing and keeps its OAuth sections by reference; ADR 0029 and ADR 0044 return to the rule, with a status line pointing at ADR 0059.
