# Clarification #667 - MCP connection: show the `claude mcp add` command line

## Round 1 - initial report (2026-10-01)

### Request

The MCP connection tab, on the web and in Sectile Desktop, gains a ready-to-run
`claude mcp add` command for the selected mode (remote HTTP, local HTTP proxy,
STDIO) when the provider is Claude, with its own Copy button, next to the JSON
snippet that stays. Out of scope: changing the JSON snippet, the agent-side
writer (`internal/agentconfig/mcp.go`), the "Update provider configuration"
action, and the custom-provider fallback.

### Code read

- `shared/mcpConfig.mjs`, `shared/mcpConfig.d.mts`: `mcpProviders`, `mcpSnippet()`.
- `web/src/components/MCPEngineConfig.tsx`: the web tab, its mode switch and Copy button.
- `web/src/locales/mcpConfig.ts`: FR/EN strings of the web tab.
- `desktop/src/mcp-settings.mjs`: the desktop tab, its hardcoded English strings
  and the "Update provider configuration" action (`api.configureMCP`).
- `internal/agentconfig/mcp.go`: `ConfigureMCP` / `BootstrapMCP`, which write the
  `sectile` entry into `~/.claude.json` with an absolute executable path.
- `web/tests/mcpConfig.test.mjs`: the existing snippet tests.
- `web/src/lib/commandTemplate.ts`: an existing POSIX `shellQuote` (not exported, web-only).

### Findings checked against the real CLIs

Run against a throwaway `HOME`, Claude Code CLI and Codex CLI on this workstation:

1. **The STDIO command proposed in the ticket fails.** `--env` is variadic in
   `claude mcp add`, so in `claude mcp add --scope user --env K=V sectile -- ...`
   it swallows `sectile` and the CLI answers
   `Invalid environment variable format: sectile`. The server name must come
   before `--env`: `claude mcp add --scope user sectile --env K=V -- sectile-agent mcp --url <server>`
   works. `--header` is variadic too, which is why it stays after the URL in the
   HTTP form (verified working).
2. **`claude mcp add` refuses an existing entry**: `MCP server sectile already exists in user config`.
   Desktop pairing (`BootstrapMCP`) already writes a `sectile` entry in
   `~/.claude.json`, so for most desktop users the bare `add` line fails on first
   use. `claude mcp remove --scope user sectile` clears it (and fails harmlessly
   when there is nothing to remove).
3. **Codex has a different CLI shape**: `codex mcp add <NAME> (--url <URL> | -- <COMMAND>...)`,
   with `--bearer-token-env-var` but no literal header option. A Codex remote
   command cannot carry the key inline the way the TOML snippet does; it needs
   the key in an environment variable, which is a different instruction to the user.

### Ambiguities (worst first)

1. Handling of the existing `sectile` entry (finding 2): a bare `add` line, a
   `remove` + `add` pair, or a hint. Product question Q1.
2. Codex in this ticket or a follow-up (finding 3). Product question Q2.
3. Scope fixed to `user` or selectable. Product question Q3.
4. Desktop: command as an alternative to "Update provider configuration" or a
   replacement. Product question Q4.

### Dependencies

- None on the server, the database or migrations: the change is in
  `shared/`, the web tab, the desktop tab, their tests and `CHANGELOG.md`.
- The command's correctness depends on the Claude Code CLI argument parser
  (finding 1); the unit tests pin the argument order so a regression is visible.

### Technical choices settled from the code (reversible)

- **One shared generator** `mcpCommand(provider, transport, server, local)` in
  `shared/mcpConfig.mjs`, declared in `mcpConfig.d.mts`, with the same signature
  and the same inputs as `mcpSnippet` (trailing slashes trimmed, `<SECTILE_API_KEY>`
  placeholder, `local` drops the header and empties the token). It returns `null`
  for a provider without a supported CLI, so each client hides the block.
- **Argument order** follows finding 1: name before `--env`, `--header` after the URL.
  Examples with a plain server URL, which needs no quoting:
  - Remote HTTP: `claude mcp add --transport http --scope user sectile https://sectile.example/mcp --header 'Authorization: Bearer <SECTILE_API_KEY>'`
  - Local proxy: `claude mcp add --transport http --scope user sectile http://127.0.0.1:8091/mcp`
  - STDIO: `claude mcp add --scope user sectile --env 'SECTILE_AGENT_TOKEN=<SECTILE_API_KEY>' -- sectile-agent mcp --url https://sectile.example`
- **Quoting**: POSIX single quotes (`'` escaped as `'\''`), applied only to an
  argument that contains a character outside `[A-Za-z0-9_./:=@%+-]`, so plain
  words stay readable. The placeholder always gets quoted, since `<` and `>` are
  redirections. Single-quoted strings are also literal in PowerShell, so the line
  works in bash, zsh and PowerShell for any value without a `'`; `cmd.exe` is not
  targeted. The quoter lives in `shared/mcpConfig.mjs`; the web `commandTemplate.ts`
  copy is left as is.
- **STDIO executable**: bare `sectile-agent`, as the JSON snippet shows, with the
  existing hint to use the installed binary path. The STDIO mode of both tabs is
  never `local` today, so its command always carries the key placeholder.
- **Language**: web strings go to `web/src/locales/mcpConfig.ts` in FR and EN;
  the desktop tab is English-only today, so its new strings are English.
- **Tests**: `web/tests/mcpConfig.test.mjs` covers the three modes, the argument
  order, the quoting of a URL with `'`, spaces and `$`, and `null` for the other
  providers; the desktop UI test `desktop/tests/mcp-settings.ui.cjs` checks the
  block and its Copy button.
- **Changelog**: one `Added` line under `[Unreleased]`.

### Product questions

- **Q1 - Existing `sectile` entry.** Recommended: show the `add` line alone and,
  under it, a hint "Already registered? Run `claude mcp remove --scope user sectile` first."
  Alternative: put both lines in the copied block (`remove` then `add`), which
  prints a harmless error when nothing is registered.
- **Q2 - Codex.** Recommended: a follow-up ticket, because its CLI cannot carry
  the key inline (finding 3) and needs its own instructions. Antigravity has no CLI.
- **Q3 - Scope.** Recommended: fixed `--scope user`. It writes the same
  `~/.claude.json` as the snippet and the agent, and `project` would write a
  `.mcp.json` into the checkout, which `BootstrapMCP` deliberately avoids.
- **Q4 - Desktop.** Recommended: keep "Update provider configuration" as the
  primary action (it writes the real pairing key and the absolute binary path)
  and show the command as an alternative, like the web.
