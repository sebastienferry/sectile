# Clarification #535 - Allow to open code

Ticket: https://github.com/sebastienferry/sectile/issues/535
Branch: `feat/535`

> Allow to open the code of the worktree with a little code icon next to the
> worktree path if configure in the dekstop app (vscode, custom...).

## Round 1 (2026-09-26)

### Restatement

In the desktop app, the toolbar line that shows the selected execution's
worktree path gains a small "code" icon button that opens that directory in the
editor configured on the workstation (VS Code, Cursor, Zed, or a custom
command). The web app, the macro panel, context repositories of multi-repo
projects, and any editor command templating (`{path}` placeholders) are out of
scope.

### What already exists

Most of the plumbing is there; nothing calls it from a client today.

- Desktop header: `#worktree` button + `#directory` label, one click copies the
  path (`desktop/src/main.js:42`, `showDirectory` at `:377`, click handler at
  `:391`). The path is `run.directory`, set by the local agent: the task
  worktree, or the project root when worktrees are off
  (`internal/agent/agent.go:1210`, `agent_run.go:280`, `agent_headless.go:105`).
- Desktop settings: an "Editor" free-text row (`editorCommand`, placeholder
  `code`, `desktop/src/main.js:1250`), stored in the workstation defaults
  (`internal/agentconfig/workstation.go:54`, `Settings.Editor()` at `:134`,
  `DefaultEditor = "code"` at `:22`).
- Launching: `runner.OpenInEditor` (`internal/runner/runner.go:1014`) splits the
  command, resolves known editors on macOS (`FindEditorBinary`, `code`,
  `cursor`, `zed`, ...), appends the path and starts the process detached.
- Agent operation `open_editor` (`internal/agent/agent_operations.go:398`,
  `editorFor` at `:441`) and server route `/api/open-editor`
  (`internal/handlers/handlers.go:3802`, `cmd/server/main.go:296`). No web or
  desktop code calls them.
- Neighbour feature to mirror: "Detach to native terminal"
  (`desktop/src/main.js:703`, IPC `detach-to-native-terminal` in
  `desktop/electron/main.cjs:346`, agent route `/desktop/terminal/detach`), and
  the terminal picker with presets plus a custom command
  (`terminalPicker`, `desktop/src/main.js:971`).

### Ambiguities (worst first)

1. **When the icon shows.** The ticket says "if configured". The Editor setting
   is optional and falls back to `code`. Reading A: the icon only appears when
   an editor is explicitly set. Reading B: it always appears and uses `code`
   when nothing is set. Different visibility rule and different empty-state.
   -> product question Q1.
2. **How the editor is configured.** "(vscode, custom...)" can mean the
   existing free-text field, or a picker like the terminal one (VS Code, Cursor,
   Zed, ..., Custom). Different settings UI. -> product question Q2.
3. **Which path is opened.** Settled below: the selected run's `directory`,
   i.e. exactly the path displayed.

### Critical dependencies

- The local agent must expose a new desktop route; an older agent does not have
  it. Handled like `task-engines`: a capability in `/desktop/status`, and a
  clear "update and restart the local agent" message otherwise.
- No migration, no server change, no tracker change. `editorCommand` keeps its
  current storage and name.
- The worktree may be gone (finished run after handoff): opening must fail with
  a readable error, not a silent no-op.

### Technical choices settled from the code (reversible)

- **Trust boundary.** The renderer sends a run ID, never a path. The agent
  resolves the directory from its own run registry (as `/desktop/terminal/detach`
  does with `runId`), checks it exists, and calls `runner.OpenInEditor` with
  `Settings.Editor()` (or the default, depending on Q1).
- **Transport.** New agent route `POST /desktop/open-editor {runId}`, new IPC
  `open-editor` in `desktop/electron/main.cjs`, exposed as `openEditor(runId)`
  in `preload.cjs`. The server's `/api/open-editor` is not used: the desktop
  talks to its own agent.
- **Placement.** A separate icon button right after the `#worktree` path button
  in `.worktree-line`, so a click on the path still copies it. Hidden whenever
  the path is hidden. Tooltip / aria-label: `Open in <editor>`.
- **Command format.** The existing contract is kept: the configured command is
  split on spaces and the path is appended (`cursor -n` works). No `{path}`
  placeholder.
- **Runtime strings** stay in English, like the rest of the desktop UI.
- **Changelog.** User-visible: one `Added` line under `[Unreleased]`.

### Product questions

- **Q1 - Visibility.** Show the icon only when an editor is set in Settings
  (reading A), or always, falling back to `code` (reading B)?
  *Recommendation: A*, it matches the ticket wording and never offers a button
  that fails because VS Code is not installed.
- **Q2 - Settings UI.** Keep the current free-text "Editor" field, or turn it
  into a picker like the terminal one (VS Code, Cursor, Zed, Sublime Text,
  Custom command)?
  *Recommendation: the picker*, the "(vscode, custom...)" wording points at it
  and `terminalPicker` is the pattern to reuse; the stored value stays a plain
  `editorCommand` string, so no migration.

## Round 2 - answers from the owner (2026-09-26)

### Settled choices

- **Q1 -> A.** The icon appears only when an editor is set in the desktop
  Settings. With no editor set, the header shows the path alone, as today. The
  `code` fallback of `editorFor` / `runner.OpenInEditor` stays for the existing
  server `open_editor` operation, but the new desktop route never falls back:
  it refuses when no editor is configured.
- **Q2 -> picker.** The "Editor" row becomes a picker built like
  `terminalPicker`: *None*, VS Code (`code`), Cursor (`cursor`), Zed (`zed`),
  Sublime Text (`subl`), *Custom command* (free text). The stored value stays the
  plain `editorCommand` string: *None* stores `""`, a preset stores its command,
  a stored value that matches no preset loads as *Custom command* with that
  text. No migration.

### Consequences recorded

- *None* is the picker's default and replaces the former `code` placeholder
  hint in the Settings row, since an empty value now means "no icon" rather
  than "VS Code".
- The icon's visibility is read from the workstation settings the desktop
  already loads (`workstationSettings`), and refreshed when they are saved.

### Reversed assumptions

None. Both recommendations of round 1 were accepted.

### Open product questions

None.
