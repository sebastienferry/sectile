## Round 1 (2026-09-25)

### Restated request and scope

Add a button to the ticket detail page that copies the ticket's identifier to
the clipboard in one click, with visible confirmation. Editing the key,
copying other fields (title, branch, URL), and changes to the board cards'
existing "Copier la référence" menu entry are out of scope.

### Verified findings

- The ticket has a title only: no description, no comments.
- The only ticket page is the web `TaskDetailModal`
  (`web/src/components/TaskDetailModal.tsx`). Both its layouts, panel
  (~L1568) and modal (~L1781), render the same `renderTaskRef()` badge
  (L480-525): `ParentKey / Key`, each an external link to the tracker. Clicking
  the key opens GitHub or Jira, so it cannot also serve as the copy action.
- The full internal id (`gh-<project>-431`) is never displayed. The user sees
  the key: `#431` for GitHub, `SFE-123` for Jira, the local key for a local
  board.
- The desktop app has no ticket page. Its execution header
  (`desktop/src/main.js` `renderHeader()`, L470-484) shows
  `taskKey · name · skill`. It already has a copy pattern (worktree path, IPC
  `copy-text`, "Copied" status text).
- Existing web copy patterns:
  - `handleCopySpec` (TaskDetailModal L686-697): `navigator.clipboard`, then a
    `Copy` → `Check` icon swap reset after 2 s, plus a success toast.
  - The `TaskCard` menu item "Copier la référence" (L733-742) copies
    `` `${key}: ${title}` `` and shows an info toast.
- UI strings are French. `web/src/locales/translations.ts` has similar
  wording ("Copier …", "… copié !").

### Ambiguities (worst first)

1. **What "ID" means.** It could be the displayed key (`#431`), the full
   internal id (`gh-…-431`), or `key: title` as the card menu does. Each
   reading copies a different string.
2. **Which client.** "Ticket page" exists only in the web app. The desktop app
   would need a button in its execution header, which is a different
   component and toolkit.
3. **Parent key.** The badge also shows the parent (`M-7`). Only the task key,
   or the parent as well?

### Reversible technical choices (resolved from the code)

- Placement: a small icon button right after the reference badge. The badge
  is shared by both layouts, so one change covers panel and modal.
- Feedback: follow `handleCopySpec`. The `Copy` icon becomes `Check` for 2 s
  and a success toast appears. The tooltip and `aria-label` read "Copier
  l'identifiant", in French like the rest of the page.
- Clipboard failure (insecure context, denied permission): an error toast and
  no icon swap, instead of a false confirmation.
- No backend, API or migration change.
- `CHANGELOG.md`: one `Added` line under `[Unreleased]`, since the change is
  visible to users.

### Critical dependencies

None. The change is web-only UI work, and `navigator.clipboard` is already
used on this page.

### Product questions (Round 1)

1. **What is copied?** Recommended: the key exactly as displayed (`#431`,
   `SFE-123`), which is what one pastes into a commit, a PR or a chat.
   Alternatives: the full internal id, or `key: title`.
2. **Which client?** Recommended: web only, because it has the only ticket
   page. The desktop execution header could follow in a separate ticket.
3. **Parent key?** Recommended: copy only the task key. The parent stays a
   link.

## Round 2 - answers from the owner (2026-09-25)

The Round 1 questions had not reached the ticket (the previous run was
canceled before posting them). They were asked in session instead.

### Settled decisions

1. **What is copied:** the key exactly as displayed (`#431`, `SFE-123`, or
   the local key). Not the internal id, not `key: title`. Recommendation
   accepted.
2. **Client:** web only, in `TaskDetailModal`. The desktop execution header
   is out of scope and may follow in a separate ticket. Recommendation
   accepted.
3. **Parent key:** one copy button per key. The parent key (`M-7`, or a Jira
   epic key) gets its own button, which copies the parent key alone. This
   **reverses** the Round 1 recommendation (task key only).

### Consequences resolved from the code

- With two buttons, one icon after the whole badge would not say which key it
  copies. Each button sits right after the key it copies, inside the badge
  rendered by `renderTaskRef()` (so both layouts, panel and modal, get it).
  The existing links keep opening the tracker.
- The parent button is rendered only when `parentKey` is set. A task without
  a parent shows a single button.
- Each button has its own tooltip and `aria-label`, naming the key it copies
  (for example "Copier M-7", "Copier #431"). The `Copy` → `Check` swap is per
  button, and the toast names the copied key.
- The button click must not trigger the neighbouring link (no navigation,
  `stopPropagation` is not needed since the button is not inside the anchor,
  but it must stay outside it).
- Clipboard failure: an error toast, no icon swap (unchanged from Round 1).
- `CHANGELOG.md`: one `Added` line under `[Unreleased]`.

### Settled scope

In scope: two copy buttons on the web ticket page (task key always, parent
key when present), with icon swap, toast and French labels.

Out of scope: the desktop app, copying the internal id, the title, the branch
or the URL, and the board card's "Copier la référence" menu entry.
