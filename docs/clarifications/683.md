## Round 1 (2026-10-02)

### Restated request and scope

In the Sectile Desktop "Changes" panel, the Rendered view of a Markdown file
displays the images whose target is a relative path to a file of the
repository, read from the same snapshot as the patch and the document, carried
by the agent and IPC rather than fetched by the window. Out of scope: remote
images (`http`, `https`, which stay unloaded), images in the conversation view
(which shares the renderer), raw HTML `<img>` tags (raw HTML stays text), and
any change to how links behave.

### Verified findings

Files read: `internal/runner/worktree_diff.go` (`inspectWorktree`,
`attachDiffDocuments`), `internal/agent/agent_diff.go` (capability constant),
`desktop/electron/main.cjs` (`git-diff` IPC handler), `desktop/src/gitDiff.js`,
`desktop/src/markdownView.mjs`, `desktop/src/conversation.js` (second user of
`renderMarkdown`), `desktop/src/style.css` (`.md-image`), `desktop/index.html`
(CSP), `docs/clarifications/575.md`.

- **The snapshot does not outlive the request.** `inspectWorktree` writes the
  worktree into loose objects under a temporary directory removed by
  `defer os.RemoveAll(temp)`, and `attachDiffDocuments` reads the Markdown
  contents from that tree before returning. An image request made later by
  Desktop would find no snapshot: to honour the "same snapshot tree"
  constraint, images must be read during the same inspection, or the snapshot
  must be kept alive between two requests.
- **The snapshot tree is the whole repository**, not only the changed paths:
  it starts from `read-tree <merge-base>` and applies the worktree changes. An
  unchanged image referenced by a changed document is therefore resolvable as
  `<tree>:<path>`, and a deleted document's images as `<merge-base>:<path>`.
- **Files left out of the snapshot** (over 8 MiB, past the 64 MiB snapshot
  budget, unsupported entries) are in the `omitted` map; the tree still holds
  their merge-base version, which is not the inspected state.
- **The current CSP blocks `data:` and `blob:` images.** `desktop/index.html`
  sets `default-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self';
  connect-src 'none'` with no `img-src`, so images fall back to
  `default-src 'self'`, which matches neither `data:` nor `blob:`. The ticket's
  two constraints, "CSP unchanged" and "images as `data:` or blob payloads",
  cannot both hold for an `<img>` element. → Question 1.
- **The renderer never creates an image today.** `markdownView.mjs` turns an
  image token into `{type:'image',src,alt}` and renders it as the text
  `[alt] (src)` in a `.md-image` span. The same renderer serves the
  conversation view, so image display must be an option passed by the Changes
  panel, with the alt-text rendering kept as the default.
- **Capability gating already exists for documents.** The agent advertises
  `markdown-documents` (`internal/agent/agent_diff.go`), and the `git-diff`
  IPC handler forwards it as `markdownDocuments`. A second capability follows
  the same path.
- Documents have their own 512 KiB per-file and 4 MiB per-response budgets,
  separate from the 4 MiB patch response limit, "so rendering them never
  removes a file or a patch from the raw diff". Images need the same
  separation.
- Note: #677 shipped Markdown files opening on Rendered by default, with the
  raw diff remembered per execution, which differs from round 2 of #575.
  Nothing in this ticket depends on it.
- The repository itself tracks PNG and SVG files (icons, web assets).

### Ambiguities (worst first)

1. **How an image reaches the page under the CSP.** `<img src="data:…">`
   needs an `img-src` directive; drawing a decoded bitmap on a `<canvas>`
   needs none but cannot show SVG and freezes animated GIFs. → Question 1.
2. **Which image formats are shown.** SVG is the usual format for diagrams in
   documentation; it is safe as an image (no script, no external fetch inside
   an image context) but only with the `<img>` route. → Question 2.
3. **The size bounds.** The ticket asks for per-image and per-response limits
   without values. → Question 3.

### Critical dependencies

- **Agent** (`internal/runner/worktree_diff.go`, `/desktop/git-diff`): read
  the referenced images from the snapshot during the same inspection, after
  the documents, bounded, with a per-image omitted reason. Advertised by a new
  `/desktop/status` capability (proposed name `markdown-images`).
- **Desktop renderer**: an image resolver option for `renderMarkdown`, used by
  the Changes panel only; the conversation view keeps alt text.
- **Desktop CSP**: depends on question 1.
- **IPC**: the `git-diff` handler forwards the new capability flag as it does
  `markdownDocuments`.
- **Changelog**: user-visible; the implementing pull request adds an `Added`
  line under `## [Unreleased]`.
- No database migration, no server change, no tracker impact.

### Technical choices resolved from the code and conventions

1. **Delivery in the same response.** Images are read during the inspection
   that produces the patch and the documents, because the snapshot is deleted
   when the request ends. Keeping a snapshot alive for an on-demand request
   would add a cache with a lifetime and eviction for no user-visible gain.
   The exact payload shape (an image table keyed by side and path, shared by
   the documents that reference it) is left to the specification.
2. **Which references.** Markdown image syntax only, inline and reference
   style (`![alt](path)`, `![alt][ref]`), as markdown-it parses them. Raw HTML
   `<img>` remains text, as today.
3. **Path resolution.** The target is percent-decoded, its query and fragment
   dropped, then resolved against the Markdown file's directory; a target
   starting with `/` resolves from the repository root, as GitHub does. A
   resolved path that leaves the repository (`..` above the root), is
   absolute on the filesystem, or carries a scheme (`http:`, `file:`, `data:`)
   is never read.
4. **Which side.** A new or modified document reads its images from the
   inspected tree; a deleted document (rendered as its old version) reads them
   from the merge-base tree, so a document and its images always describe the
   same state.
5. **What is not followed.** A symlink entry (mode `120000`), a submodule, a
   directory, a path in the snapshot's `omitted` map, or a missing path is not
   displayed. Git LFS pointer files fail the content check below.
6. **Type from the content, not the name.** The agent identifies the format
   from the leading bytes (PNG, JPEG, GIF, WebP, and SVG if question 2 keeps
   it) and sends the MIME type with the bytes; anything else is not displayed.
7. **Fallback.** An image that is not displayed keeps today's rendering
   (`[alt] (path)`), with its reason as the element's tooltip, for example
   "Image exceeds the 2 MiB display limit." or "Image not found in the
   inspected state." An older agent without the capability keeps the current
   alt-text rendering for every image, with no extra message.
8. **Layout and accessibility.** An image keeps its `alt` and `title`, is
   scaled down to the width of the rendered view (`max-width: 100%`), never
   up, and is not a link unless the Markdown wraps it in one (an external link
   then opens in the default browser, as links already do).
9. **Remote images.** `http` and `https` targets keep today's rendering; the
   CSP keeps blocking them in any case.

### Product questions (owner)

1. **CSP versus `data:` images.** Recommended: **(a) add the single directive
   `img-src 'self' data:`** to the Desktop CSP. It allows only inline image
   payloads already present in the page; `connect-src 'none'` and the rest stay
   as they are, and remote images remain blocked. Alternative: **(b) keep the
   CSP byte for byte** and draw each image on a `<canvas>` from a decoded
   bitmap: no SVG, animated GIFs show their first frame, and the alt text needs
   an ARIA label on the canvas.
2. **SVG.** Recommended: **display SVG** (requires 1a), shown through `<img>`,
   where scripts do not run and the SVG cannot load anything external.
   Alternative: raster formats only (PNG, JPEG, GIF, WebP), SVG falls back to
   alt text.
3. **Size bounds.** Recommended: **2 MiB per image and 8 MiB of image bytes
   per response** (before Base64 encoding, about 10.7 MiB on the wire), with
   images taken in document order, then reference order, until the budget is
   spent; each skipped image shows its reason. Alternative: tighter bounds
   (for example 1 MiB and 4 MiB, matching the document budget) to keep the IPC
   payload small.
