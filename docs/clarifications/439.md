## Round 1 (2026-09-25)

### Restated request and scope

When `processSkillJob` fails to rename its queued row to `agent_launch`, the row must
still end in a terminal status with a readable reason, so it leaves the one-run index
and the task accepts a new launch at once. Out of scope: the other failure paths of a
launch (they already close the row once renamed) and the reclaim of rows left by a
dead instance (#403).

### What was read

- `internal/db/db.go` `processSkillJob`: the rename, `StartAgentRun`, and the final
  `UPDATE ... SET skill_id='agent_launch', status=?, ... WHERE id=? AND status !=
  'canceled'`.
- `internal/db/migrations.go`: `idx_activities_one_active_run` counts a row when its
  status is `queued`, `pending` or `running` and its skill id is a stage skill or
  `remote_run`; `agent_launch` is not in the list.
- `internal/db/agentlaunch.go`, `internal/db/activerun.go`, `docs/db-concurrency-audit.md`.

### Verified findings

1. **The final close repeats the rename.** It sets `skill_id='agent_launch'` again in
   the same statement as the status, so whatever refused the rename most likely refuses
   the close, and the row stays `running` under its stage skill.
2. **A terminal status alone is enough.** The index predicate requires an active
   status, so `failed` takes the row out of it whatever its skill id.
3. **The failure can be forced in a test without a production hook.** A SQLite trigger
   raising on `UPDATE OF skill_id` to `agent_launch` refuses the rename and the
   combined close, and lets a status-only update through.

### Resolved technical decisions (reversible)

- **D1:** When the rename failed, the close updates the status, summary, error and
  completion time without touching the skill id, so the row ends `failed` under its
  own skill with the reason "Agent launch failed" and the database error.
- **D2:** The close is retried a few times with a short pause, since a database error
  can be transient; if it still fails, the failure is logged with the activity id,
  and reclaim remains the last resort.
- **D3:** A test forces the rename to fail and shows the row ends `failed` with its
  reason, and that a new launch on the same task is accepted.

### Open product questions

None. The acceptance criteria allow either a terminal status or a retried close; both
are applied.
