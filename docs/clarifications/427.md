### Existing behavior and evidence

- `internal/auth/oidc.go` implements Sectile as a client of an external identity provider. It reads issuer, client ID, secret and redirect URL from environment variables, discovers authorization, token and UserInfo URLs at startup, and rejects missing endpoints or an issuer mismatch.
- The same file implements authorization code exchange with PKCE and reads identity from the provider's UserInfo endpoint.
- `internal/handlers/auth.go` starts login, handles the callback, creates browser sessions and revokes the local session at logout. Local e-mail sign-in is disabled when a provider is configured.
- `cmd/server/main.go` registers `/auth/login`, `/auth/callback` and `/auth/logout`.
- `README.md`, "Signing in and pairing a workstation", documents the current configuration and mandatory sign-in behavior.
- `docs/adrs/0008-web-sign-in-through-openid-connect.md` establishes the external-provider design. Its historical implicit-user fallback is superseded by the local sign-in behavior visible in the current handler and README.
- `AGENTS.md` and `.agents/MEMORY.md` were consulted for workflow and project constraints.

These observations describe existing code, not a protocol compliance audit or a verified external-provider deployment.
