# Clarification #527 - Web i18n: task details, editing and specification actions

Batch #526 to #534; shared decisions D1 to D9 are in `docs/clarifications/526.md`.

## Round 1 (2026-09-26)

### Request

The task detail (drawer and centered modal) bypasses the catalog for many
actions: copy feedback, type fallback, the specification report and its full
screen view, the recommended step, the rewrite preview, assignee/team lookup
hints, the cross-tracker move confirmation, PR actions, comments, the clone
dialog and task notifications. They must follow the UI language, interpolating
task keys, project and provider names unchanged.

Out of scope: shared card and navigation controls (#526), quick-add (#455),
task content, tracker statuses and names.

`TaskDetailModal.tsx`, `TaskComments.tsx`, `CloneTaskModal.tsx`,
`CopyTaskSkillMenu.tsx`, `LookupField.tsx`, `PrioritySelect.tsx`;
`tests/issue-detail-layout.browser.mjs` and `tests/pr-state.browser.mjs`
(French assertions through `translations.fr`).

### Ambiguities

1. "Type: Défaut" is a Sectile fallback for a task without issue type:
   translated. The issue type names the tracker returns are not.
2. Comment and activity timestamps use the browser locale today: they move to
   the shared formatter (D4), in the UI locale.
