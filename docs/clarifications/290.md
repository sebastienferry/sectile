# #290 - Workflow & Status display

Round 1 - 2026-09-21 (unattended pickup)

## Request restated

The Board view and the Backlog (list) view both let the user switch between the status
grouping and the agentic workflow grouping, but each view renders its own toggle: different
order, labels, icon sizes and tooltips. Both toggles must become a single shared control so
the switch looks and behaves the same wherever it appears.

Out of scope: changing the grouping semantics, the workflow stages, the column
configuration, the sidebar behaviour, or adding the toggle to any other view.

## Files read

- `web/src/components/BoardView.tsx` (toolbar toggle, lines ~430-460)
- `web/src/components/ListView.tsx` (backlog toolbar toggle, lines ~714-742)

- `web/src/components/Sidebar.tsx` (consumer of `boardGrouping`)

## Divergences found

| Aspect | BoardView | ListView |
| --- | --- | --- |
| Button order | Workflow, then Status | Statuts, then Workflow Agentique |
| Labels | `Workflow` / `t.list.columns.status` | `Statuts` / `Workflow Agentique` |
| Icon size | 15 | 12 |
| Icon colour when inactive | amber-400 / cyan-400 | inherited |
| Container | `bg-[var(--bg-tertiary)]`, padding `px-2 py-1.5` | `bg-[var(--bg-secondary)]`, padding `px-2 py-1` |
| Tooltips | English, long | French, short |
| Responsive label | hidden below `md` | always visible |

## Ambiguities (resolved, reversible technical choices)

1. **Which rendering wins?** The Board toolbar is the reference: Workflow first, then Status.
   Rationale: the workflow pipeline is the product's differentiator and the board is the
   primary view. The backlog adopts it.
2. **Labels.** Short and identical in both views: `Workflow` and `Statuts`, taken from the
   translations module so they stay localised. The responsive `hidden md:inline` behaviour is
   kept and applies to both views.
3. **Sizing.** A single `size` prop (`sm` for the dense backlog toolbar, `md` for the board
   toolbar) covers the only legitimate difference; everything else (order, labels, icons,
   colours, tooltips, active state) is shared and non-configurable.
4. **Where does it live?** A new presentational component
   `web/src/components/BoardGroupingToggle.tsx` plus a pure options module
   `web/src/lib/boardGrouping.ts` holding the ordered option descriptors, so the ordering and
   labelling contract is unit-testable with `node --test` like the other `lib/` modules.

## Dependencies

None. No API, migration or third-party dependency; `boardGrouping` already lives in
`AppContext` and both views already consume it.

## Open product questions

None. The ticket is a UI consistency defect and every remaining choice is reversible and
settled above.
