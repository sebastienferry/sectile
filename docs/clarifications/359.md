Title: "Move Agents CLI settings to Desktop only"

## Round 1 — analysis (2026-09-22)

### Restated request and scope

Move the configuration of AI Agent CLIs (provider selection, model selection, interactive/autonomous command templates, and presets) out of the central web server and web interface (`ProfileModal`, `ProjectModal`) so that they are managed exclusively on the developer's workstation via the Desktop app and `~/.config/sectile/settings.json`.
Out of scope: SDD skill prompt customization (`promptClarify`, `promptSpecify`, `promptImplement`, `promptAdjust`, `promptHandoff`) and SDD framework selection (`speckit`/`openspec`), tracker credentials, and the core agent daemon execution loop beyond how it resolves CLI settings locally.

### Verified findings

1. **The Parallelism precedent (`cfdd63b`)**: Previously, execution parallelism was stored in `projects.parallelism` on the server and edited in `ProjectModal.tsx`, with an awkward "Inherit from server" in Desktop. Commit `cfdd63b` eliminated the web picker and `models.Project.Parallelism`, making parallelism workstation-only stored in `~/.config/sectile/settings.json`.
2. **Current state of AI CLI settings**:
   - Web `ProfileModal.tsx` contains an `aiEngine` tab ("Paramètres de l'agent" / "Agent settings") configuring server-wide `aiProvider`, `aiModel`, `aiProviderModels`, and CLI interactive/autonomous command templates.
   - Web `ProjectModal.tsx` contains an "Agents & IA" section under the `agent` tab allowing per-project override of `aiProvider`, `aiModel`, `aiCommandTemplate`, and `aiCommandTemplateAutonomous`.
   - Desktop already supports local per-project overrides for `aiProvider`, `aiModel`, `aiCommandTemplate`, and `aiCommandTemplateAutonomous` in `desktop/src/main.js`, but it still queries server defaults, displays "Inherited from server", and offers "Reset to server default" buttons.
   - Desktop has no global AI settings panel: `openSettings()` has General, Profile, Connection, Logs, but no AI/CLI category. Workstation-wide defaults (`overrides.AIProvider`, `overrides.AIModel`, `overrides.AICommandTemplate`) are supported in `internal/agentconfig/local.go`, but there is currently no UI in Desktop to configure them.
3. **The `SupportsAutonomousRun` preflight in `internal/db/db.go`**:
   - `EnqueueFullChainRun` validates `models.SupportsAutonomousRun(project.AIProvider, project.AICommandTemplate, project.AICommandTemplateAutonomous)`. If the server no longer stores the provider or command template, this server-side preflight will fail or be meaningless without knowing the workstation's configuration. As noted in `MEMORY.md` §10 (line 151), autonomous run capability validation must be handled on the agent.

### Dependencies and constraints

- Workstation settings file: `~/.config/sectile/settings.json` is owned by the local machine and never committed or uploaded to the server (`agentconfig.Overrides`).
- Backward compatibility & database schema: Similar to `parallelism`, database columns in SQLite (`projects.ai_provider`, `settings.ai_provider`, etc.) can remain unwritten without requiring destructive table migrations, adhering to ADR 0021.
- English-only documentation and code identifiers.
- Testing: Desktop changes require `cd desktop && npx vite build && npm test && npm run test:ui` (as pinned in `MEMORY.md` §11). Web changes require `npm test && npx tsc --noEmit && npx oxlint src` in `web/`.

### Reversible technical decisions (taken here)

- Align with the parallelism architecture (`cfdd63b`): CLI settings belong strictly to the workstation executing them.
- Keep `MCPEngineConfig` (direct MCP connection guides for Claude/Codex/Cursor/AGY) accessible, moving it to the `workstations` tab in `ProfileModal.tsx` since connecting an external CLI directly to the server's MCP endpoint is a workstation-setup activity.
- Preserve prompt customizations (`promptClarify`, `promptSpecify`, etc.) in Web under `sdd` / Skills tabs, because prompts define the development method, not the local binary execution flags.

### Open product questions

1. **Scope of removal in Web UI**:
   Should the entire `aiEngine` tab in `ProfileModal.tsx` be removed from the web interface, and the "Agents & IA" section in `ProjectModal.tsx` also be completely removed?
   *Recommendation: Yes. Remove the `aiEngine` tab from `ProfileModal.tsx` (moving the direct MCP instructions to the `workstations` tab) and remove the custom AI CLI section from `ProjectModal.tsx`. CLI parameters and providers will no longer be configured in the web UI.*

2. **Global Workstation AI Settings in Desktop**:
   Since CLI settings will no longer have a server default to fall back to, should Desktop add a new "Agents CLI" category in its main Settings dialog (`openSettings`), allowing developers to configure their workstation-wide default AI Provider (e.g. AGY, Claude, Codex), default model, and default command templates?
   *Recommendation: Yes. Add an "Agents CLI" tab to Desktop's `openSettings()`. Project settings in Desktop will then inherit from the workstation's default rather than a server default.*

3. **Desktop Project Settings Inheritance**:
   In Desktop's project settings dialog, should the reset buttons and hints change from "Reset to server default" / "Inherited from server" to "Reset to workstation default" / "Inherited from workstation"?
   *Recommendation: Yes. Project settings will inherit from the global workstation configuration defined in Desktop settings, with clear "Inherited from workstation" / "Local override" labels.*

4. **Handling of `EnqueueFullChainRun` server pre-flight**:
   How should the server validate whether an autonomous run / full chain can be executed if it no longer stores `aiProvider` and `aiCommandTemplate`?
   *Recommendation: The server delegates execution capability validation to the local agent when the job is received, or defaults `SupportsAutonomousRun` to true on the server and lets the agent daemon reject unexecutable headless modes locally before dispatching.*

5. **Database columns and API payloads**:
   Should `ai_provider`, `ai_model`, `ai_command_template`, etc. in `models.Project` and `models.Settings` be marked deprecated/ignored, or cleanly removed from project creation/update payloads like `parallelism` was?
   *Recommendation: Cleanly remove them from the active web update payloads and project models, keeping the DB columns unwritten/ignored to prevent breaking existing databases without complex migrations.*

## Round 2 — answers from the owner (2026-09-22)

The owner answered all five open product questions. Decisions are recorded below:

1. **Web UI Scope (Reversed Assumption)**:
   - Prior recommendation in Round 1 suggested removing the entire `aiEngine` tab and all engine configuration.
   - **Settled**: The `aiEngine` tab in `ProfileModal` and the engine section in `ProjectModal` are **kept** for choosing the AI engine/provider (`aiProvider`) and model (`aiModel`, `aiProviderModels`).
   - The CLI command template portion (`aiCommandTemplate`, `aiCommandAutonomous`, presets, variable buttons, previews) is **removed** from both `ProfileModal` and `ProjectModal`.
   - Direct MCP snippets (`MCPEngineConfig`) move to the `workstations` tab.

2. **Global Workstation Settings in Desktop**:
   - An "Agents CLI" category is added to Desktop's main Settings dialog (`openSettings`) to configure workstation-wide default provider, model, and interactive/autonomous command templates stored in `~/.config/sectile/settings.json`.

3. **Desktop Project Settings Inheritance**:
   - Project settings in Desktop inherit from the workstation default (with "Inherited from workstation" and "Reset to workstation default" indicators), replacing server inheritance for CLI commands and engine defaults.

4. **Full Chain Autonomous Preflight**:
   - The server-side `SupportsAutonomousRun` preflight in `EnqueueFullChainRun` is removed; autonomous capability validation is delegated to the local agent daemon upon receiving the chained job.

5. **Server Database and API Payloads**:
   - Cleanly drop CLI template fields (`aiCommandTemplate`, `aiCommandTemplateAutonomous`) from active web update/create payloads and models, following the exact precedent set by `parallelism` in `#cfdd63b` (existing DB columns remain unwritten/ignored).

### Settled scope

- **In scope**:
  - Web UI: Remove CLI command template configuration, fast presets, and live command preview from `ProfileModal.tsx` and `ProjectModal.tsx`. Move `MCPEngineConfig` to the `workstations` tab in `ProfileModal.tsx`. Keep AI engine and model selection in both modals.
  - Desktop UI: Add an "Agents CLI" category in `openSettings()` for global workstation defaults. Update Desktop project settings to inherit from workstation defaults instead of server defaults.
  - Server & Agent: Drop CLI command templates from web update/create requests. Remove the server-side `SupportsAutonomousRun` check in `EnqueueFullChainRun`, delegating the check to the local agent daemon.
- **Out of scope**:
  - SDD skill prompt customization (`promptClarify`, `promptSpecify`, etc.), which remains in Web under `sdd` / Skills tabs.
  - Destructive SQLite schema migrations (columns `ai_command_template` and `ai_command_template_autonomous` remain in the database schema unwritten).

Round 2 closed. Exit condition **met**: all open questions are resolved, decisions and scope are settled.
