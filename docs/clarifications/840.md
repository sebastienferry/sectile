Ordinary creation already includes both the in-app link and the optional tracker link. Ordinary update and cloning omit them. Macro story creation reuses the creation link when an imported task is available; createStoryFromMacroTodo deliberately omits it for a tracker-only story without a local ID. Move and export notifications also omit task links. Bulk edits inherit one success toast per updateTask call.

### Ambiguities, worst first

1. Does "Creation / Update" cover only the ordinary creation/update handlers, or also cloning, macro story creation, move and export? Different answers change the set of producers to modify.
2. Does "link" mean the existing internal Open action plus optional tracker icon, or a direct tracker link? Tracker-only stories cannot use the current internal callback; local tasks have no tracker URL.
3. Does "always" include warnings and failed writes, or only successful operation notifications? Creation can succeed while priority or macro attachment fails, producing separate warnings; missing-token errors already offer a credentials action.

### Recommended baseline, awaiting owner confirmation

- Cover successful creation through every WebUI issue creation entry point (ordinary creation, clone, and macro stories), plus ordinary edits through updateTask, including its bulk callers.
- Keep move/export, macro edits, warnings and failed writes outside this ticket.
- Reuse the current internal Open action with a separate tracker link when a local task exists. For tracker-only creation, offer a direct tracker link when the response provides its URL; never fabricate an internal task.
- Leave existing toast styling, dismissal, lifetime, pause behaviour and automatic opening after cloning intact.

### Reversible technical choices

Reuse the toast navigation pattern and the returned task object, so the detail view receives the updated data. Generalize the creation helper's name if it is reused for edits; existing Open wording is already operation-neutral. Keep both locale catalogs consistent if any new wording is needed. Do not introduce a new dependency or migration.

### Dependencies and acceptance implications

The ordinary update and clone responses already return Task objects, sufficient for navigation. Tracker-only story creation must be checked for a usable externalUrl during specification if included; the current ToastLink contract cannot represent an external-only action without a callback. No third-party quota, new service or schema migration is identified for the narrow scope. The implementation will need a user-facing changelog entry under Unreleased.
