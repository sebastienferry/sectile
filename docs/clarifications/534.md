# Clarification #534 - Web i18n: document language, date formatting and translation regression checks

Batch #526 to #534; shared decisions D1 to D9 are in `docs/clarifications/526.md`.

## Round 1 (2026-09-26)

### Request

The page keeps `lang="fr"` and a French title in English; dates follow the
browser locale in some places and a forced `fr-FR` in others. Set the document
language and title from the UI locale (startup and signed-out views
included), provide shared locale-aware date, time, number and count
formatting, migrate the call sites, and add a lightweight bilingual
regression suite plus a documented browser check matrix.

Out of scope: screen-specific copy (companion tickets); pre-authentication
locale selection (#533).

### Code read

`web/index.html`, `main.tsx`, `App.tsx`, `AppContext.tsx` (theme effect),
`lib/sprints.ts`, `lib/elapsed.ts`, date call sites in `TaskDetailModal.tsx`,
`TaskComments.tsx`, `ActivitiesView.tsx`, `SkillsView.tsx`, `TeamView.tsx`,
`AdminView.tsx`, `UsersPanel.tsx`, `ApiKeys.tsx`; the test runner
(`node --test tests/*.test.mjs`) and the Playwright browser harnesses.

### Ambiguities

1. English date style: `en-US` (the default for `en`), `fr-FR` for French.
2. Instants (timestamps) are shown in the viewer's time zone; date-only values
   are calendar dates, never shifted by the time zone (D4).
3. Regression checks: catalog parity (same keys, non-empty values, same
   placeholders in both languages), helper unit tests, and rendered browser
   checks of representative components in English asserting accessible names.
   No accent detector.

### Decisions

D4 and D5 are owned here; the check matrix lives in
`docs/web-translation-checks.md`.
