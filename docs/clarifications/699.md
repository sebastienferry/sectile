## Round 1 (2026-10-02)

### Restated request and scope

In a Sectile Desktop conversation (#696), the status shown in the composer
toolbar is plain, static text: nothing on screen moves while Claude Code works,
so the owner cannot tell at a glance that the model is busy. The request is to
give that status indicator an animation while the model is working.

Out of scope: the run console and the sidebar/ticket run-state icons (the
`running` state already pulses, `desktop/src/style.css:339-342`), the web app,
the wording of the status sentences, and any change to how the agent computes
`busy` or `approvals`.

### Files read

- `desktop/src/conversation.js`: the composer markup (line 30) holds a
  `<span class="conversation-status" role="status">`; its text is chosen at
  line 142 (`Read-only history`, `Claude is asking you a question`,
  `Waiting for your approval`, `Claude Code is working…`, `Ready`) and
  overwritten at lines 160 (notice), 167 (`Stopping the answer…`),
  329 (send error), 351 (`Running in the shell…`, `Checking MCP servers…`,
  `Claude Code is working…`) and 359 (`Loading conversation…`).
- `desktop/src/style.css`: `.conversation-status` (line 591) is faint 11px
  text with no state styling; existing animations: `run-state-pulse`
  (lines 339-342) and the streaming caret `conversation-caret` (lines 563-565),
  both disabled under `prefers-reduced-motion: reduce`.
- `desktop/src/tool-cards.mjs`: a pending tool call shows the static word
  `running…` (line 168).
- `internal/agent/agent_conversation_approvals.go`: an `AskUserQuestion` call
  is surfaced as a pending approval; while it is pending the model is waiting
  for the owner, not generating.

### Ambiguities (worst first)

1. **Which status animates.** The ticket quotes "Claude is asking a question"
   but asks for an animation meaning "the LLM is working". In the code these are
   two different states: while `AskUserQuestion` is pending, the model is idle and
   waits for the owner. Reading A animates only the working states; reading B
   also animates the question/approval states. They lead to different code and
   a different message to the owner.
2. **Form of the animation.** A small pulsing/spinning glyph before the text,
   a shimmer over the text itself, or animated ellipsis. Each is a distinct
   visual; none exists today in the composer.
3. **Whether the question/approval state gets its own, distinct look** (e.g. the
   `--waiting` colour already used by `.task-skill-status.waiting`) so that
   "Claude needs you" and "Claude is busy" are told apart at a glance.

### Critical dependencies

- None on the server, the agent or the database: `busy` and `approvals` are
  already delivered by the conversation poll.
- The status text is written from six places in `conversation.js`; the
  animation must follow a state, not the text, so a state attribute
  (e.g. `data-state="working|asking|idle"`) has to be set at each of them.

### Reversible technical choices (settled from conventions)

- CSS-only animation driven by a `data-state` attribute on
  `.conversation-status`, in the style of `.run-state[data-run-state=running]`.
- Disabled under `@media (prefers-reduced-motion: reduce)`, like the two
  existing animations.
- Working states = `busy` from the poll, plus the transient client-side
  states `Running in the shell…`, `Checking MCP servers…`,
  `Stopping the answer…` and `Claude Code is working…` after a send.
  `Loading conversation…` is treated as working too. `Ready`,
  `Read-only history`, notices and errors never animate.
- The sentences keep their current wording; `role="status"` stays as is, the
  animated glyph is `aria-hidden`.
- A `Changed` line under `## [Unreleased]` in `CHANGELOG.md` (user-visible).

### Product questions (owner)

1. **Should "Claude is asking you a question" animate?**
   Recommended: **no**. Animate only while Claude Code is actually working;
   a pending question or approval is the model waiting on you, and an
   animation there would say the opposite. If you saw "asking a question"
   displayed while Claude was in fact still working, say so: that is a
   different bug (stale approval) to file separately.
2. **What animation?**
   Recommended: **a small pulsing dot in the accent colour before the status
   text**, reusing the existing `run-state-pulse` rhythm, so the conversation
   and the run icons speak the same visual language.
   Alternatives: a shimmer sweeping across the text (as Claude Code's CLI
   does), or animated ellipsis.
3. **Should the question/approval state get a distinct static look?**
   Recommended: **yes**, the text in the `--waiting` colour with a static
   dot, so it stands out from both "working" and "Ready".
