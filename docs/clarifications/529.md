# Clarification #529 - Web i18n: roadmap, triage and team workload views

Batch #526 to #534; shared decisions D1 to D9 are in `docs/clarifications/526.md`.

## Round 1 (2026-09-26)

### Request

The Roadmap, Triage and Team views hardcode French tabs, filters, empty states,
batch assignment forms, selection counts and feedback. They must be bilingual,
with consistent translated horizon terms, while stored horizon keys and
user-authored names stay unchanged.

Out of scope: sprint lifecycle dialogs (#530).

### Code read

`RoadmapView.tsx`, `MacroTaskRow.tsx`, `MacroLabelGroups.tsx`,
`MacroRealignButton.tsx`, `TriageView.tsx`, `CurationTable.tsx`,
`TeamView.tsx`, `lib/roadmap.ts` (horizon keys `now`, `next`, `future`, labels
`NOW`, `NEXT`, `FUTURE`), `lib/macroRuns.ts`, `lib/labelAxes.ts`.

### Ambiguities

1. Horizon terms: `NOW`, `NEXT`, `FUTURE` are product vocabulary already used
   in both languages (`Roadmap : NOW / NEXT / FUTURE` in the catalog). They
   stay as they are in both locales; the descriptions and hints around them
   are translated. The stored keys are untouched.
2. Counts ("3 tickets sélectionnés") use `plural` (D3).
