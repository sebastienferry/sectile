# Clarification #703 - Desktop: keep settings controls clear of the macOS overlay scrollbar

## Round 1 (2026-10-02)

### Restatement

In Sectile Desktop's settings dialog, the controls of a panel that scrolls sit
flush with the panel's right edge, so on macOS the overlay scrollbar (about
15 px, drawn over the content) catches clicks meant for them. The fix gives
every scrolling settings container a right gutter wide enough for an overlay
scrollbar, so the reset buttons of Execution defaults are clickable across
their whole width and `workstation-settings.ui.cjs` passes on macOS.

Out of scope: restyling the scrollbar itself (no `::-webkit-scrollbar`
theming), the web app's settings, other scrolling areas of the desktop app
outside the settings dialog (task lists, conversation, log reader), and any
change to the reset buttons' size or layout.

### Code read

- `desktop/src/style.css:374`: `.settings-content{overflow-y:auto;padding-right:6px}`.
- `desktop/src/style.css:405-412`: in the workstation dialog
  (`.settings-content.stretch`), the scrolling element is each panel
  `section` other than `#settings-panel-Logs`, which has no right padding at all.
- `desktop/src/main.js:1720-1740` (`openSettings`, workstation dialog, `stretch`)
  and `desktop/src/main.js:2096` (project settings, plain `.settings-content`,
  which scrolls itself with the 6 px padding).
- `desktop/src/main.js:1016` (`settingRow`) and `:1462` (the
  "Reset custom project skills win to default" row): the reset button ends the
  `.setting-control` flex row, right-aligned against the container edge.
- `desktop/tests/workstation-settings.ui.cjs:190-225`, the failing test.

### Ambiguities (worst first)

1. **Which element gets the gutter.** Two scrolling shapes exist: the
   workstation dialog scrolls each panel `section`, the project settings dialog
   scrolls `.settings-content` itself (6 px, also too narrow). Settled below:
   both.
2. **How the gutter is made.** `scrollbar-gutter: stable` reserves space for
   classic scrollbars only; the spec excludes overlay scrollbars, so it does
   not fix macOS "Automatic". Settled below: plain right padding.

### Dependencies

None: CSS in `desktop/src/style.css`, one UI test, the changelog. No server,
agent, migration or web change.

### Settled technical choices (reversible)

- A shared right gutter of 16 px (one overlay scrollbar of about 15 px plus a
  pixel) on every scrolling settings container: the workstation panel sections
  (`.settings-content.stretch>section:not(#settings-panel-Logs)`) and the
  project dialog's `.settings-content`. In the `stretch` case the outer
  `.settings-content` does not scroll, so its 6 px is not stacked on top.
- The log reader (`#settings-panel-Logs`) is left as is: it does not scroll as
  a panel, its reader scrolls inside a bordered box with no controls on its
  right edge.
- The narrow layout (`max-width:720px`) keeps the same gutter.
- Test: the existing click in `workstation-settings.ui.cjs` already covers the
  macOS case. A new platform-independent assertion checks geometry instead of
  relying on the host's scrollbar style: once Execution defaults is scrolled,
  the right edge of each reset button is at least 15 px inside the panel's
  `clientWidth`. A positioned click (`position:{x:2,y:...}`) is rejected: it
  would hide the defect rather than fix it.
- Changelog: one `Fixed` line under `## [Unreleased]`, written for users.
