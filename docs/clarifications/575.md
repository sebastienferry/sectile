## Round 1 (2026-10-01)

### Restated request and scope

In the Sectile Desktop "Changes" view, when the selected changed file is a
Markdown file, a toggle lets the reader switch between the raw diff and a
rendered Markdown view of that file. Out of scope: editing the file, a
Markdown preview anywhere else (web app, ticket descriptions, conversation
view), rendering other formats (HTML, AsciiDoc, MDX, notebooks), and a
general-purpose file browser.

### Verified findings

Files read: `desktop/src/gitDiff.js`, `desktop/src/main.js` (wiring of
`createGitDiff`), `desktop/electron/main.cjs` (`git-diff` IPC handler, window
navigation guards), `desktop/electron/preload.cjs`, `desktop/index.html` (CSP),
`desktop/src/style.css` (`.diff-*` rules), `desktop/src/conversation.js`
(`renderConversationText`), `desktop/src/changelog.mjs`,
`internal/runner/worktree_diff.go`, `web/src/components/TaskDetailModal.tsx`,
`web/package.json`, `desktop/package.json`, `docs/clarifications/81.md`.

- The only diff viewer in the product is the Desktop "Changes" panel built in
  #81 (`desktop/src/gitDiff.js`). Per ADR 0003 and `docs/clarifications/81.md`,
  the web app has no diff view; the "Git Diff Button" slots in
  `TaskDetailModal.tsx` are empty comments.
- The agent endpoint `GET /desktop/git-diff` (`InspectWorktree`) returns, per
  file, only a unified `git diff --patch` with the default 3 lines of context,
  capped at 256 KiB per file and 4 MiB per response. **It never returns the
  full file contents.** A rendered view of a whole Markdown document therefore
  cannot be built from what Desktop receives today: the agent must expose the
  file's content (new side, and old side for a deleted file).
- The patch is computed against a temporary tree snapshot of the worktree
  (committed + staged + unstaged + untracked), so the content shown must come
  from that same snapshot, not from a later read of the working directory, or
  the rendered view and the diff can disagree.
- Desktop has no Markdown engine. Its two existing renderers are hand-written
  subsets that build DOM nodes and never inject HTML
  (`renderConversationText`, `parseChangelog`). The web app uses
  `react-markdown` + `remark-gfm`, which cannot be reused in the vanilla-JS
  Desktop renderer.
- The Desktop window is already hardened: CSP `default-src 'self'`,
  `connect-src 'none'`, `will-navigate` prevented, `window.open` denied.
  Remote images are therefore blocked by the CSP, and a clicked link would do
  nothing unless explicitly routed to `shell.openExternal`.
- The agent advertises features through `/desktop/status` capabilities
  (`git-diff`, `claude-conversation`); Desktop already degrades with "Update
  and restart the local agent" when one is missing.

### Ambiguities (worst first)

1. **What "rendered" shows.** (a) the whole file at the inspected state,
   rendered; (b) a rich diff, rendered blocks with additions and deletions
   highlighted, as GitHub's "rich diff"; (c) only the hunks of the patch,
   rendered. (c) yields broken Markdown (half lists, unclosed fences); (b) is
   several times the work of (a). → Question 1.
2. **Default and memory of the toggle.** Opened on raw diff or rendered; kept
   when selecting another Markdown file; kept across Desktop restarts. →
   Question 2.
3. **Links and images inside the rendered document.** → Question 3.

### Critical dependencies

- **Agent API change** (Go, `internal/runner/worktree_diff.go` and the
  `/desktop/git-diff` handler): expose Markdown file contents from the
  inspection snapshot, behind a new capability so an older agent keeps the
  current behaviour (toggle hidden or disabled with the usual "update the
  agent" message). Whether contents ride in the existing response or come
  from a second on-demand request is a specification choice; the 4 MiB
  response cap argues for on-demand.
- **A Markdown renderer in Desktop**: a new npm dependency or an extended
  hand-written subset. Either way, raw HTML in the document is never
  interpreted (engine output and repository files are untrusted).
- **Changelog**: user-visible, so the implementing PR adds an `Added` line
  under `## [Unreleased]`.
- No database migration, no tracker impact, no server (non-agent) change.

### Technical choices resolved from the code and conventions

1. **Surface:** Sectile Desktop "Changes" panel only (ADR 0003, #81).
2. **Which files:** paths ending in `.md` or `.markdown`, case-insensitive.
   `.mdx` is excluded (JSX, not Markdown). Files whose `kind` is not `text`,
   or whose content is omitted by a size limit, show no toggle or a disabled
   one with the reason, like the existing `omittedReason`.
3. **Deleted file:** the rendered view shows the old version, labelled as
   such. Added / modified / renamed files show the new version.
4. **Safety:** raw HTML blocks and inline HTML are shown as text, never
   interpreted; nothing in the rendered view can navigate the Desktop window.
5. **Source of truth:** the rendered content is read from the same snapshot
   tree as the patch, so both views describe the same state.
6. **Accessibility:** the toggle is a button with `aria-pressed`, consistent
   with the existing Console / Changes buttons; the rendered view keeps the
   `.diff-patch` scroll area and focusability.
7. **Supported Markdown:** CommonMark + GFM tables, task lists,
   strikethrough and fenced code (no syntax highlighting). Mermaid diagrams
   and math are shown as code blocks.

### Product questions (owner)

1. **Rendered content.** Recommended: **(a) the whole file at the inspected
   state, rendered**, without highlighting what changed; a rich diff (b) can
   be a follow-up ticket. Alternatives: (b) rich diff now; (c) render only the
   patch hunks.
2. **Toggle behaviour.** Recommended: opens on the **raw diff** (current
   behaviour unchanged); once switched to "Rendered", the choice **sticks for
   other Markdown files** selected in the same Desktop session, and resets
   when Desktop restarts. Alternative: remembered across restarts, or opened
   on "Rendered" by default for Markdown files.
3. **Links and images.** Recommended: `http(s)` and `mailto` links open in
   the default browser; relative links (to other repository files) and
   anchors are shown but inert; images are **not loaded** (the CSP already
   blocks remote ones) and appear as their alt text with the target path.
   Alternative: also display images stored in the repository (relative
   paths), which needs the agent to serve them from the snapshot.

## Round 2 - answers from the owner (2026-10-01)

The owner answered the three questions of round 1 interactively and chose the
recommended option each time.

### Settled decisions

1. **Rendered content:** the whole Markdown file at the inspected state
   (snapshot tree), rendered, without highlighting what changed. A deleted file
   renders its old version, labelled as such. A rich diff (rendered blocks with
   additions and deletions highlighted) is out of scope and may become a
   follow-up ticket.
2. **Toggle behaviour:** the "Changes" panel opens a Markdown file on the raw
   diff, as today. Once the reader switches to "Rendered", that choice sticks
   for every other Markdown file selected in the same Desktop session; it is
   not persisted and resets to the raw diff when Desktop restarts. Non-Markdown
   files always show the raw diff.
3. **Links and images:** `http`, `https` and `mailto` links open in the default
   browser (through the main process, never by navigating the window).
   Relative links to other repository files and in-page anchors are displayed
   but inert. Images are never loaded: each is replaced by its alt text and
   target path.

### Reversed assumptions

None. The technical choices of round 1 stand.

### Remaining dependencies (for the specification)

- Agent: expose the Markdown file content from the inspection snapshot behind a

- Desktop: a Markdown renderer with raw HTML disabled (new dependency or
