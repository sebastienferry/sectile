## Round 1 (2026-09-25)

### Restated request and scope

Every setting that only matters to *how* a workstation runs an AI CLI
(provider, models, command templates, terminal, editor, worktrees,
parallelism, setup providers, per-skill command names, checkout paths) is
resolved from `~/.config/sectile/settings.json` by the local agent, edited
from the desktop app, and no longer stored, served or edited by the server
and the web interface. The method (skills, specification framework, workflow
limits), identity, secrets, tracker, sync, board mirror and web presentation
stay on the server; merging `/pickup-issue` with the server-orchestrated full
chain is out of scope.

### Verified findings: where the ticket no longer matches the code

The ticket predates #456/#470 (multi-repo), ADR 0027 and ADR 0028. Its
line numbers are stale, and several statements are now inaccurate:

1. **The headless pre-flight is already on the agent (ticket impact 3).**
   `EnqueueFullChainRun` (`db.go:5139`) checks only the stop stage and the
   next step; it reads no provider. The refusal is
   `models.SupportsAutonomousRun`, called by the agent
   (`agent.go:999-1011`, `agent_run.go:238-247` `admitProjectRun`) on the
   configuration *after* `ApplyOverrides`, i.e. against the workstation
   provider. What is missing is an up-front refusal: the chain is queued and
   its first step fails on the agent.
2. **`resolveLaunchProviderModel` is now `ResolveTaskEngine`
   (`db.go:5279`)** and already says its result is a guess until the agent
   reports. The agent reports through `POST /api/activities/{id}/engine`
   (`postRunEngine`, fire-and-forget).
3. **`get_project_context` does change (ticket impact 7).** `sessionContext`
   (`taskmcp/server.go:151-156`) serves `useWorktrees`, `aiProvider` and
   `aiModel` from the server-composed configuration, i.e. the values this
   ticket makes wrong.
4. **The skill command name already reaches the prompt on the agent (impact
   6).** `db.AgentConfig` copies `Project.SkillOverrides[id]` into
   `Skill.Command`; the agent builds the prompt in `dispatchCommand`
   (`agent_config.go:815-839`). The server-side substitution
   (`applySkillCommandOverride`, `ProjectSkillCommand`) is dead code.
5. **`Dispatch.TerminalOverride` is never read by the agent.**
   `dispatchTerminal` has no non-test caller; desktop launches use
   `resolveTerminalForProject` (explicit, local project, local global, server
   config, `--terminal`, autodetect). The server fills the DTO from the
   project then the *deployment* row, not from `user_settings`.
6. **`editorCommand`** is resolved server-side from the caller's
   `user_settings` (`HandleOpenEditor`, `handlers.go:3700-3735`) and falls
   back to the deployment `settings.editor_command` (`'code'`). No local
   override exists. No web code calls `open-editor` or edits the field.
7. **`ttyMode`** is stored, scanned and written, but no code branches on it;
   the web has the type only, the desktop nothing.
8. **`setupProviders`** has no web UI, and `ProjectModal` always sends
   `setupProviders: []`, wiping the stored value on every save. The agent
   consumes it for scaffolding.
9. **`aiProviderModels`** feeds the web launch picker (`TaskCard.tsx:401`),
   `ProjectModal` and `ProfileModal`. It is not in the agent DTO and the
   server never checks `Dispatch.Model` against it (shape only).
10. **Repository paths.** `RepoPath`/`RepoPaths` still have live readers:
    `LegacyRepoPaths` → the agent's `convertLegacyRepoPaths` (the #456
    migration), `checkoutCandidates` in `internal/agent/evidence.go`, and the
    RepoPath-as-project alias of `callAgentContext`. The tracker adapters
    receive the path but ignore it. The web still edits `repoPath` in
    `ProjectModal`.
11. **UI labels.** The web tab the ticket calls *Moteur IA* is `aiEngine`,
    labelled "Paramètres de l'agent"; it also hosts `MCPEngineConfig`. The
    web `ProjectModal` "Agent settings" tab edits provider, model, skill
    models, `useWorktrees` **and `prCreationStage`**. #300 was the *desktop*
    category sidebar, not the web tab.
12. **The desktop already has a global settings screen** (`openSettings`,
    category AgentCli: provider, model, both templates), written by the
    Electron main process straight into `settings.json` with a shallow merge,
    while the project dialog goes through the agent and `WriteSettings`. Two
    writers with two merge rules.
13. **`.taskflow/agent.json` is not a sharing mechanism today.** It is read
    only as a fallback (whole file when `settings.json` is missing, then
    `projects`/`worktrees`/`parallelism` and the per-project overlay of
    `localProjectRoot`). It holds absolute workstation paths; the copy
    committed in this repository names `/Users/sferry/Sources/taskflow`.
14. **ADR 0015 decided the opposite for the AI configuration**: "the AI
    configuration … keeps reading the deployment row, since a launch is
    configured by the deployment and not by whoever started it." This ticket
    reverses that sentence.
15. **No workstation capability report exists.** Presence carries user,
    project, device and last ping; nothing reports the agent version, the
    installed CLIs, the provider or the model list.

### Ambiguities (worst first; each changes the code)

1. **What replaces the team-wide project defaults.** Today a project's
   provider, model, commands and `useWorktrees` set on the server apply to
   every workstation. After the move, a new team member starts from nothing
   unless something shares them.
2. **Where the web launch picker and the pre-run badge get a model list.**
   The web cannot read a workstation file; moving `aiProviderModels` local
   leaves `TaskCard`'s picker without a source.
3. **When the server columns disappear.** Seeding each workstation "from the
   values currently stored on the server" requires the server to keep serving
   them after the release that stops writing them.
4. **`ttyMode`**: revive or drop.
5. **Full-chain pre-flight**: agent-side only (as today) or also up front on
   the server.

### Critical dependencies

- **Contract v1** (`docs/contracts/server-agent-v1.md`): removing fields from
  `agentconfig.Config` is tolerated by JSON decoding, but an old agent on a new
  server loses its provider. ADR 0006 already requires upgrading both
  together; the desktop's `contractError` is the only guard.
- **Schema migrations**: dropping `projects.ai_*`, `setup_providers`,
  `skill_overrides`, `tty_mode`, `external_terminal_command`, `repo_path(s)`,
  `use_worktrees`, `settings.ai_*`, `editor_command`, `repo_path` and
  `user_settings.editor_command/external_terminal_command` goes through
  `migrations.go` only, updates the forget-and-replay fixtures and the rewind
  test helpers, and must be exercised on PostgreSQL too.
- **#456 migration**: `LegacyRepoPaths`/`convertLegacyRepoPaths` must have
  run on every workstation before `repo_path(s)` can be dropped.
- **Multi-user**: server values were per deployment (AI) or per account
  (terminal, editor). A workstation is paired to one account, which decides
  whose `user_settings` seed it.
- **ADR**: a new ADR superseding the AI sentence of ADR 0015 and extending
  ADR 0001's "local overrides only on the workstation".

### Reversible technical choices (resolved from the code and conventions)

- **Local file shape.** `Overrides` becomes the configuration, with an
  explicit global section and one section per project. The flat keys written
  today stay readable and are rewritten in the new shape on the first save,
  so no workstation needs a manual step. Exact field names belong to the
  specification.
- **One writer.** Desktop global settings stop writing `settings.json`
  directly from Electron and go through the agent, like the project dialog,
  so both use `WriteSettings` and its null-for-emptied-map rule.
- **Resolution moves to the agent.** `MergeModels`,
  `EffectiveCommandTemplate` and the project-over-global order run in the
  agent on local values only. `db.AgentConfig` keeps project identity,
  tracker metadata, `specFramework`, `prCreationStage`, `defaultSkillMode`,
  `fullChainStopStage`, `monoRepo`, `repositories` and skill content.
- **Skill command names.** A local per-project `skillCommands` map
  substitutes `Skill.Command` in the agent; the server serves the stage's
  default command only. Dead server substitution code is removed.
- **Editor.** A local global `editorCommand` resolved by the agent;
  `op.Editor` sent by an older server is still honoured, then `code`.
- **Terminal.** The local global and per-project values are the only levels;
  the unused `Dispatch.TerminalOverride` and server columns go.
- **`get_project_context`** stops serving `useWorktrees`, `aiProvider` and
  `aiModel`: a value the server cannot know is worse than an absent one.
- **Web.** The profile tab loses provider, models and model; `MCPEngineConfig`
  stays in the profile. The project "Agent settings" tab goes;
  `prCreationStage` moves to "Agentic workflow"; `repoPath` leaves
  `ProjectModal`.
- **Seed.** Once per workstation and project (a marker in the local file), the
  agent writes the server's effective values (project over deployment, and the
  paired account's `user_settings` for terminal and editor) into keys the local
  file does not already set. A local value always wins.
- **Out of scope, reported separately**: the committed `.taskflow/agent.json`
  with a workstation path in a public repository.

### Product questions (owner: @sebastienferry)

1. **Team sharing of project defaults.**
   - **A (recommended)**: no sharing in this ticket. Each workstation owns its
     configuration; the one-time seed covers existing setups; a new
     workstation starts from provider defaults. Sharing via a versioned repo
     file becomes its own ticket, designed with the security of a public repo
     in mind.
   - B: `.taskflow/agent.json` becomes a versioned, path-free team default,
     overridden by `~/.config/sectile/settings.json`.
   - C: keep the server project values as a read-only team default.
     Contradicts the guiding principle.
2. **Model list for the web launch picker and the pre-run badge.**
   - **A (recommended)**: the agent reports, per project, its effective
     provider, model and model list when it connects and after each local
     save. The web picker and badge use the report of the user's connected
     workstation; with none connected, no picker and the badge says
     "unknown". This also turns the pre-run guess into a fact.
   - B: the web picker disappears; a one-off model is chosen from the desktop
     only.
   - C: `aiProviderModels` stays on the server as a shared catalogue of
     suggestions, never an execution setting.
3. **Upgrade path.**
   - **A (recommended)**: two steps. This ticket stops every write, removes
     every editor and keeps the columns read-only, served only for the seed.
     A follow-up ticket drops the columns once workstations have upgraded.
   - B: drop the columns in this ticket; the seed runs before the migration
     drops them. That requires the new agent to meet the old server first,
     which ADR 0006 does not guarantee.
4. **`ttyMode`**: **drop the column (recommended)**, since nothing ever read
   it and the desktop already chooses integrated or external per launch; or
   revive it as a local setting.
5. **Full-chain pre-flight.**
   - **A (recommended)**: keep the agent-side refusal as it is, which already
     meets the acceptance criterion, and make sure a first-step refusal ends
     the chain with a readable reason.
   - B: in addition, the server refuses the chain up front from the reported
     capability. Requires 2A.

## Round 2 - answers from the owner (2026-09-25)

Answers given interactively in session by @sebastienferry. Every question

### Settled decisions

1. **Team sharing: none in this ticket (1A).** Each workstation owns its
   configuration. The one-time seed covers existing setups; a new workstation
   starts from provider defaults. Sharing through a versioned repository file
   is a separate ticket (#493), designed with the security of a public repository in
   mind. `.taskflow/agent.json` keeps its current fallback role only.
2. **Model list: reported by the agent (2A).** The agent reports, per project,
   its effective provider, model and model list when it connects and after
   each local save. The web launch picker and the pre-run badge use the report
   of the user's connected workstation; with none connected, the picker is
   hidden and the badge says the engine is unknown. `ResolveTaskEngine` reads
   that report instead of guessing from server columns.
3. **Upgrade path: two steps (3A).** This ticket stops every write of an
   execution setting and removes every editor; the server columns stay,
   read-only, served only to seed workstations. A follow-up ticket (#492) drops them
   once workstations have upgraded (and after the #456 `LegacyRepoPaths`
   conversion has run everywhere).
4. **`ttyMode`: dropped (4).** Nothing reads it and nothing seeds from it, so
   unlike the other columns it is removed in this ticket, through
   `migrations.go`, with the replay fixtures and rewind helpers updated.
5. **Full-chain pre-flight: agent only (5A).** The refusal stays on the agent,
   against the local provider. The ticket must make sure a first-step refusal
   ends the chain with a readable reason instead of a bare failed step. No
   server-side up-front refusal.

### Reversed or amended assumptions

- The ticket's impact 7 ("`get_project_context` does not change") is
  reversed, as found in round 1: it stops serving `useWorktrees`, `aiProvider`
  and `aiModel`.
- The ticket's "server column is dropped" in tables A and B is amended by
  decision 3: columns become read-only in this ticket and are dropped in a
  follow-up, except `ttyMode`.
- ADR 0015's sentence on the AI configuration is superseded; a new ADR records
  the workstation-owns-invocation rule and the capability report.

### New dependencies surfaced

- **Capability report (decision 2)**: a new agent-to-server call and a storage
  place on the server (per workstation and project, volatile or persisted),
  added to contract v1 as an optional field so an older agent simply reports
  nothing. Its exact shape belongs to the specification.
- **Follow-up tickets** (created 2026-09-25, under M-8):
  - #492 - drop the read-only execution setting columns (decision 3);
  - #493 - share project execution defaults across a team's workstations
    (decision 1);
  - #494 - remove the committed `.taskflow/agent.json` holding a workstation
    path.
