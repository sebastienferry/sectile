# Clarification of #627: Roadmap | Give each epic its own priority and quarter

Ticket: https://github.com/sebastienferry/sectile/issues/627 (parent M-11, Roadmap).

## Round 1 (2026-09-29)

### Request

An epic gets a priority (P0 to P3) and a quarter that belong to it, set and
cleared from its roadmap panel, stored in Sectile and written to the tracker
epic as labels; the roadmap filters on the epic priority (including "no
priority") and sorts on it in either order. A one-off seeding action reads both
values from the epic titles, previews them per epic, and writes nothing until
the user confirms.

Out of scope: grouping the roadmap into sections and dragging epics onto them
(#628), naming the axis prefixes or mapping them to tracker custom fields
(#635), a free editor for the other epic labels (#626), a readiness axis
(#633), rewriting epic titles, and filtering or sorting on the quarter (the
ticket asks for the priority only; the quarter becomes useful with #628).

### Ambiguities, worst first

1. **Where the roadmap priority comes from once an epic can carry its own.**
   Either the epic's own priority only (an epic without one shows "no
   priority"), or its own with a fallback on the children's highest. The first
   makes the column honest but blank until seeded; the second keeps today's
   look but shows two different things under one name. Question 1.
2. **Trackers whose epics cannot carry a label.** On GitHub the epics are
   milestones, GitLab declares no epic capability, and local projects have no
   tracker: only Jira can receive the labels. Sectile's own board (GitHub,
   parent M-11) is in the first case. The values can stay local there, as the
   horizon already does, or the feature can be limited to Jira. Question 2.
3. **How a quarter is picked.** A free text field validated as `YYYY-Qn`, or a
   list of quarters around today. Question 3.
4. **What the seeding touches.** Only epics without a value on that axis, or
   also epics whose title disagrees with their label; one preview for both axes
   or two actions; all proposed values applied, or ticked one by one.
   Question 4.

### Critical dependencies

- **#626 (keep and show an epic's labels).** Not a hard prerequisite: the
  horizon import already reads the labels of Jira epics through `ListEpics`,
  and the priority and quarter can be read the same way. What #627 needs from
  #626 is that `priority:` and `quarter:` join `roadmap:` among the protected
  axis prefixes, hidden from the label badges and filter and not editable as
  free labels. Whichever ticket lands second adds them.
- **Migration.** Two new columns on `macros` (`priority`, `quarter`), added in
  `migrations.go` only, never in the frozen baseline, and dropped by the rewind
  test helpers.
- **Tracker.** Jira only for the writes (see ambiguity 2). One label write per
  epic, through a queued activity like the horizon push, never inside the
  click.

### Technical choices settled from existing code

- **Label format.** `priority:p0` to `priority:p3`, exclusive; `quarter:YYYY-qN`,
  exclusive and open-ended. Lowercase and single colon, like `roadmap:now`.
  Case is ignored on read; a value that is not a priority or a quarter is
  ignored.
- **Bare quarter label.** A bare `2026-Q3` label is read as that quarter, as
  Taskativ does; the prefixed form wins a disagreement. Only the prefixed form
  is written, and setting a quarter removes both forms of the previous one. A
  bare label is never rewritten on an epic nobody touches.
- **Storage and sync.** Local first, like the horizon: stored in `macros`,
  shown immediately, then pushed. On read-back the tracker wins when the epic
  carries a label; an epic without one keeps the local value, which joins the
  pending pushes. A failed push says the value is set in Sectile but not on the
  ticket, and names the tracker error.
- **Scale.** P0 to P3 reuse the four levels already in the code (P0 urgent, P1
  high, P2 medium, P3 low) for their colours; the badge reads P0 to P3.
- **Title markers read by the seeding.** Priority: `[P0]` to `[P3]` or a bare
  `P0` to `P3` on a word boundary. Quarter: `2026.Q4`, `2026-Q4`, `2026 Q4`, on
  a word boundary, case ignored. The title is never changed.
- **Sort.** A toolbar control: backlog order (default), priority descending,
  priority ascending. Epics without a priority come last in both directions,
  and ties keep the backlog order. The choice is not remembered between visits
  (#629 owns remembering the view).
- **Filter.** A priority filter in the toolbar: P0, P1, P2, P3, "no priority",
  shown as a chip like the other filters.

### Product questions

1. **Roadmap priority source.** Recommended: the epic's own priority only. An
   epic without one shows "no priority"; the children's highest priority is no
   longer shown as the epic's.
2. **Trackers that cannot carry epic labels (GitHub milestones, GitLab,
   local).** Recommended: the priority and the quarter work there too but stay
   local to Sectile, as the horizon does, and the panel says they are not
   written to the tracker. Jira epics get the labels.
3. **Quarter picker.** Recommended: a list with "none", the current quarter,
   the next four, and the value already set if it lies outside that range.
4. **Seeding scope.** Recommended: one action for both axes; the preview lists
   each epic with the value found for each axis, only for axes where the epic
   has no value yet, each line ticked by default and untickable; confirming
   writes the ticked lines, and each failure is named.
