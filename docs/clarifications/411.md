## Round 1 (2026-09-26)

### Restated request and scope

Every database stamped before `projects.enabled_views` existed must gain the
column on upgrade, and the project must be protected against a column being
added to the frozen baseline again. Changing the migration runner, the ADR 0021
scheme or migrations already merged is out of scope.

### Verified findings

- The column itself is already fixed on `main` by `a5747ce4` (#420): migration 5
  adds `projects.enabled_views`, the column was removed from the baseline
  `CREATE TABLE` and from `applyLegacyMigrations`, and
  `TestAStampedDatabaseStillGainsALaterColumn` reads the projects back from a
  stamped database that lacks it. The ticket's reproduction no longer fails.
- The ticket's suggested `ADD COLUMN IF NOT EXISTS` hedge was rejected by #420
  in favour of removing the column from the baseline, which is what ADR 0021
  prescribes ("never an `IF NOT EXISTS` hedged against having run before").
- What remains open is the last bullet: a guard against adding columns to the
  frozen baseline again. None exists. The baseline is frozen only by comments
  (`internal/db/migrations.go`, `applyBaseline`) and by the ADR.
  `TestPostgresBaselinesADatabaseWrittenByAnOlderBinary` covers `lateColumns`,
  not the `CREATE TABLE` statements, and needs a PostgreSQL DSN.

### Ambiguities

1. **What the guard checks.** A review rule relies on people; a test catches the
   mistake before review. Resolved: a test.

### Resolved technical decisions

1. The guard is a SQLite test in `internal/db` that builds the baseline alone
   (`applyBaseline`, no numbered migration), reads every table's columns
   (name, type, NOT NULL, default) and compares them with a snapshot checked
   into `internal/db/testdata/`. Any drift fails with a message that points to
   ADR 0021 and says to write a numbered migration instead.
2. The snapshot has no update flag: the baseline never changes, so a snapshot
   diff in a pull request is itself the review signal.
3. SQLite only. The two engines share the baseline DDL through `RewriteDDL`, and
   the PostgreSQL suite skips without a DSN, so a SQLite guard is the one that
   always runs.

### Critical dependencies

None: no migration, no service, no data.

### Questions
