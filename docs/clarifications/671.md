# Clarification #671: move the Framing / Execution / Phases / Goals switcher into the side panel

Ticket: https://github.com/sebastienferry/sectile/issues/671
Branch: `feat/671`

## Round 1 (2026-10-06)

### Request

The four-way mode switcher of the Roadmap (Framing, Execution, Phases, Goals)
leaves the top toolbar and moves into the right-hand panel of the selected
macro, since it mostly decides what that panel's body shows. Out of scope: new
modes, persisting the chosen mode across reloads, changing what each mode's
panel body contains, and any server, tracker or desktop change.

### Code read

- `web/src/components/RoadmapView.tsx`: `displayMode` state (l. 283), default
  mode per horizon `useEffect` on `tab` (l. 386-393), `visibleRows` filter on
  `displayMode === 'execution' && onlyIssues` (l. 826-833), row badges in
  `renderMacroRow` (l. 1411-1429), toolbar switcher (l. 1885-1942), "À corriger"
  toggle (l. 1960-1975), sprint strip (l. 2026-2038), panel visibility
  (`panelShown`, `expandedHere`, l. 999-1000), hidden-panel rail (l. 2090-2100),
  panel header and its action buttons (l. 2103-2446), panel body switch on
  `displayMode` (l. 2475-2479).
- `web/src/locales/planning.ts`: `modes` strings (l. 153-160 French, l. 667+
  English).
- `web/tests/roadmap-framing.browser.mjs`, `roadmap-todos.browser.mjs`,
  `roadmap-batch-stories.browser.mjs`, `roadmap-slicing-upload.browser.mjs`:
  they select the mode with `getByRole('button', { name: 'Framing', exact: true })`.

### What `displayMode` drives today

| Surface | Framing | Execution | Phases / Goals |
| --- | --- | --- | --- |
| Panel body | description, framing notes, TODO checklist | stories, sprints, slicing | `MacroLabelGroups` on the axis |
| Row badge (unfolded row) | TODO count | "N à corriger" / "Tout est placé" | TODO count |
| "À corriger" toggle in the toolbar | hidden | shown | hidden |
| `onlyIssues` filter on the list | ignored | applied | ignored |
| Sprint strip (Now / Next) | hidden | shown | hidden |

The condensed row already ignores the mode: it always computes placement issues.

### Ambiguities (worst first)

1. **Who owns the list's Execution behaviour.** Once the switcher sits in the
   panel, the row badges, the "À corriger" toggle, the `onlyIssues` filter and
   the sprint strip would change when a control inside the panel is clicked,
   and would stay frozen on the last mode while the panel is hidden or no macro
   is selected. Two readings lead to different code: (A) the list follows the
   horizon tab and no longer reads `displayMode`; (B) the list keeps reading
   `displayMode`. Product question Q1.
2. **Where the switcher sits in the panel.** The header already carries
   expand, hide, copy, link, tickets, rename and migrate buttons, plus the
   horizon, priority, quarter and readiness axes. Product question Q2.
3. **Default mode per horizon.** Settled below (D1).

### Dependencies

None outside `web/`: no migration, no API, no tracker call, no desktop code
(the desktop app loads the same web build). Four browser tests select the mode
by button name and must follow the new markup.

### Settled technical choices (reversible)

- **D1. The default mode per horizon stays as it is.** The `useEffect` on
  `tab` keeps resetting the panel to Framing on Later and to Execution on Now
  and Next. It does not depend on where the switcher is drawn.
- **D2. The mode stays a single component state** (`displayMode`), not
  persisted, as today. A macro change does not reset it; a horizon tab change
  does (D1).
- **D3. The switcher is a `role="tablist"` of four `role="tab"` buttons with
  `aria-selected`**, since it selects which body the panel shows. The visible
  labels and titles (`strings.modes.*`, axis plurals) are unchanged. The four
  browser tests switch from `getByRole('button', …)` to `getByRole('tab', …)`.
- **D4. The switcher is rendered only inside the panel**, so with no macro
  selected or the panel hidden there is no switcher anywhere (acceptance
  criterion 3). The hidden-panel rail keeps its single "show panel" button.
- **D5. The expanded panel shows the same switcher at the same place**; the
  expanded layout only widens the panel, it does not need a second copy.
- **D6. Changelog**: one `Changed` line under `## [Unreleased]`, in English.

### Product questions

**Q1. Should the list's Execution behaviour follow the horizon tab instead of
the panel's mode?**

- **(A, recommended)** Yes. On Now and Next the list always shows the
  placement badges ("N à corriger" / "Tout est placé"), the "À corriger" toggle
  stays in the toolbar and the sprint strip stays above the list, whatever mode
  the panel is in. On Later, Unclassified and Masqués the rows show the TODO
  count and there is no "À corriger" toggle nor sprint strip. The panel's mode
  then only changes the panel. Consequence: switching the panel to Framing on
  Now no longer swaps the row badges to TODO counts, and placement badges are
  no longer reachable on Later (where they compare against no sprint anyway).
- (B) No. The list keeps reading the panel's mode: the toolbar toggle and the
  badges change when a tab inside the panel is clicked, and stay on the last
  mode while no macro is selected.

**Q2. Where in the panel does the switcher go?**

- **(A, recommended)** A tab strip at the bottom of the panel's header block,
  right above the scrolling body: it stays visible while the body scrolls and
  reads as "what this body shows". Same place in the expanded panel.
- (B) In the header's top line, among the expand / hide / copy / rename
  buttons. That line already wraps on a narrow panel.

## Round 2 - answers from the owner (2026-10-06)

The owner answered both questions interactively, each with the recommended
option.

### Settled decisions

- **Q1 → A. The list follows the horizon tab, not the panel's mode.**
  `visibleRows`, the unfolded row badge, the "À corriger" toggle and the sprint
  strip stop reading `displayMode`:
  - on Now and Next, the rows always show the placement badge ("N à corriger" /
    "Tout est placé"), the "À corriger" toggle is shown in the toolbar and the
    `onlyIssues` filter applies, and the sprint strip is shown above the list;
  - on Later, Unclassified and Masqués, the rows show the TODO count, and
    there is neither toggle nor sprint strip. `onlyIssues` keeps its value
    across tabs but is only applied on Now and Next.
  - `displayMode` then only selects the panel body.
- **Q2 → A. The switcher is a tab strip at the bottom of the panel's header
  block**, right above the scrolling body, at the same place in the expanded
  panel (D5).

### Reversed assumptions

- Today, picking Framing, Phases or Goals on Now or Next hides the "À
  corriger" toggle and the sprint strip and turns the row badges into TODO
  counts; picking Execution on Later shows placement badges. Neither happens
  any more: those list elements now depend on the horizon tab only.

### Acceptance criteria, as settled

1. The four modes are shown as tabs at the bottom of the macro panel's header,
   in both the normal and the expanded panel, and no longer in the toolbar.
2. With no macro selected or the panel hidden, no mode switcher is shown.
3. Changing tab in the panel changes only the panel body.
4. On Now and Next, the placement badges, the "À corriger" toggle with its
   filter and the sprint strip are shown whatever the panel's mode; on Later,
   Unclassified and Masqués, rows show the TODO count and neither the toggle
   nor the sprint strip is shown.
5. Changing horizon tab still resets the panel to Framing on Later and to
   Execution on Now and Next.
6. The Roadmap browser tests that select a mode use the new tabs, and a test
   covers criteria 2 and 4.
7. A `Changed` line under `## [Unreleased]` in `CHANGELOG.md`.
