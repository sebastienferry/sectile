# Clarification #487 - Add an option to allow to drop the specs

- Ticket: https://github.com/sebastienferry/sectile/issues/487
- Branch: `feat/487`
- Stage: new -> clarified

## Round 1 - analysis (2026-09-25)

### Request restated

A project can opt out of committing the specification artefacts that the task
stages produce today in the code repository (`specs/<KEY>-<slug>/` under
Spec Kit, `openspec/changes/<KEY>-<slug>/` under OpenSpec), so that they no
longer land on the task branch and in its pull request, either by writing them
in a separate folder or by keeping them ignored by Git. Out of scope: the macro
workflow, whose specifications folder was already made a workstation setting
that accepts a plain folder (#443), the choice of SDD framework itself, and the
layout of the specification files.

### What exists today (files read)

- **Where the task stages write**: the skill bodies are rendered from
  `internal/skills/fragments/<stage>/*.md` per framework
  (`internal/skills/catalog.go`, `internal/agent/renderskills.go`, golden files
  under `internal/skills/testdata/golden/`). `specify/steps*.md` writes
  `specs/<KEY>-<title-slug>/{spec,plan,tasks}.md` or
  `openspec/changes/<KEY>-<title-slug>/{proposal,design,tasks}.md` plus
  `specs/<capability>/spec.md`, on the task branch. `clarify/steps.md` writes
  and commits `docs/clarifications/<n>.md` (`docs(spec): clarify #<n>`).
  `implement/read-first.md` reads "the specification and its task checklist"
  from the worktree.
- **#443** (`specs/443-specifications-folder/spec.md`) explicitly left the task
  stages out of scope: "they keep writing `docs/clarifications/<n>.md` and
  `specs/<n>-*` in the code repository, on the task branch, reviewed with the
  pull request". The specifications folder it introduced
  (`Overrides.SpecRepos`, `internal/agentconfig/local.go`; resolution in
  `internal/agent/agent_desktop.go`; `internal/sddfiles/sddfiles.go`) only
  serves macros.
- **Project settings**: `specFramework` is a server-side project setting
  (`internal/models/models.go`, `internal/db/specframework.go`, edited in
  `web/src/components/ProjectModal.tsx`). `.agents/MEMORY.md` records that
  per-project settings live only in the database, never in a repository file.
- **Checkout checks**: the agent's `git_evidence` answer computes `clean` from
  `git status --porcelain` (`internal/agent/agent_operations.go`), which does
  not list ignored files; `transition_stage` refuses a dirty checkout.
- **Cleanup**: worktrees are removed with `git worktree remove`
  (`internal/agent/agent_operations.go`, `internal/agent/repositories.go`,
  `internal/workspace/git.go`). Git refuses to remove a worktree holding
  untracked files, but **deletes ignored files silently**.
- **This repository** has no ignore rule for `specs/` or `openspec/` today
  (`.gitignore`), and itself commits its specifications.

### Ambiguities (worst first)

1. **What "drop" means.** (a) The artefacts stay on the workstation, ignored by
   Git, and are never pushed; (b) a committed `.gitignore` rule in the
   repository does the same, visible to every clone; (c) the artefacts are
   written to a separate folder outside the code checkout (for instance the
   #443 specifications folder, which may itself be a Git repository or a plain
   folder). (a)/(b) change only the skills and an ignore rule; (c) changes
   where every stage reads and writes, and the launch environment.
2. **Which artefacts.** Only the SDD folders (`specs/<KEY>-*`,
   `openspec/changes/<KEY>-*`), or also the clarification report
   `docs/clarifications/<n>.md`, which is part of the same spec-driven trail.
3. **Where the option lives.** A server project setting (like `specFramework`,
   same answer for every workstation, shown in the web project options), or a
   per-workstation setting (like the #443 specifications folder).
4. **Lifetime of dropped artefacts.** Under (a)/(b) they exist only in the task
   worktree: another workstation picking the task up does not see them, and
   the handoff cleanup deletes them. Either that is accepted, or Sectile keeps
   them somewhere (tracker comment, separate folder).
5. **Who writes the ignore rule** under (a)/(b): Sectile once per checkout
   (`.git/info/exclude`, shared by all worktrees of the checkout, no diff), the
   skill in the task branch (`.gitignore`, a diff in every first PR), or the
   user by hand with Sectile only adapting the skills.

### Critical dependencies

- **Skill rendering**: the specify, clarify and implement fragments, their
  per-framework variants and every golden file change; the skill text must be
  selected by the option (a new render input next to the framework).
- **Setting storage**: a server setting needs a new `projects` column, added
  only through `internal/db/migrations.go` (never the frozen baseline), with
  the rewind helpers of the db tests dropping it; a workstation setting needs a
  new `Overrides` key, merged by `localProjectRoot` and nulled when emptied.
- **Cleanup**: `git worktree remove` deletes ignored files without warning; if
  dropped specifications must survive, cleanup has to know about them.
- **Multi-workstation / cloud runs**: a stage run on another agent starts from
  the pushed branch, which no longer carries the specification.
- **Pull request review**: the reviewer no longer sees the specification in
  the diff; the specify stage report in the task activity
  (`TaskDetailModal`) and the transition note on the ticket remain.
- **Specify stage evidence**: the specify transition must still pass with no
  committed specification (the ignored files leave the checkout clean, and no
  new commit is produced by the stage).

### Technical choices resolved from the code

- The option is **off by default**: every existing project keeps committing its
  specifications, and nothing changes until it is turned on.
- The option applies identically to Spec Kit and OpenSpec; only the folder
  names differ, as `sddfiles.SearchRoots` already encodes.
- The macro workflow is untouched: #443 already lets its folder be separate or
  plain.
- User-facing strings follow the surface's language (French on server and
  web, English in the desktop UI); `CHANGELOG.md` gets an `Added` line.

### Product questions (with recommendation)

1. **Mechanism** - Recommended: (a) keep them local and ignored, Sectile
   adding the rule to the checkout's `.git/info/exclude` (no diff in the
   repository, works in every task worktree of that checkout).
2. **Artefacts covered** - Recommended: the SDD folders **and**
   `docs/clarifications/<n>.md`, since both form the specification trail a
   project opting out does not want in its history.
3. **Setting level** - Recommended: a server project setting in the web project
   options, since it changes what the team's pull requests contain.
4. **Lifetime** - Recommended: accept that dropped artefacts are local to the
   worktree and disappear at handoff cleanup; the stage reports posted on the
   ticket remain the durable trace.

## Round 2 - answers from the owner (2026-09-25)

The owner answered the four questions of round 1 interactively.

### Settled decisions

1. **Mechanism**: local Git exclusion. Sectile adds the rule to the
   checkout's `.git/info/exclude`; the artefacts exist in the worktree, are
   never committed or pushed, and the repository gets no diff. The committed
   `.gitignore` and the separate folder were rejected.
2. **Artefacts covered**: the SDD folders (`specs/<KEY>-*` under Spec Kit,
   `openspec/changes/<KEY>-*` under OpenSpec) **and**
   `docs/clarifications/<n>.md`.
3. **Setting level** (differs from the recommendation): a **server project
   setting**, edited in the web project options, **with a per-workstation
   override** in the desktop project settings.
4. **Lifetime**: dropped artefacts are local to the worktree and are deleted
   with it at handoff cleanup; the stage reports posted on the ticket remain
   the durable trace. Sectile does not preserve them elsewhere.

### Reversed assumptions

- Round 1 recommended a server-only setting. The desktop now carries an
  override as well, which brings in the `Overrides` dependency (new key merged
  by `localProjectRoot`, nulled when emptied) on top of the `projects` column.

### New points raised by the answers

- **Override shape**: the desktop needs a way to say "follow the server", so
  the override is three-valued (inherit / keep in the repository / drop).
- **Turning the option off**: the exclusion rules Sectile wrote must be
  recognisable to be removed, without touching lines the user wrote.
- **Turning the option on for a repository that already committed
  specifications**: an exclusion rule has no effect on tracked files; what is
  already in the history stays.
