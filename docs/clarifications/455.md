## Round 1 — initial report (2026-10-02)

### Restated request and scope

Move every label of the web quick add dialog (`web/src/components/QuickAddModal.tsx`) that is still hard-coded in
French into the web catalog, so that an English interface shows no French label and a French interface reads exactly
as today. The desktop app's quick add, the task detail modal, the clone dialog and every other screen are out of
scope, and no behaviour of the dialog changes.

### Files read

- `web/src/components/QuickAddModal.tsx` (the right-hand "details" column, lines 285–470, and the sprint lookup setup)
- `web/src/locales/translations.ts` (`TranslationSchema.quickAdd`, the `fr.quickAdd` and `en.quickAdd` blocks)
- `web/src/locales/taskDetail.ts` (`issueType`, `lookups`, `clone`)
- `web/src/locales/taskDetail.ts` `fields` (`project`, `favorites`, `otherProjects`), `web/src/locales/shell.ts`
  (`projectPicker.favorites`), `web/src/locales/planning.ts` (sprint wording)
- `web/src/components/CloneTaskModal.tsx` (neighbouring dialog that already localises the same sprint lookup)
- `web/tests/quick-add.browser.mjs`, `CHANGELOG.md`

### Ambiguities (worst first)

1. **`projet par défaut` (GitLab fallback) is missing from the ticket's list.** Leaving it out vs. including it leads to
   different code. *Settled:* included — acceptance criterion 1 ("the quick add dialog shows no French label") catches
   it.
2. **Reuse a shared key or create a `quickAdd.*` key.** The ticket allows both. *Settled:* reuse a shared key only when
   its French text is byte-identical to today's label (so AC 2 holds) and it lives in a namespace already shared across
   dialogs; otherwise add a `quickAdd.*` key. Precedent: `CloneTaskModal.tsx` already reads the sprint lookup strings
   from `t.taskDetail.lookups.*` and its project groups from `t.taskDetail.fields.*`, and `QuickAddModal.tsx` already reads `t.taskDetail.lookups.sprintKinds`.

### Settled technical choices (reversible)

| Label (fr, unchanged) | Key | en |
|-----------------------|-----|----|
| `Projet *` | new `quickAdd.project` | `Project *` |
| `Tracker :` | new `quickAdd.tracker` | `Tracker:` |
| `projet non configuré` | new `quickAdd.trackerNotConfigured` | `project not configured` |
| `projet par défaut` | new `quickAdd.trackerDefaultProject` | `default project` |
| `Favoris` | reuse `taskDetail.fields.favorites` (the clone dialog's project `<optgroup>` uses it) | `Favorites` |
| `Autres projets` | reuse `taskDetail.fields.otherProjects` (same) | `Other projects` |
| `Type de ticket` | new `quickAdd.issueType` | `Ticket type` (mirrors `taskDetail.issueType.changeTitle`) |
| `Défaut` | new `quickAdd.issueTypeDefault` (`taskDetail.issueType.defaultOption` reads `Type: Défaut`, not a match) | `Default` |
| `Tâche` | reuse `taskDetail.issueType.task` | `Task` |
| `Sprint` | new `quickAdd.sprint` (identical in both languages, keyed anyway per AC 3) | `Sprint` |
| `Affecter un sprint (optionnel)…` | new `quickAdd.sprintPlaceholder` (the identical `taskDetail.clone.sprintPlaceholder` belongs to the clone dialog, not a shared namespace) | `Assign a sprint (optional)…` |
| `Backlog (aucun sprint)` | reuse `taskDetail.lookups.sprintClear` | `Backlog (no sprint)` |
| `Aucun sprint trouvé. Tapez un nom pour créer.` | reuse `taskDetail.lookups.sprintEmpty` | `No sprint found. Type a name to create one.` |
| `Nouveau sprint` | reuse `taskDetail.lookups.newSprint` | `New sprint` |

The new keys go into `TranslationSchema.quickAdd` and into both the `fr` and `en` blocks of `translations.ts`, so the
compiler enforces that each language defines them. The exact key names may still be adjusted at specification time;
the French texts may not.
