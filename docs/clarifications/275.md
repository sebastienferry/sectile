# #275 - Autonomous and JSON stream not visible with AGY/CLAUDE

- Type: Bug
- Tracker: https://github.com/sebastienferry/sectile/issues/275
- Branch: feat/275
- Round: 1 (open - awaiting owner answers)

## Restatement

An autonomous (headless) launch driven by the AGY or CLAUDE provider does not show
what the CLI prints: neither the progressive output nor the `stream-json` events
reach the surface where a user watches a run. The ticket is about the visibility
of a headless run's output, not about the run failing to execute.

Out of scope for this ticket: interactive (PTY) runs, provider authentication,
model selection, and any change to the workflow stages themselves.

## Ambiguities (worst first)

   "JSON stream" with "and". Two readings lead to different code:
   a. the *configuration* is not visible (autonomous command field / preset not
      offered or not applied for AGY and CLAUDE), or
   b. the *run output* is not visible (a headless AGY/CLAUDE run shows nothing,
      or shows raw JSON, in the activity panel).
   Reading (b) is the one the code supports as a real defect; see the hypothesis below.
2. **Which surface** - the web UI activity panel, the desktop application's run
   view, or both. The desktop lists a headless run but has no console for it
   (`agent_headless.go`), so "not visible" may simply be the desktop's expected
   behaviour rather than a bug.
3. **AGY *and* CLAUDE, or AGY *via* CLAUDE** - whether both providers are affected
   independently, or the report describes a single AGY run using a Claude model.
4. **Expected rendering of `stream-json`** - raw NDJSON lines as printed, or parsed
   events rendered as readable progress. This changes whether the fix is plumbing
   or a new renderer.
5. **Live vs. final** - whether the run output is missing during the run only, or
   still missing after the process exits.

## Leading technical hypothesis (to be confirmed by the owner's answers)

Both default autonomous presets buffer everything until exit:

- AGY: `agy ... --output-format stream-json -p "{prompt}" | jq -rs 'map(select(.event == "result"))[0].result.response'`
  `jq -rs` slurps the whole stream before emitting anything, so the 3-second flush
  in `superviseHeadlessRun` has nothing to post until the CLI has finished, and the
  individual `stream-json` events are discarded by the `jq` filter by design.
- Claude: `claude -p --permission-mode bypassPermissions ...` carries no
  `--output-format stream-json`, so it prints a single final answer.

If this is the reported behaviour, the defect is in the presets and in how the
headless channel is expected to consume a JSON event stream, not in the transport
(`postRunOutput` -> `HandleAgentRunOutput` -> `AppendRemoteRunOutput`), which is
already incremental.

## Dependencies

- Provider CLIs are external: the exact `stream-json` event shape for `agy` and for
  `claude` is owned by those tools and must be treated as unstable input.
- `RemoteRunOutputLimit` (256 KiB) caps what one run can record; a raw event stream
  is far more verbose than a final answer and will hit that cap on long runs.
- The tracker's comment API returned HTTP 401 during this run, so the ticket's own
  discussion could not be read. If the owner already answered there, that answer was
  not visible to this round.

## Reversible technical choices, resolved here

- Keep the existing output transport (agent -> `/api/v1/agent/run-output` -> activity
  output) rather than adding a second channel; it already flushes every 3 seconds.
- Keep `web/src/lib/commandTemplate.ts` mirroring `internal/agent/agent_config.go`
  as the file's own doc comment requires; any preset change lands in both.
- Presets stay overridable by environment (`SECTILE_PRESET_*` / `VITE_PRESET_*`),
  so no default is hard-coded past the point of being changed by a user.

## Owner input already present on the ticket (2026-09-20)

Retrieved after the tracker's 401 cleared. The owner had already recorded two
suspects, which this round did not see when it was written:

> This might comes from the used JQ expression
> `agy --dangerously-skip-permissions --model {model} --output-format stream-json -p "{prompt}" | jq -rs 'map(select(.event == "result"))[0].result.response'`
> Or from the fact that in autonomous, no TTY is attached to the console.

Consequences for this round:

- The `jq -rs` suspect matches the hypothesis above, independently reached. It is
  treated as confirmed in direction, not yet as the settled scope of the fix.
- The **no-TTY** suspect is new and must be investigated alongside it: a CLI that
  detects no terminal may suppress progress output entirely, or switch to a
  non-interactive rendering, regardless of what `jq` does downstream. This is
  deliberate in `startHeadlessRun` (`agentexec.DetachedSession()`, `cmd.Stdin = nil`),
  so it cannot simply be undone: an autonomous run has no terminal by definition.
  The question becomes whether the providers need an explicit flag or environment
  variable to keep emitting progress without a TTY, not whether to attach one.
- This comment does not answer any of the six open product questions; it narrows
  question 5 and adds a technical line of investigation for the specify stage.
