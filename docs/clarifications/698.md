## Round 1 (2026-10-02)

### Restated request and scope

Sectile Desktop's command palette (⌘K / Ctrl+K) gains an **Add project** command
that opens the same flow as the `+` button next to PROJECTS in the sidebar, so a
project can be added without hovering the sidebar or opening it at all. Out of
scope: creating a new project on the Sectile server (only the web app does that),
changing the Add project dialog itself, and any change to the web app's palette.

### Verified findings

- The ticket has a title only: no description, no comments, no parent epic.
- The palette is a list of actions, `COMMANDS` in `desktop/src/main.js:2975`,
  holding today **Quick add task** and **Tasks list**. Its comment says adding a
  command is meant to be one row. `openCommandPalette` (`desktop/src/main.js:2999`)
  filters the rows by label and runs the first visible one on Enter.
- The Add project flow is the anonymous handler of `#add-project`
  (`desktop/src/main.js:2032`). It opens the `Add project` dialog, loads the
  server's projects with `loadProjects()`, and lists each one as a button:
  enabled to configure it (`openProject`), disabled with "Already added", or
  "Hidden, show in sidebar" to unhide a hidden project. Errors go to `error(err)`.
- The `+` button is invisible until the sidebar section is hovered or focused
  (`desktop/src/style.css:188`), and unreachable when the sidebar is collapsed
  (Cmd+B), which is the gap the palette command fills.
- Both palette commands and the `+` button render into the same shared `dialog`,
  so running a command from the palette replaces the palette's content; that is
  how **Quick add task** and **Tasks list** already behave.
- Desktop has no way to create a server project: `createProject` exists only in
  the web app (`web/src/context/AppContext.tsx:2374`, `ProjectModal.tsx`).
- UI tests already drive the palette (`desktop/tests/project-open-tasks.ui.cjs:61`)
  and the `+` button (`console.ui.cjs:86`, `disconnect.ui.cjs:93`,
  `tooltips.ui.cjs:42`).

### Ambiguities (worst first)

1. **What "add" means.** Connecting an existing server project to this
   workstation (today's desktop flow), or creating a new project on the server.
   The second needs a whole project form in desktop and a server write; the first
   is one palette row. See question 1.
2. **Label.** The dialog is titled "Add project" while the `+` tooltip says
   "Add a remote project". Resolved below.

### Critical dependencies

None. No server, migration or IPC change: the flow already exists in the
renderer and uses the existing `api.projects` call through `loadProjects()`.

### Resolved technical choices (reversible)

- Extract the `#add-project` handler into a named function (e.g.
  `openAddProject`) and reference it both from the button and from a new
  `COMMANDS` row, rather than calling `.click()` on a possibly hidden button.
- Label the command **Add project**, matching the dialog title and the CHANGELOG
  wording; the filter then matches "add" and "project".
- Row order: after **Quick add task** and **Tasks list**, keeping existing
  commands where users find them.
- Interface strings stay in English, the language the desktop UI already speaks.
- A UI test opens the palette, filters on "project", runs **Add project** and
  asserts the `Add project` dialog lists the server's projects.
- One `Added` line in `CHANGELOG.md` under `[Unreleased]`, as the change is
  user-visible.

### Product questions

1. **Scope of "Add project".** Recommended: the palette command opens today's
   desktop flow (connect an existing server project to the workstation, or show a
   hidden one again). Alternative: also let the desktop create a new project on
   the server, which is a separate, much larger feature.
