# Clarification #711 - Desktop: a task launched from the web follows the console view setting

## Round 1 (2026-10-02)

### Restatement

With **Settings → Appearance → Claude consoles** set to **Conversation** in
Sectile Desktop, a skill launched interactively from Desktop opens in the
conversation view, but the same launch started from the web app (the
**Clarify** follow-up of a new task, a card button, **Run skill** in the
detail modal) opens a terminal on the workstation. The fix makes an
interactive launch the server dispatches to this workstation's agent follow
the Desktop setting whatever client asked for it.

Out of scope: autonomous (headless) launches, which keep their read-only trace;
engines other than Claude and Claude engines the conversation view cannot
honour, which keep the terminal as today; **Discussion in native terminal** and
`open_terminal`; a per-launch "terminal or conversation" choice in the web app;
moving the setting to the server or to the project configuration.

### Code read

- `desktop/electron/main.cjs:155-166`: `consoleView` is stored in Desktop's own
  `settings.json`; nothing sends it to the agent except a launch.
- `desktop/electron/main.cjs:360` and `:363`: `launch-console` and
  `launch-server-task` add `view: "conversation"` to the agent request only
  when Desktop launches.
- `desktop/src/main.js:171-172`, `:2902`, `:2954`, `:3199`, `:3300`, `:3359`:
  every Desktop launch passes `consoleView`, including the **Clarify now**
  follow-up of its own **New task** dialog.
- `internal/agent/agent_desktop.go:931-981` (`desktopTasks` POST): the agent
  records `View == "conversation"` with `d.conversationViews.mark(task.ID)`
  and forwards the launch to the server's `/run-skill` without it.
- `internal/agent/agent_discussion_conversation.go:31-61`
  (`pendingDiscussionViews`): a mark lives for `conversationDiscussionTTL` and
  is consumed by the dispatch.
- `internal/agent/agent.go:1255-1290`: a dispatch opens a conversation only if
  it is interactive, not `open_terminal`, the mark is found, and
  `conversationDiscussionEngine(config)` holds; otherwise it opens a PTY.
- `web/src/components/QuickAddModal.tsx:180-188`,
  `web/src/components/TaskCard.tsx:310-334`,
  `web/src/components/TaskDetailModal.tsx:751`, `:1553`,
  `web/src/context/AppContext.tsx:3836-3851`: the web app calls the server's
  `/run-skill` directly; no mark is ever set on the agent.
- `CHANGELOG.md:21`: the conversation launch feature is still under
  `[Unreleased]` and says "launched interactively from Desktop".

### Root cause

The view is a per-launch hint Desktop hands to its agent, not a workstation
preference the agent knows. A dispatch the agent did not see coming from
Desktop (the web app, and any other server-side launch) finds no mark and
falls back to the terminal. The quick-add of the web app is the most visible
case, not the only one.

### Ambiguities (worst first)

1. **Which launches follow the setting.** Only the web **New task → Clarify**
   follow-up named by the ticket, or every interactive dispatch reaching this
   workstation (web buttons, detail modal, discussion, a chain the server
   continues on its own). Product question Q1.
2. **Where the preference lives.** Desktop's `settings.json` is invisible to
   the agent, and the server must not know it (it is a workstation display
   choice; another workstation may differ). Settled below.
3. **Desktop closed.** The agent keeps running when Desktop is closed; a
   dispatch then still has to pick a view. Settled below.

### Settled technical choices

- **The agent holds the workstation's console view.** Desktop sends its
  setting to the agent when it connects and whenever it changes (a new
  `/desktop/...` endpoint, or a field on an existing settings call), and the
  agent persists it in its own state so that a restart keeps it. A dispatch
  with no explicit mark uses that default; Desktop's explicit per-launch view
  keeps working and wins.
- **Same eligibility as today.** The default only replaces the missing mark:
  autonomous runs, `open_terminal`, the native terminal discussion and engines
  `conversationDiscussionEngine` rejects keep the terminal path unchanged.
- **Desktop closed.** The agent applies the last value Desktop gave it; a
  conversation is as visible as a PTY once Desktop opens (both are hosted by
  the agent). An agent that never received a value keeps the terminal.
- **Old agent, new Desktop.** Desktop checks a capability in
  `/desktop/status` before sending the setting, as it does for
  `claude-conversation`; an older agent keeps today's behaviour.
- **Changelog.** The conversation feature has not been released yet, so the
  `[Unreleased]` line of `CHANGELOG.md:21` is amended ("launched
  interactively from Desktop or the web app") rather than adding a `Fixed`
  line for a bug no release had.

### Dependencies

- Agent and Desktop change together; no server, database or migration change.
- No web change if the agent default is used.

### Product questions

1. **Q1 - Scope of the fix.** Should every interactive launch dispatched to
   this workstation follow the Desktop setting (web card buttons, **Run
   skill**, **Discussion**, the quick-add **Clarify**, a chain the server
   continues), or only the web quick-add follow-up?
   *Recommended:* every interactive dispatch. It is the same root cause, and a
   setting that applies to some web buttons but not others would be the next
   ticket.

## Round 2 - answers from the owner (2026-10-02)

Report: `docs/clarifications/711.md`, committed on `feat/711`. Round 1 was
published as a ticket comment.

### Answers

- **Q1 - Scope of the fix: every interactive dispatch.** The recommended
  option. Every interactive launch the server dispatches to this workstation
  follows the Desktop **Claude consoles** setting, whoever asked for it: the
  web quick-add **Clarify**, the card buttons, **Run skill** and
  **Discussion** of the detail modal, and a chain the server continues on its
  own.

### Settled scope

- The agent holds the workstation's console view, given by Desktop when it
  connects and whenever the setting changes, persisted across an agent
  restart; an agent that never received one keeps the terminal.
- A dispatch with no explicit per-launch mark uses that default. Desktop's
  explicit view keeps working.
- Unchanged: autonomous runs, `open_terminal`, **Discussion in native
  terminal**, engines `conversationDiscussionEngine` rejects, and an agent
  older than the Desktop (gated by a `/desktop/status` capability).
- No server, web, database or migration change.
- `CHANGELOG.md:21` (`[Unreleased]`) is amended to say that the setting
  applies to interactive launches started from Desktop or from the web app.

### Reversed assumptions

None.

### Open questions

None. The exit condition is met: the stage moves to `clarified`.
