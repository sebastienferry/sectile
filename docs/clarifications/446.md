## Round 1 (2026-09-25)

### Restated request and scope

The ticket, titled "Desktop: running execution indicator", only says "Align
them." It follows #438 (merged in #441), which moved the run-state indicator
before the title in the Desktop sidebar row and header and turned Running into
a pulsing dot; the most likely request is that these indicators now line up.

Out of scope until the owner says otherwise: the glyphs and colours themselves
(settled in #438), the run-state vocabulary, the web board badges, and the
server-side run statuses.

### Verified findings

Files read: `desktop/src/main.js` (`renderRunState`, `renderHeaderState`, the
sidebar row builder around `button.append(state,title,status)`, `ticketRow`,
`updateTicketRow`), `desktop/src/style.css` (`.run-state`, `.header-state`,
`.local-task`, `.task-number`, `.ticket-state`), `shared/runStates.ts`,
`web/src/components/RemoteRunBadge.tsx`, `docs/clarifications/438.md`.

- **Sidebar row** (`.local-task`): `[task-number button] [run button: state ·
  title · skill badge] [PR] [archive] [menu]`. The task number (`#42`, `#446`,
  `M-7`) sits *outside* the run button, before the state, and has no fixed
  width. A free console has no task number at all (`if(!freeConsole(run))
  row.append(context)`).
  → The run-state glyphs of consecutive rows therefore start at different x
  positions: they are not in a column. This is the most likely "align them".
- **Toolbar header**: `[state glyph + label] [title] [skill badge]`, 14 px glyph.
- **Tickets pane**: the state is the first column (`.ticket-state`, 16 px), so
  it is already aligned by the table.
- **Sizes differ**: 14 px in the sidebar and header (`runStateSvg(state,14)`),
  16 px cell in the tickets pane, 12 px on the web badge (`RemoteRunBadge`).
- **Pulse differs**: Desktop pulses opacity *and* scale over 2 s
  (`run-state-pulse`); the web uses Tailwind's `animate-pulse` (opacity only),
  and the web always pulses Waiting while the Desktop does not.

### Ambiguities (worst first)

1. **What "them" is and what "align" means.**
   - (A) Visual alignment in the sidebar: the state glyphs should form one column
     whatever the width of the task number, and for free consoles too.
   - (B) Consistency across Desktop surfaces (sidebar, header, tickets pane): same
     size, same position, same animation.
   - (C) Consistency between Desktop and the web board (size, pulse, which states
     pulse).
   Each leads to different code (CSS layout of `.local-task` vs. shared sizes vs.
   web components).
2. **For (A), where the column is.** Either the state moves before the task
   number (`[state] [#key] [title]`, first column like the tickets pane), or the
   task number gets a fixed width so the state column after it lines up.

### Critical dependencies

- None on the server, the database or the tracker: this is Desktop CSS/DOM, plus
  the web only under reading (C).
- Desktop UI tests (`desktop/tests/*.ui.cjs`) select row elements; they load
  `dist/index.html`, so `npx vite build` is needed before running them.

### Reversible choices resolved from the code

- Glyphs, colours and labels stay as `shared/runStates.ts` defines them.
- The skill-result badge stays after the title (settled in #438).
- If a free console has no task number, its row reserves the same space so its
  state glyph falls in the same column.

### Product questions (with recommendation)

1. **Which indicators should be aligned?** Recommended: (A), the run-state glyphs
   in the sidebar rows, into one vertical column.
2. **Where should that column be?** Recommended: the state first, before the task
   number (`[state] [#key] [title]`), which is what the tickets pane already does
   and needs no fixed width guess for keys like `M-12` or `#1024`.
3. **Should sizes and the pulse also be unified** (one size across Desktop
   surfaces, same pulse as the web)? Recommended: not in this ticket unless it is
   what you meant.

## Round 2 - answers from the owner (2026-09-25)

### Settled choices

1. **Scope is reading (A)**: the run-state glyphs of the Desktop sidebar rows
   must form one vertical column. Readings (B) and (C) are out of scope.
2. **The state comes first** in the sidebar row: `[state] [#key] [title] [skill
   badge]`, like the first column of the tickets pane.
3. **Titles are aligned too**: the task number reserves a common minimum width
   (tabular figures); a longer key overflows that width rather than being
   truncated. A free console, which has no key, reserves the same empty width so
   its state and title fall in the same columns.
4. **Sizes and the pulse stay as they are** (settled in #438).
5. The owner **confirmed that the clarification is satisfactory**. Exit condition
   met.

### Reversed or adjusted assumptions

- Round 1 kept the task number before the state. It now follows the state. The
  task number stays its own button (it opens the task in Sectile, and is disabled
  for a macro run); only its position and width change.

## Settled scope (consolidated)

1. In every Desktop sidebar row, the run-state glyph is the first element, and
   the glyphs of all rows share one column, free consoles included.
2. The task number follows the state in a column of common minimum width, with
   tabular figures, so titles start at the same x in every row; a longer key
   pushes its own title rather than being truncated.
3. A free console reserves the empty key width.
4. The key keeps its behaviour (opens the task, disabled for a macro run), its
   tooltip and its accessible label.
5. Header, tickets pane, glyph sizes, colours, the pulse, the web board and the
   server are unchanged.
6. The change is user-visible: the pull request adds a line under
   `## [Unreleased]` in `CHANGELOG.md`.
