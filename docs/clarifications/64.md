## Ambiguities, worst first

1. **Legacy tool-call compatibility — resolved by the user.** The user explicitly confirmed that `taskflow_*` names must no longer be supported and that both agent and server must be updated. Expose only the eight generic tools, reject old tool names, and provide no compatibility aliases. This decision supersedes the earlier rename's compatibility approach for MCP tool names specifically.
2. **Meaning of generic names — resolved from the request.** Remove only the product prefix, retaining the existing snake_case action names and schemas. Do not replace it with `sectile_`.
3. **MCP name scope — resolved from the code.** Rename both server implementation identities and the managed client registration to `sectile`; use Sectile names for the bridge and desktop MCP client identities. Changing only server metadata would leave the client-visible namespace as `taskflow`.
4. **Existing client configuration — resolved by convention.** Migrate the reserved legacy registration to one `sectile` entry during normal bootstrap, preserving unrelated configuration and explicit permission restrictions. Repeated bootstrap must not create duplicates. If both names already exist, preserve the existing Sectile configuration and do not silently broaden permissions while reconciling the legacy entry. Invalid or unsafe-to-reconcile configuration should produce a clear error without destructive rewriting.

## Critical dependencies

- Server and workstation agent changes must be coordinated: the bridge forwards upstream names, and desktop run completion directly calls a named tool. With immediate removal, old agents and already-running client sessions require upgrade/reconnection.
- All six supported provider configuration formats need migration coverage, including Vibe's array and Antigravity's user-level registry at `.gemini/config/mcp_config.json`.
- Project-owned skill overrides supersede built-in templates. Refreshing templates alone does not update stored custom instructions. Preserve user-owned content and document any manual update required by the compatibility decision; retain the existing backup workflow for generated files.
- No database schema change, external service addition, new credential, or other team dependency is identified.
