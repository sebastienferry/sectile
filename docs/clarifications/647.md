# Clarification #647 - MCP exposes no way to write a macro's todos

- Ticket: https://github.com/sebastienferry/sectile/issues/647
- Branch: `feat/batch-393-497-498-584-647-648` (batch of #393, #497, #498, #584, #647, #648)
- Report: `docs/clarifications/647.md` (committed on the batch branch)

## Round 1 - initial analysis (2026-10-01)

### Request

A macro skill that produced a slicing has no MCP tool to write it as the
macro's todos, and the REST fallback the skills name is not reachable from a
session on the workstation. An MCP tool writes a macro's todos without sending
the macro's shaping back, and `prepare_macro_worktree` reliably returns the
todos it says it returns.

Out of scope: creating the stories of a slicing (#634 already does it from the
web), writing todos to the tracker (they are Sectile's own), and the
marketplace `specify-macro` skill, which is maintained outside this
repository.

### Code read

- `internal/taskmcp/server.go`: the thirteen tools, `runTarget`,
  `prepare_macro_worktree`.
- `internal/db/macroruns.go`: `macroOf` (project, then the stored macro by
  key, case-insensitive), `PrepareMacroWorktree`, which copies `macro.Todos`

- `internal/db/macros.go`: `SaveMacroMeta`, `UpdateMacro` (writes the GitHub

- `internal/handlers/handlers.go`: the `POST /api/projects/{id}/epics` save

### Findings

- **The missing `todos` field.** `MacroWorkspace.Todos` is `omitempty`, so a
  macro whose stored list is empty returns no field at all. The 22 lines of
  PE-1078 were published on the Jira ticket as a comment on 2026-09-10; the
  likely reading is that they were never saved as the macro's todos, so the
  stored list is empty. This is confirmed or refuted on the live server during
  implementation; either way the answer always carries `todos`, an empty
  array when there are none, so "no field" stops being ambiguous.
- **The bridge catalog.** Adding a fourteenth tool makes an older agent's
  bridge refuse the newer server ("upgrade server and agent together"), and an
  older server refuse a newer bridge. Server and agent ship together, as for
  every catalog change.

### Ambiguities (worst first)

1. **Replace or merge, and what happens to a line that already has a
   story.** The ticket accepts either semantics. A whole-list replace that
   drops a line with a `storyKey` loses the link between the macro and a story
   that exists on the tracker; the web editor allows it today, after a person
   sees the list.

### Dependencies

- Server and agent upgrade together (bridge catalog).

### Technical choices settled here (reversible)

- **Tool.** `update_macro_todos(projectId, macroKey, todos, mode)`, `mode`
  being `replace` (default) or `append`. It writes the todos only, through the
  same local save as the web, so the shaping, the horizon and the tracker are
  never touched.
- **Ids.** A line that names an existing id updates that line and keeps its
  `storyKey` and targets unless the line sets them; a line without an id gets
  a new one. An unknown id is refused, so a list built from a stale read
  fails loudly instead of duplicating lines.
- **Append.** Keeps every existing line as it is and adds the given ones,
  which must carry no id.
- **Answer.** The saved macro's todos, with their ids.
- **`prepare_macro_worktree`.** Always returns `todos` (empty array when
  none).
- **Skills.** `refine-macro` names the tool for depositing the slicing, after
  the user confirms it; `realign-macro` keeps its rule of not writing todos.
- **Tests.** DB tests for replace, append, id preservation, unknown id,
  untouched description; an MCP contract test for the tool; the bridge test
  updated to fourteen tools.
- **Changelog.** One `Added` line.

### Open product questions

1. **A replace that drops a line linked to a story.**
   - A. Refused: the tool answers with the lines it would drop, and the skill
     asks the user to remove them from the web, where the story is visible.
   - B. Allowed, as in the web editor.
   - Recommended: **A**. A session cannot see what the person would see in the
     panel, and losing a story link is the one loss that is hard to notice.
