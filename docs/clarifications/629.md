## Round 1: analysis (2026-09-29)

### Request restated

Make the roadmap remember, between visits, its horizon tab, its selected epic, whether
the details panel is expanded and which panel sections are collapsed; let the user hide
the details panel so the list takes the full width; copy an epic's link or key from its
panel; maximize the framing editor into a full-screen editor with a side-by-side
preview; and show on an epic's maturity badge how many tickets lag behind it.
Out of scope: remembering the panel's display mode per tab, maximizing the ticket
description editor in the ticket detail modal, epic label badges (row 25, #626), and
anything on the Timeline.

### Findings that change the reading of the ticket

1. **"Tickets lagging behind the maturity" is always zero in Sectile today.** Sectile's
   maturity is the *lowest* stage among the open children (`web/src/lib/roadmap.ts:111`),
   so by construction no open ticket is below it. Taskativ's count only means something
   because its maturity is the highest stage reached by a *majority* of the children.
   Porting the count therefore needs a product decision (question 1).
2. **The "open in tracker" button opens a child ticket, not the epic.** The panel links
   `selected.tasks[0]?.externalUrl` (`RoadmapView.tsx:1153`), the URL of the first child,
   and the button disappears on an epic without children. `MacroMeta` carries no URL of its
   own. Copying "the epic's link" needs that URL first (dependency below).
3. **There are two framing editors, not one.** The framing panel has a "Description"
   `MarkdownEditor` and a "Framing notes" `MarkdownEditor`, both collapsible
   (question 3).
4. **Tab memory interacts with two existing behaviours.** Changing tab resets the panel
   display mode (LATER → framing, NOW/NEXT → execution), and a search with no match on
   the current tab jumps to the first tab that has one. A remembered tab must go through
   the same setter so both keep working.

### Ambiguities (worst first)

1. How "lagging" is counted (finding 1), which decides whether the maturity badge itself
   changes for every epic.
2. What "expanded panel" hides: Sectile keeps the tabs and toolbar visible when the panel
   takes the full width; Taskativ hides that chrome (`chromeHidden`).
3. Which editors get the maximize button (finding 3).
4. Copy "link or key": one button with a fallback, or two actions.

### Critical dependencies

- **Epic URL.** No stored or computed URL for a macro. It is derivable per tracker
  (GitHub milestone `https://github.com/<repo>/milestone/<n>`, Jira `<base>/browse/<key>`,
  GitLab depends on how macros map there). No migration is needed if the server computes
  it when listing macros. Without a URL the copy falls back to the key (question 4).
- **Clipboard.** `navigator.clipboard` requires a secure context; a server reached over
  plain HTTP (not localhost) has none. The failure must be said, with the text to copy by
  hand, as Taskativ does.
- **Translations.** New strings go to both catalogs under `t.planning.roadmap`
  (`docs/web-translation-checks.md`).
- No server migration, no tracker write. `CHANGELOG.md` gets one `Added`/`Changed` entry
  (user-visible change).

### Resolved technical decisions (reversible, settled here)

- **Storage.** Browser `localStorage`, following `roadmapDisplayMode.ts` (injectable
  `StorageLike`, tolerant reads, unavailable storage is a no-op), under
  `sectile_roadmap_*` keys. Same scope as the row mode and the panel width: per browser,
  so the web and the desktop app each remember their own.
- **Scope of each value.** Tab, panel expanded, panel hidden and the two section states
  are per browser, whatever the project. The selected epic is stored per project
  (`sectile_roadmap_selected_key:<projectId>`): an epic key means nothing in another
  project. A stored key that is no longer visible (closed, filtered, deleted) falls back to
  the first visible row, as today, and is not erased.
- **Tab restore.** The remembered tab goes through the same setter as a click, so the
  display-mode default of that horizon applies and the search jump still overrides it.
  An unknown stored value falls back to NOW.
- **Hide panel** (from Taskativ #53, which the ticket asks for): a button in the panel
  header next to Expand; hidden and expanded are exclusive (hiding un-expands, expanding
  un-hides); selecting another epic does not bring the panel back; a thin rail on the
  right edge brings it back; the split handle is hidden with the panel; the choice is
  remembered.
- **Maximize editor** (from Taskativ #16): an optional prop on `MarkdownEditor`, off by
  default so the comment and quick-add editors do not change; full-screen overlay with the
  editor and its rendered preview side by side; closed by its Restore button or Escape,
  and Escape there does not close anything else. The draft stays the same draft: the
  existing Save button and dirty state are untouched.
- **Open in tracker** uses the epic's own URL once available, and stays hidden when there
  is none (rather than opening a child).

### Product questions for the owner

1. **Lagging count.** Sectile's maturity is the lowest stage of the open tickets, so none
   lags behind it. What should the badge show?
   - **A (recommended):** keep the current maturity rule ("Ready" still means no ticket
     waits for clarification or specification), and show `+N` where N is the number of open
     tickets still at that lowest stage, only when some other open tickets are further
     along. Tooltip: "N tickets hold this epic at <stage>".
   - B: adopt Taskativ's rule (the highest stage reached by a majority), with `+N` the
     tickets below it. Every epic's badge may move up, and "Ready" no longer guarantees
     that no ticket waits.
2. **Expanded panel.** When the panel takes the full width, should the view's chrome
   (horizon tabs, toolbar, filter chips) disappear too?
   - **A (recommended):** yes, as in Taskativ: only the panel remains, with its Collapse
     button; the sidebar of the app stays.
   - B: no, keep today's behaviour and only remember the expanded state.
3. **Framing editors to maximize.**
   - **A (recommended):** both the Description and the Framing notes of the epic panel.
   - B: the Description only.
4. **Copy link or key.**
   - **A (recommended):** one "Copy link" button in the panel header copying the epic's
     URL, or `KEY: title` when the epic has no URL, with a toast saying which was copied;
     plus the "open in tracker" fix of finding 2.
   - B: two actions, "Copy link" and "Copy key" (the key alone).

## Round 2 - answers from the owner (2026-09-29)

Answered interactively in the session that ran round 1.

### Settled choices

1. **Lagging count: dropped.** No lagging count and no new badge. The maturity badge and
   its rule (lowest stage among the open tickets) stay exactly as they are. Row 12 of the
   comparison is left as it is; this ticket no longer covers it.
2. **Expanded panel hides the view's chrome.** When the panel is expanded, the horizon
   tabs, the toolbar and the filter chips disappear with the list; only the panel remains,
   with its Collapse button. The app sidebar stays. The expanded state is remembered.
3. **Maximize both framing editors.** The Description and the Framing notes of the epic
   panel get the maximize button; the other `MarkdownEditor` uses stay unchanged.
4. **One copy button with a key fallback.** A "Copy link" button in the panel header
   copies the epic's own tracker URL, or `KEY: title` when the epic has no URL, and a toast
   says which of the two was copied; a clipboard failure is said with the text to copy by
   hand. "Open in tracker" opens the epic itself, and is hidden when the epic has no URL,
   instead of opening its first child.

### Reversed assumptions

- Round 1 listed the lagging count in the restated request; it is now out of scope.

### Settled scope

In scope: remember the horizon tab, the selected epic (per project), the expanded panel
and the collapsed Description and Framing notes sections; hide and bring back the details
panel (remembered, exclusive with expand, not reopened by selecting another epic); hide
the view's chrome when the panel is expanded; maximize both framing editors with a
side-by-side preview, closed by Restore or Escape; copy the epic's link or key; open the
epic itself in the tracker, which needs the macro list to carry the epic's tracker URL.

Out of scope: any maturity count or rule change, remembering the panel display mode per
tab, the ticket description editor of the ticket detail modal, epic label badges (#626),
the Timeline.

The technical decisions of round 1 stand unchanged. No product question remains open.
