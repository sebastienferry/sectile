## 1. Restated Request and Scope

Extract all skill prose from Go string literals in `internal/db/skilltemplates.go` into embedded Markdown fragments (`goal.md`, `read-first.md`, `steps.md`, `guard.md`, `report.md`, and shared contracts) embedded via Go's `embed.FS`, retaining only UI metadata in `StageSkill`. Provide automated CI/CD validation scripts and build-time composition for `pickup` skills, verifying byte-for-byte exact rendering outputs against golden test baselines.

**Out of scope:**
- Changing the wording, phrasing, or formatting of any existing skill or slash command contract.
- Modifying UI labels, descriptions, icons, colors, or step descriptions displayed in the Sectile web or desktop interfaces.
- Altering the database schema or modifying `project_skills` persistence in `internal/db/projectskills.go`.
- Modifying client-side agent hooks, MCP tools, or runner execution flows.

## 3. Ambiguities, Worst First

1. **Skill Architecture & Layout**:
   - *Resolution*: Adopt fragment-based decomposition as proposed in #202:
     - `internal/db/skills/<id>/{goal,read-first,steps,guard,report}.md`
     - Framework variants suffixed: `steps.openspec.md`, `steps.speckit.md`, `read-first.openspec.md`.
     - Shared contracts in `internal/db/skills/contracts/{task-access,session-title,transition}.md`.
   - Reusable fragments allow `pickup` and `pickup_issues` to compose stages without duplicated wording.

2. **Skill Count & Coverage (10 skills vs 9 in ticket title)**:
   - *Resolution*: Migrate all 10 skills in `StageSkills` (`clarify`, `specify`, `implement`, `adjust`, `handoff`, `create_pr`, `pickup`, `rewrite_story`, `refine_macro`, `pickup_issues`) so that zero prose remains in `skilltemplates.go`.

3. **Title, Frontmatter, and Guard Heading Placement**:
   - `Title`, `FrontmatterDesc`, and `GuardTitle` remain metadata fields on `StageSkill`.
   - `guard.md` contains purely the list items, directly embeddable into `pickup` composition without stripping header lines.

4. **CI/CD Validation and Pickup Rebuilding**:
   - *Resolution*: Add automated skill validation script/tests in CI/CD to check YAML frontmatter syntax, markdown validity, and required sections.
   - Assert `pickup` composition consistency during `make test` / CI.

5. **Golden Baseline Test Storage**:
   - *Resolution*: Placed under `internal/db/testdata/golden/<skill>.<framework>.skill.md` and `...command.md`.

## 4. Critical Dependencies

- **Go Standard Library**: Uses `embed.FS` and `text/template`. No third-party dependencies required.
- **Backwards Compatibility**: Byte-for-byte exact match required so `projectskills.go`'s `isCustom` check (`strings.TrimSpace(content) != strings.TrimSpace(def.Content)`) does not trigger false positive customizations for projects using default templates.
- **Zero Tracker / DB Migration**: Pure codebase refactoring with no database changes or tracker migrations.
