## 3. Ambiguities, Worst First

1. **Skill Count & Coverage (10 skills vs 9 in ticket title)**:
   The ticket description refers to "nine workflow skills", but `StageSkills` currently defines 10 skills (`clarify`, `specify`, `implement`, `adjust`, `handoff`, `create_pr`, `pickup`, `rewrite_story`, `refine_macro`, `pickup_issues`).
   - *Resolution*: Migrate all 10 skills so zero prose remains in `skilltemplates.go`.

2. **Skill Architecture: Full Markdown Templates vs Micro-Fragments**:
   - The ticket initially proposed breaking skills down into `{goal,read-first,steps,guard,report}.md`.
   - *Owner Guidance & Resolution*: Extract each skill as a complete, readable Markdown template (e.g. `internal/db/skills/<id>.md`). This allows skills to be distributed and installed from a skills marketplace, standard `.claude/skills/` or `.skills/` directories, completely usable by any native agent (Claude Code, Codex, Antigravity) without relying on Go-side micro-stitching.

3. **Title and Frontmatter Description Location**:
   - *Resolution*: Lives naturally in each skill's Markdown frontmatter and `# Title` heading.

4. **Shared Contracts (`task-access`, `session-title`, `transition`)**:
   - *Resolution*: Placed in `internal/db/skills/contracts/` and included/templated where appropriate.

5. **Golden Baseline Test Storage**:
   - *Resolution*: Placed under `internal/db/testdata/golden/<skill>.<framework>.skill.md` and `...command.md`.

## 4. Critical Dependencies

- **Go Standard Library**: Uses `embed.FS` and `text/template`. No third-party dependencies required.
- **Backwards Compatibility**: Byte-for-byte exact match required so `projectskills.go`'s `isCustom` check (`strings.TrimSpace(content) != strings.TrimSpace(def.Content)`) does not trigger false positive customizations for projects using default templates.
- **Zero Tracker / DB Migration**: Pure codebase refactoring with no database changes or tracker migrations.
