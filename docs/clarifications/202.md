## 3. Ambiguities, Worst First

1. **Skill Count & Coverage (10 skills vs 9 in ticket title)**:
   The ticket description refers to "nine workflow skills", but `StageSkills` currently defines 10 skills (`clarify`, `specify`, `implement`, `adjust`, `handoff`, `create_pr`, `pickup`, `rewrite_story`, `refine_macro`, `pickup_issues`).
   - *Reading A*: Migrate all 10 skills in `StageSkills` so that zero prose remains in `skilltemplates.go`.
   - *Reading B*: Migrate only the 9 original workflow skills, leaving newer utilities like `rewrite_story` embedded in Go code.
   - *Resolution*: Reading A. All 10 skills should be migrated to maintain consistency across the catalogue.

2. **Placement of English Title and Frontmatter Description**:
   `StageSkill` holds `title` ("Clarify Issue", "Handoff and Close") and `frontmatterDesc` ("Analyse a ticket against the code...").
   - *Reading A*: Keep `Title` and `FrontmatterDesc` in `StageSkill` as Go metadata fields, treating them as structural metadata for YAML frontmatter and H1 headers.
   - *Reading B*: Extract `title` and `frontmatterDesc` into separate text/yaml fragments (e.g. `description.txt` or `metadata.yaml`) under each skill directory.
   - *Resolution*: Clarification question 1 below.

3. **Guard Section Heading Handling**:
   In 9 skills, the guard section heading is `## Do not`. In `implement`, it is `## Recovery and blockers`. Furthermore, in `pickup` and `pickup_issues`, the guard prose is included without the `## Do not` section header.
   - *Reading A*: Keep `GuardTitle` as metadata in `StageSkill` (defaulting to `"Do not"` when omitted), keeping `guard.md` strictly as the markdown list. This allows direct reuse in `pickup` composition without stripping header lines.
   - *Reading B*: Put the heading inside `guard.md`, requiring regex/prefix stripping during `pickup` step composition.
   - *Resolution*: Reading A. Cleanest composition without fragile text parsing.

4. **Directory Structure & Go Embed Path**:
   The proposed directory is `internal/db/skills/<id>/...` and `_contracts/...`. In Go `embed.FS`, directories or files starting with `_` or `.` are excluded by default unless `all:` is prefixed (`//go:embed all:skills` or `all:skills/*`).
   - *Reading A*: Use `internal/db/skills/contracts/` (without underscore) or `internal/db/skills/_contracts/` with `//go:embed all:skills`.
   - *Resolution*: Use `internal/db/skills/contracts/` or `//go:embed all:skills` to ensure standard Go embed compatibility.

5. **Golden Baseline Test Storage**:
   The safety net requires golden files generated from the current code prior to refactoring.
   - *Reading A*: Place golden files under `internal/db/testdata/golden/<skill>.<framework>.skill.md` and `...command.md`.
   - *Resolution*: Reading A, following standard Go `testdata` conventions.

## 5. Decisions (Reversible Technical Choices Settled from Existing Code)

1. **Golden Test Generation Prior to Code Changes**:
   A test will be created to render all 10 skills across all frameworks (`speckit`, `openspec`, and default `""`) for both `RenderSkillContent` and `RenderSkillCommand`, saving them into `internal/db/testdata/golden/`. The test suite will assert that the new embedded fragment renderer matches these golden files byte-for-byte.
2. **Fragment Granularity**:
   Each skill will have a directory `internal/db/skills/<id>/` containing:
   - `goal.md`
   - `read-first.md` (with framework variants `read-first.openspec.md` where needed)
   - `steps.md` (with framework variants `steps.openspec.md`, `steps.speckit.md` for `specify`)
   - `guard.md`
   - `report.md`
3. **Shared Contracts**:
   Shared contracts will be placed under `internal/db/skills/contracts/`:
   - `task-access.md`
   - `session-title.md` (using `text/template` for `.Item` ticket/macro and batch notes)
   - `transition.md` (using `text/template` for `.FromStage`, `.ToStage`, `.ID`, etc.)
4. **Template-Driven Assembly**:
   A clean template will assemble the skill content from the embedded fragments and metadata, replacing manual string concatenations while faithfully preserving spacing and newlines.
