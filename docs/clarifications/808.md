## Round 1 (2026-10-09)

### Restated request and scope

In the web UI Roadmap, a macro can no longer be sent to the HIDDEN horizon from where the owner works with it, whereas it could in Taskativ; the fix restores a reachable "hide" gesture (and, by symmetry, its undo). Out of scope: the meaning of the `hidden` horizon itself, its `roadmap:hidden` tracker label (#345), the board's "hidden project" notion, and the Desktop app unless it shares the same component.

### Files read and findings

- `web/src/components/RoadmapView.tsx`
  - `renderMacroRow` (unfolded row, line ~1462) still offers NOW / NEXT / LATER / HIDDEN buttons, each calling `persist(row.key, { horizon })`.
  - `renderCondensedRow` (line ~1563) offers only `CONDENSED_HORIZONS`.
  - The side panel header (line ~2047) only shows the current horizon as a read-only badge. Its NOW / NEXT / LATER / HIDDEN selector was removed by `3263a5a2` (2026-09-03, "remove duplicate horizon selector … from Macro side panel header").
  - The Hidden tab always renders unfolded rows (`condensedHere = … && tab !== 'hidden'`), so un-hiding is reachable from there.
  - `persist` saves through `saveMacroMeta` and switches to the target tab on success.
- `web/src/lib/roadmapDisplayMode.ts:27-34`: `CONDENSED_HORIZONS = ['now', 'next', 'later']`, with the comment "hiding a macro … stays offered by the unfolded shape **and by the panel**". Since `3263a5a2` the second half of that comment is false.
- `web/src/lib/roadmapDisplayMode.ts:62-76`: the unfolded shape is the default; the condensed shape is a stored preference.
- `internal/db/macros.go:29-72` (`HorizonHidden`, `normalizeHorizon`): the server still accepts and stores `hidden`; `internal/db/macrohorizons.go` mirrors it as `roadmap:hidden`. No server-side regression found.
- Taskativ (`/Users/sferry/Sources/apps/taskativ`, last commit 2026-09-14): same `CONDENSED_HORIZONS` rule and a test asserting it (`roadmap.test.ts:755`), and the panel shows a badge only. Taskativ's code as checked out therefore does not offer more than Sectile does; the difference the owner remembers may come from an earlier Taskativ version or from a gesture I did not find.

### Most likely cause

A user on the **condensed** row shape has no way left to hide a macro: the condensed row deliberately omits HIDDEN, and the panel that was supposed to make up for it lost its selector on 2026-09-03. Only switching back to the unfolded shape gives the button back. Not yet confirmed by the owner (Q1).

### Ambiguities, worst first

1. **Symptom.** (a) No HIDDEN control is reachable (condensed shape / panel), or (b) clicking HIDDEN does nothing or the macro comes back (save or tracker re-import overriding it). (a) is a UI change; (b) is a persistence or sync bug in another layer. See Q1.
2. **Where the gesture comes back.** Panel selector, condensed row, or a row action menu. Each leads to different code and reverses a different earlier decision. See Q2.

### Critical dependencies

None: no migration, no API change, no tracker limit. `saveMacroMeta` and the `roadmap:hidden` label already handle the value.

### Reversible technical choices resolved from existing code

- Whatever surface is chosen calls the existing `persist(key, { horizon: 'hidden' })`, so the tab switch, the toast on a missing project and the tracker mirroring stay as they are.
- The comment of `CONDENSED_HORIZONS` is corrected to match the surface that offers HIDDEN.
- A UI test covers hiding a macro from the chosen surface while the list is condensed.
- A `Fixed` line goes under `## [Unreleased]` in `CHANGELOG.md` (user-visible).
