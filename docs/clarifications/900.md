# Clarification #900: Desktop | Select operating mode (Companion vs Agent) at first launch and allow switching in Settings

## Round 1 (2026-10-30)

Report: `docs/clarifications/900.md` on `feat/tauri-monorepo` (ticket [#900](https://github.com/sebastienferry/sectile/issues/900)).

### Restated request and scope

Provide an explicit, welcoming onboarding view on initial launch when Sectile Desktop (Tauri) has no configured runtime mode, letting the user choose between **Local Companion mode** (fully autonomous on the workstation with an embedded SQLite server) and **Agent / Fleet mode** (paired with a remote Sectile team server). Furthermore, allow switching between these modes at any time in Settings (under Services / Mode d'exécution) with full state and data isolation.

Out of scope: modifying the central Sectile server API, altering standalone headless CLI behavior (`sectile-agent`), or merging local SQLite databases with remote Fleet databases.

### Files read

- `desktop-tauri/src/App.tsx`: startup sequence, project refresh, fallback to settings when empty, view routing.
- `desktop-tauri/src/components/LocalSettings.tsx`: sections navigation, current mode rendering, Fleet pairing form, local runtime enablement.
- `desktop-tauri/src/lib/local.ts`: API wrappers for `localSetupStatus`, `enableLocalRuntime`, `pairFleetAgent`, `attachFleetAgent`.
- `desktop-tauri/src-tauri/src/local.rs`: `runtime_mode`, `save_mode`, `local_setup_status`, `resume`, `LocalRuntime`.
- `desktop-tauri/src-tauri/src/lib.rs`: setup lifecycle, menu events, settings shortcut.

### Ambiguities, worst first

1. **First-launch experience: Modal vs Dedicated full-screen onboarding.**
   When no mode is selected, the application currently falls back to `LocalSettings` with a confusing list of tabs. A dedicated onboarding view provides clear framing, whereas a modal or dropping directly into settings overwhelms a first-time user.
2. **Data retention across mode switches.**
   When switching from Local to Fleet and back, should the local SQLite database and projects remain intact?
3. **Active executions guard during mode transition.**
   If an LLM discussion or autonomous task is actively running in one mode, switching modes would detach the UI from that execution.
4. **Window closing and daemon lifecycle on macOS.**
   Closing the Tauri window vs quitting the application (`Cmd+Q`): how background tasks and conversations continue.

### Critical dependencies

- `desktop-tauri/src-tauri/src/local.rs`: Already supports `RuntimeMode::Local` and `RuntimeMode::Fleet` with independent directory isolation (`generations/companion-v1` and `fleet/`).
- Native Tauri window events and background process management.

### Reversible technical choices

- Create a dedicated component `desktop-tauri/src/components/ModeOnboarding.tsx` shown in `App.tsx` when `setup.mode === "unconfigured"` or `!setup.mode`.
- In `LocalSettings.tsx`, unbind mode-switching controls from the `unconfigured` state so that "Switch to Fleet" is always accessible from Local mode, and "Switch to Local Companion" is always accessible from Fleet mode.
- Maintain independent data roots (`generations/companion-v1` and `fleet/`) so toggling modes never deletes local tickets or fleet pairing credentials.
- When active executions exist, prompt with a confirmation warning before switching modes.

### Product questions for the owner

1. **Onboarding Presentation:**
   Do you confirm that first launch (unconfigured) should display a dedicated full-view onboarding screen with two visual cards ("Mode Compagnon Local" vs "Mode Agent Fleet") rather than dropping directly into the Settings panel?
   *(Recommended: Yes, a dedicated full-view onboarding screen).*

2. **Data Isolation vs Unified Views:**
   When switching between Local mode and Fleet mode in Settings, each mode maintains its own separate workspace, projects, and credentials (switching to Fleet shows the team's projects on the server; switching to Local shows local SQLite projects). Do you confirm this isolation?
   *(Recommended: Yes, maintain strict isolation between Local workspace and Fleet workspace).*

3. **Active Executions Guard:**
   If a conversation or background task is running when the user attempts to switch modes in Settings, should Desktop block the switch with a confirmation prompt ("Des tâches sont en cours d'exécution. Voulez-vous vraiment basculer de mode ?")?
   *(Recommended: Yes, require explicit confirmation to avoid accidental detachment).*
