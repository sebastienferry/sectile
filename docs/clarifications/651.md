# Clarification: #651 - Fix the browserRoot and skillLaunchModel web tests failing on Windows

## Round 1 - reproduction and code review (2026-09-30)

### Request and scope

Make `web/tests/browserRoot.test.mjs` and `web/tests/skillLaunchModel.test.mjs` pass on Windows, from a checkout with CRLF line endings and whether or not its path contains `#`, without breaking them on Linux / CI. The Vite-root behaviour of `web/tests/browserRoot.mjs`, the TSX components the source assertions read, the browser tests (`*.browser.mjs`), a repository-wide line-ending policy and the other web tests are out of scope; skipping the tests on Windows is not allowed.

### Verified context

- Task: `gh-11a4f59c-b6bd-4747-8ea5-0a10d5b78da4-651`, https://github.com/sebastienferry/sectile/issues/651. No comments, no parent.
- Assigned branch: `feat/651`; worktree: `.tasks/worktrees/issue-651` (its path holds no `#`).
- Environment: Windows 11, Node v26.10.0, `core.autocrlf=true` (user `.gitconfig`), no `.gitattributes` in the repository, so tracked text files are checked out with CRLF (`git ls-files --eol` gives `i/lf w/crlf` for `web/src/components/TaskCard.tsx`).
- Read: `web/tests/browserRoot.mjs`, `web/tests/browserRoot.test.mjs`, `web/tests/skillLaunchModel.test.mjs`, `web/src/components/TaskCard.tsx` (the `modeActions` fragment, line 586), `web/package.json`, the `test` recipe in `Makefile`, `.github/workflows/*.yml` (every job runs on `ubuntu-latest`), and `docs/clarifications/553.md` (the earlier `#`-path fix in the i18n date test).

### Evidence - 3 failures, 2 root causes, neither is `#`

`node --test tests/browserRoot.test.mjs` (from `web/`): 2 of 4 fail.

- `a path without # is served as it is` (line 19): `assert.equal(root, join(dir, 'web'))` gets `C:/Users/.../387/web` against `C:\\Users\\...\\387\\web`.
- `a path with # relaunches the test through a link to the same checkout` (line 29): `assert.equal(root, web)`, where `web = join(script, '..', '..')`, fails the same way (`.../checkout/web` with `/` against `\\`). The symbolic link itself is created and resolved correctly; every earlier assertion of the test passes.
- **Root cause: path separators.** `browserRoot()` deliberately returns `web/` "in forward slashes and without a trailing slash, because the fixtures match Vite's module ids against it" (its doc comment), while the test builds its expected value with `path.join`, which uses `\` on Windows. The helper is right; the test's expectation is platform-specific. On Linux both sides use `/`, which is why CI passes.

`node --test tests/skillLaunchModel.test.mjs` (from `web/`): 1 fails.

- `both card shapes share the model entry` (line 124): `the shared fragment is still there` - `card.match(/const modeActions = \([\s\S]*?\n {2}\)\n/)` returns `null`.
- **Root cause: CRLF.** The regex requires `)` directly followed by `\n`; in a CRLF checkout the source line ends with `)\r\n`. Verified: the same regex matches once the file content has `\r\n` replaced by `\n`, and the `{isCondensed && (...)}` / `{!isCondensed && (...)}` patterns of the same test match in both cases.

`#` in the path: not involved in either failure. `skillLaunchModel.test.mjs` reads sources through `new URL('../src/…', import.meta.url)`, which keeps `#` percent-encoded (`%23`); a reproduction from a scratch directory named `#605` reads the sibling file correctly. `browserRoot.test.mjs` builds its checkouts in fresh temporary directories, so the worktree's own path never reaches its assertions. The `#` hypothesis in PR #623 is therefore reversed; #553 was a different problem (a spawned script embedding a decoded path).

### Settled technical choices

1. **browserRoot: fix the test, not the helper.** Compare `root` with the expected path converted to forward slashes (e.g. a local `slashes = p => p.replace(/\\/g, '/')` applied to `join(dir, 'web')` and to `join(script, '..', '..')`), keeping the helper's documented contract that Vite fixtures depend on. The `realpathSync` comparisons and the relaunch assertions stay as they are.
2. **skillLaunchModel: make the source read independent of line endings in the test.** Normalise in the test's `read` helper (`.replace(/\r\n/g, '\n')`), so every assertion of the file sees LF, rather than rewriting each regex to `\r?\n`. No `.gitattributes` is added: it would change the checkout of every file for every Windows contributor and needs a renormalisation, which is far beyond these tests (see question 1).
3. **No skip, no platform branch.** Both fixes are no-ops on Linux (no `\`, no `\r`), so CI behaviour is unchanged.
4. **Verification during implementation:** `node --test tests/browserRoot.test.mjs` and `node --test tests/skillLaunchModel.test.mjs` from `web/`, in this worktree (no `#`) and in a worktree whose path holds `#` (e.g. a `git worktree add` under a `#651-check` directory, removed afterwards), plus `npm test` in `web/` once. The root cause of each failure goes into the PR description, as the acceptance criteria require.
5. No production code, dependency, migration, changelog, README or ADR change: this is a test-only correction.

### Ambiguities and dependencies

- **Symbolic links on Windows (noted, not in scope).** The `#` test calls the real `symlinkSync(checkout, link, 'dir')`. It succeeds on this workstation, but on a Windows machine without Developer Mode or elevation it would throw `EPERM`. This is a pre-existing property of the helper that the ticket's failures do not involve; it is recorded here and left out unless the owner wants it covered.
- **Other source-reading tests.** Other `web/tests/*.test.mjs` read TSX sources as text; they pass today in a CRLF checkout, so they are not touched. Normalising only `skillLaunchModel.test.mjs` keeps the change to the reported failures.
- No external service, data or third-party limit is involved.

### Open questions for the owner

1. **Line-ending fix location** - recommended: normalise CRLF in `skillLaunchModel.test.mjs`'s `read` helper (local, no effect on anyone's checkout). Alternative: add a `.gitattributes` pinning LF (`* text=auto eol=lf`, or only for `web/src/**`), which also protects future source-assertion tests but renormalises the working tree of every Windows contributor.
