# Clarification Report — Ticket #795

**Ticket**: `#795` (`gh-7f9fa863-3320-4e5d-a2d6-d14f7b3c35cf-795`)
**Title**: Ask for tracker credentials after a project save only when the chosen tracker needs them, on that tracker
**Date**: 2026-10-14
**Mode**: Autonomous (`pickup-issues` batch)

## 1. Context & Codebase Analysis

1. **Current Post-Save Trigger (`web/src/components/ProjectModal.tsx`)**:
   - After creating or updating a project (`ProjectModal.tsx:499`), the modal runs:
     ```ts
     if (selectedChoices.some(option => needsCredentialsFor(option.provider, settings, userCredentials))) {
       setIsTrackerSetupOpen(true)
     }
     ```
   - `TrackerOption` (`web/src/lib/projectTrackers.ts`) does not carry `site` from `TrackerSummary`, even though `GET /api/trackers` returns `site` on every `TrackerSummary`.

2. **Why `needsCredentialsFor` and `TrackerSetup` Are Out of Sync with `#741` and `#654`**:
   - `needsCredentialsFor` (`web/src/lib/trackers.ts:338-349`) only checks the provider string (`c.tracker === kind`). For Jira, it ignores the tracker's site (or the deployment's `settings.jiraUrl` when the tracker's `site` is empty), so a user whose Jira API token (`siteUrl`) or OAuth grant (`grantedSites`, `!disconnected`) covers another site is not prompted, while a disconnected OAuth grant still counts as `c.tracker === 'jira'`.
   - `TrackerSetup` (`web/src/components/TrackerSetup.tsx`) always initializes its provider to `initialTracker(settings.issueTracker)` and shows the provider picker over all providers (`jira`, `github`, `gitlab`), without pre-filling the chosen tracker's site.
   - `trackerCredentials.setup.description` (`web/src/locales/translations.ts`) still says that without these values "synchronization fetches nothing", whereas since `#741` tracker synchronization runs under the server credential and personal credentials are needed to act on the tracker under the user's own account (`ForWrite`).

## 2. Decisions Recorded

1. **Site-Aware Credential Coverage (`web/src/lib/trackers.ts` & `web/src/lib/projectTrackers.ts`)**:
   - Carry `site` on `TrackerOption` in `web/src/lib/projectTrackers.ts` (from `summary.site`, or from the second segment of `ref.identity` when building a fallback option).
   - Normalize Jira sites with `jiraSite(raw)` (matching `trackerapi.JiraSite` / `jiraBaseURL` on the server: `http`/`https` scheme + lowercased host).
   - Resolve a tracker's effective site via `trackerSiteFor(tracker, settings)` (the tracker's own `site`, or the address in its `identity`, falling back to `storedFor(settings, provider).siteUrl`).
   - Update `needsCredentialsFor` to accept either a provider string or a tracker descriptor (`{ provider, site?, identity? }`):
     - For Jira, a personal credential covers the tracker only when:
       - `kind === 'oauth'`: `!c.disconnected` and (`grantedSites` covers the normalized target site, or is non-empty when no target site is known).
       - `kind !== 'oauth'` (API token): `!targetSite || jiraSite(c.siteUrl) === targetSite`.
     - For GitHub and GitLab, a personal credential covers the tracker when its `siteUrl` is empty or matches the tracker's site; when no personal credential covers it, the server token (`tokenIsSet` / `tokenFromEnv`) covers the tracker only when the tracker uses the deployment's site.
   - Provide `trackerSetupTargetFor(trackers, settings, mine)` returning `{ provider, site }` for the first selected remote tracker that lacks covering credentials, or `null` when all selected trackers are covered.

2. **Target-Aware `TrackerSetup` (`web/src/components/TrackerSetup.tsx`, `web/src/components/TrackerCredentialForm.tsx`, `web/src/context/AppContext.tsx`, `web/src/components/ProjectModal.tsx`)**:
   - Store `trackerSetupTarget` in `AppContext` via `openTrackerSetup(target)` (cleared when `TrackerSetup` closes).
   - When `TrackerSetup` is opened with a target tracker, open directly on `target.provider`, hide the provider picker, and pass `initialSiteUrl={target.site}` to `TrackerCredentialForm` so the site field is prefilled with the chosen tracker's site.
   - Update `trackerCredentials.setup.description` in French and English to state that credentials are needed to act on the tracker under the user's own account and are verified with the instance before being saved.
