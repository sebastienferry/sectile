# Clarification #533 - Web i18n: sign-in and account credential/workstation flows

Batch #526 to #534; shared decisions D1 to D9 are in `docs/clarifications/526.md`.

## Round 1 (2026-09-26)

### Request

The sign-in screen is outside the authenticated translation context and
hardcodes English; `ApiKeys.tsx`, `lib/apiKeys.ts` and `LocalAgentSetup.tsx`
hold English status, expiry and copy text. A signed-out visitor must get
French or English through an explicit, documented selection and fallback;
after sign-in the personal preference wins. Credential behaviour is unchanged.

### Code read

`SignInScreen.tsx`, `SignInStatus.tsx`, `ProfileModal.tsx`,
`TrackerCredentialsTab.tsx`, `TrackerCredentialForm.tsx`, `ApiKeys.tsx`,
`LocalAgentSetup.tsx`, `MCPEngineConfig.tsx`, `UsersPanel.tsx`,
`lib/apiKeys.ts`, `lib/session.ts`, `App.tsx` (the sign-in screen is rendered
before `AppProvider`), `tests/apiKeys.test.mjs`, `tests/session.test.mjs`.

### Ambiguities

1. Pre-authentication locale: settled by D6 (remembered language, then the
   browser language, French when it starts with `fr`, English otherwise, and
   a French/English switch on the sign-in screen).
2. `lib/apiKeys.ts` returns English warnings: it takes the strings as a
   parameter instead of returning prose, so the helper stays pure and
   testable.
3. Error messages the server sends back (`body.error`) stay verbatim, with a
   translated fallback when there is none.

### Decisions

Strings go to the `signIn` namespace (D1). The sign-in screen reads its
strings from `translations[locale]` directly, since `useApp()` is not mounted
there.

### Product questions

None open. Exit condition met.
