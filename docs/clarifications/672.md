# Clarification #672 - Roadmap: make "AI refine" launch the refine-macro skill on the local agent

## Round 1 - initial report (2026-10-06)

### Request

The "AI refine" button of a macro's Framing panel stops calling the
deterministic line splitter behind `POST /macros/{key}/refine` and launches the
interactive `refine_macro` skill on the user's local agent instead, exactly as
"Realign the spec" launches `realign_macro`, with the same agent check, active
run display, stop action and refresh of the macro once the run ends.
Out of scope: any change to the `refine-macro` skill itself, to the server's
`run-skill` / `runs` / `cancel-run` routes, to how the Desktop app shows an
interactive run, and to a launch path for users without a local agent.

### Ambiguities, worst first

1. **Fate of the deterministic generator** (`/refine` routes, `RefineMacro`,
   the preview modal, "import selected"). Removing it and relabelling it lead to
   different code, tests and UI. This is a product choice: question Q1 below.
2. **Which button shows a run.** Both buttons poll the same `runs` list, and
   `activeMacroRun` takes any running run. Without a filter, a refine run would
   show as "Realignment running" on the Realign button, with its stop square.
   Settled below (D2).
3. **When the panel refreshes.** Nothing pushes a macro update to the browser
   (the SSE listener only handles `task_updated`), and `fetchProjectMacros` only
   reruns on `activeJobCount` or a project change. Settled below (D4).

### Critical dependencies

- No server change and no migration: `run-skill` already accepts `refine_macro`
  (`macroruns_test.go` launches exactly that), and the server already refuses a
  second active run on a macro.
- The refine-macro skill writes TODOs through `update_macro_todos` and cards
  through `create_task`; the panel only has to re-read the macro.
- A connected local agent is required, as for Realign. Without one, the button
  is disabled and says why; there is no fallback launch.

### Technical choices settled from the code (reversible)

- **D1 - One generic component.** `MacroRealignButton` becomes a
  `MacroSkillButton` taking the skill ID, the strings block, the icon and the
  colour classes as props. Realign keeps its sky colour and `GitCompareArrows`
  icon; Refine keeps its current orange colour and `Sparkles` icon, so neither
  button changes look.
- **D2 - One run list, matched by skill.** The runs are read once per macro (a
  `useMacroRuns` hook or the parent passing them down) instead of each button
  polling on its own. A button shows the active run and its stop action only
  when the run's `skillName`, normalised through the catalog aliases
  (`refine`, `refine-macro`, `refine_macro`), is its own skill. The other button
  is disabled with a tooltip saying another skill is running on this macro. Where
  a run of a third skill (started by hand through MCP) is shown is left to the
  specification, with one constraint: it stays stoppable from the panel, as it
  is today through the Realign button.
- **D3 - Before launch.** The Refine button keeps the current preconditions of
  `handleRefineMacro`: a blank description shows the "framing required"
  warning and launches nothing; a dirty draft is saved first, then the skill is
  launched. Realign is unchanged.
- **D4 - Refresh on run end.** When the matched run leaves the active state
  (completed, failed or canceled), the component calls back to the panel, which
  re-reads the project's macros with `fetchProjectMacros`. This applies to both
  skills, since realign-macro also rewrites the macro.
- **D5 - Strings.** A `refine` block mirrors `realign` (noAgent,
  alreadyRunning, running, waiting, launched, launchRefused, stopTitle,
  stopLabel, stopRefused, forceClose) in both the French and English locales,
  plus one "another skill is running" string. The button label stays
  "AI refine" / "Raffiner AI": it now runs an AI skill. Its tooltip is reworded
  to say it launches the refine-macro skill on the local agent.
- **D6 - Tests.** `web/tests/macroRuns.test.mjs` extends to the skill matching
  and the shared blocker; a component or browser test covers the launch, the
  blocked case (no agent) and the cross-skill guard, following the existing
  macro run tests.

### Product questions

- **Q1 - The deterministic generator: remove it or relabel it?**
  - **(a) Remove it (recommended).** Delete both `/refine` routes,
    `RefineMacro`, `GenerateMacroTodosFromFraming`,
    `GenerateProposedMacroTasksFromFraming`, `TestRefineMacro`,
    `refineMacro` in `AppContext`, `RefineMacroResult`, the preview modal and its
    strings. The skill does the same job with judgment, the generator only
    prefixes each description line, and two neighbouring buttons that both
    "turn the description into TODOs" would confuse. Without an agent, TODOs are
    still added by hand.
  - **(b) Keep it, relabelled** "Generate TODOs from the description" /
    "Générer les TODO depuis la description", with no AI wording, as a third
    button in the Framing header (or in a menu). It keeps working without an
    agent, at the cost of the code and a third action next to Refine and
    Realign.

## Round 2 - answers from the owner (2026-10-06)

### Answers

- **Q1 - removed.** The owner chose (a): the deterministic generator goes.
  "AI refine" launches only the refine-macro skill.
- **Clarification confirmed.** The owner confirmed that the clarification is
  satisfactory, with D1 to D6 of Round 1 kept as they are.

### Reversed assumption

- **The skill creates no cards.** The ticket says that the run writes "TODOs
  and cards". It does not: refine-macro saves the confirmed TODOs through
  `update_macro_todos` (`internal/skills/testdata/golden/refine_macro.speckit.skill.md`,
  step 6) and only *proposes* tickets in the session. Cards come from the panel's
  existing "Create the stories (n)" action (`createStoriesFromMacroTodos`), one
  story per selected TODO in its target project, which also replaces the modal's
  "import selected" step. The acceptance criterion "TODOs and cards written by
  the run show up in the panel" reads as "TODOs saved by the run show up in the
  panel without a manual reload" (D4).

### Settled scope for the specification

- Remove: both `/refine` routes (`internal/handlers/handlers.go`, the
  project-scoped one and `HandleMacroRoute`), `RefineMacro`,
  `GenerateMacroTodosFromFraming`, `GenerateProposedMacroTasksFromFraming`
  (`internal/db/macros.go`), `TestRefineMacro`, `refineMacro` in
  `AppContext`, `RefineMacroResult`, the `refinePreview` modal and its state in
  `RoadmapView.tsx`, and the strings left unused (`refineModal.*`,
  `noGeneratedData*`, `refineRefused`, `refineFailed`). The specification checks
  each helper for another caller before deleting it.
- Keep and generalise: `MacroRealignButton` into `MacroSkillButton` (D1), the
  shared run list matched by skill (D2), the launch preconditions (D3), the
  refresh on run end (D4), the strings (D5) and the tests (D6).
- `CHANGELOG.md` under `## [Unreleased]`: a `Changed` line ("AI refine" now
  launches the refine-macro skill on the local agent) and a `Removed` line (the
  line-by-line TODO preview generated from the description).
