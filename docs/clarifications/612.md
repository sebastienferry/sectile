## Round 1 - initial report (2026-09-29)

### Restated request and scope

On the web board's task card, the model indicator shown in front of the action
buttons becomes the control that changes the launch model, instead of a passive
label whose picker is buried in the `(...)` menu. The card also gains an icon
button that copies, in one click, the prompt to paste into the AI engine's
desktop app (Claude Code, Codex or AGY) to run the task's next step.

Out of scope: the Sectile Desktop app (its own renderer, `desktop/src/`), the
task detail modal, the server and the local agent, the way a launch resolves its
model, and the wording of the copied prompt beyond what the questions below
settle.

### What the card does today

- `web/src/components/TaskCard.tsx` shows `modelIndicator`, a plain `<span>`,
  on both card shapes (full: bottom row before the `>` / `>>` buttons;
  condensed: before the `(...)` button). Its colour tells a chosen model
  (accent) from the configured one (muted); `?` means no agent of the caller
  serves the project (`engine.state === 'unknown'`).
- Changing the model goes through `(...)` → "Avancer avec le modèle" → a
  sub-list of `menuitemradio` entries: the configured model ("(actuel)") plus
  `reportedPickerModels(engine, skill)`. Choosing stores the pick per task in
  local storage (`web/src/lib/launchModel.ts`) and launches nothing; every
  launch from the card then uses it (`advanceTask(..., effectiveLaunchModel)`).
- The picker exists only when the reported command line has a model slot and a
  model list (`cardModels`). When no model is configured and none is chosen,
  the indicator renders nothing although the sub-menu is available.
- Copying a prompt already exists in the `(...)` menu through
  `web/src/components/CopyTaskSkillMenu.tsx` (also used by
  `TaskDetailModal.tsx`): "Copier /<stage skill>" and "Copier /pickup-issue".
  The prompt is engine-neutral: `/<skill> <task id>. Use Sectile MCP to read
  the task … start_run … finish_run …`. On a blocked clipboard it shows the
  prompt in a `<pre>` to select by hand. `skillCommand` in `AppContext.tsx`
  currently returns the default command (no per-project override).
- The local agent launches every engine with the same `/<command> <taskKey>`
  prompt (`dispatchCommand` in `internal/agent/agent_config.go`); only the
  command line around it differs per provider.

### Ambiguities (worst first)

1. **Which prompt the icon copies**: the current column's step only, or a
   choice between the step and the full chain (`/pickup-issue`), as the menu
   offers today. One click versus a small menu.
2. **Whether the copied prompt depends on the engine**: one engine-neutral
   prompt (today's) or a per-engine form (Codex and AGY do not necessarily
   invoke skills with a leading `/`). Changes the prompt builder and needs the
   reported provider.
3. **What happens to the old model sub-menu** in `(...)`: removed (the
   indicator becomes the only entry point) or kept as a second path.
4. **Which card shapes get the copy icon**: the condensed card is a single
   line already crowded with badges.

### Critical dependencies

- None outside the web app: no migration, no server or agent change for the
  engine-neutral reading. A per-engine prompt would rely on
  `EngineReport.provider`, which is only present when the workstation reported.
- The clipboard API needs a secure context; the existing fallback (`<pre>`)
  must stay reachable from an icon that has no menu around it.

### Resolved technical choices (reversible)

- The indicator becomes a `<button aria-haspopup="menu">` that opens a small
  popover anchored to it, reusing the existing radio list (configured model +
  offered models), its keyboard handling and `saveLaunchModel`. Choosing still
  launches nothing.
- The indicator is clickable only when there is something to pick
  (`cardModels.length > 0`). When no model is configured and none is chosen,
  it shows a neutral placeholder (a `Cpu` icon) so the menu stays reachable.
  `?` (engine unknown) and a command line without a model slot stay passive,
  with their current tooltip.
- Same behaviour on the full and the condensed card, since both already carry
  the indicator.
- The copy icon reuses `CopyTaskSkillMenu`'s prompt builder (extracted into a
  shared helper), confirms with the existing toast pattern, and is hidden on a
  finished task (no step left).
- Clicks on both controls stop propagation, so they neither open the task nor
  start a drag.
- UI strings are added in French and English in `web/src/locales/`.

### Product questions (with recommendation)

1. **Copy icon content**: recommended: copy the prompt of the current
   column's step in one click; `/pickup-issue` stays in the `(...)` menu.
2. **Per-engine prompt**: recommended: keep the single engine-neutral prompt,
   as the agent itself launches every engine with it; a per-engine form would
   be a separate ticket.
3. **Old sub-menu "Avancer avec le modèle"**: recommended: remove it from
   `(...)`, the indicator being the one place to choose; "Avancer
   (interactif / autonome)" entries stay.
4. **Copy icon on the condensed card**: recommended: full card only; the
   condensed card keeps the copy entries of its `(...)` menu.

## Round 2 - answers from the owner (2026-09-29)

The owner answered the four Round 1 questions interactively.

### Settled decisions

1. **Copy icon content**: one click copies the prompt of the current column's
   step (`/clarify-issue`, `/specify-issue`, ...). `/pickup-issue` stays in the
   `(...)` menu. Recommendation accepted.
2. **Per-engine prompt**: a single engine-neutral prompt, the one
   `CopyTaskSkillMenu` builds today and the agent sends to every engine.
   Recommendation accepted; a per-engine form is out of scope.
3. **Sub-menu "Avancer avec le modèle"**: kept in the `(...)` menu. The model
   indicator becomes a second entry point to the same choice, sharing the same
   stored pick (`saveLaunchModel`). Recommendation reversed by the owner.
4. **Copy icon on the condensed card**: full card only; the condensed card keeps
   the copy entries of its `(...)` menu. Recommendation accepted.

### Reversed assumptions

- Round 1 assumed the sub-menu would be removed and the indicator would be the
  only place to choose. Both entry points now stay, and must show the same
  selection: a pick made from one is reflected by the other.

### Settled scope

- Web board task card only (`web/src/components/TaskCard.tsx` and helpers);
  Sectile Desktop, the task detail modal, the server and the agent are out of
  scope.
- The model indicator is a button opening the model radio list on both card
  shapes when the engine offers models; `?` and a command line without a model
  slot stay passive. The reversible technical choices of Round 1 stand.
- A copy icon on the full card's bottom row copies the current step's prompt,
  confirms with a toast, keeps a manual-selection fallback when the clipboard is
  refused, and is hidden on a finished task.
- The change is user-visible: the implementation adds a line under
  `## [Unreleased]` in `CHANGELOG.md`.

### Status

No product question remains open; exit condition met. Report
`docs/clarifications/612.md` committed on `feat/612` (not pushed:
`pushStageCommits` is off). Ready for specification.
