# Clarification — GitHub #56

## Restated Request & Scope
The user requests that the Board view remembers whether cards are displayed in condensed (single-line) or expanded (detailed) mode across page reloads and view navigation, rather than always resetting to condensed.

Out of scope: modifying other views (such as Backlog, Roadmap, or Sprint Timeline), introducing additional density modes beyond the current condensed/expanded toggle, or modifying card layout/content.

## Ambiguities, Worst First
1. **Persistence Mechanism**: LocalStorage client-side persistence vs database/backend `UserSettings`.
   - *Impact*: Changes data contracts, API endpoints, and migration requirements if stored in DB.
   - *Resolution*: Use `localStorage` client-side storage, matching existing view-level preferences like `sectile_board_grouping`, `sectile_hide_done`, and `sectile_sprint_display_mode`. No backend changes or DB schema migrations needed.
2. **Default State When Unset**:
   - *Impact*: Determines what new users or cleared sessions see.
   - *Resolution*: Default to `condensed` (`true`), preserving the established default behavior.
3. **Storage Key & Value Representation**:
   - *Impact*: Affects naming convention and compatibility.
   - *Resolution*: Use key `sectile_board_display_mode` with fallback check on `taskacao_board_display_mode`. Store values `'condensed'` | `'expanded'`, with resilient parsing that also handles boolean strings (`'true'` / `'false'`).

## Settled Scope & Assumptions
