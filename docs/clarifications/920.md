### Actual symbol inventory

| Context | Symbol | Meaning and action |
| --- | --- | --- |
| Ticket skill: working | Pulsing blue circle | Work queued, preparing or running; no response implied. |

| Ticket skill: done | Green circle | The skill's outcome is recorded; workflow skills also satisfy their expected task stage. Does not mean the entire ticket is finished. |

Reduced-motion preferences disable the pulse. Identical-looking indicators need contextual explanations rather than invented visual distinctions. The current conversation rows do not render separate skill identity glyphs: identity is conveyed through text/tooltips. The inspected Tauri sidebar and reconciled status labels are English, despite general instructions describing French runtime surfaces.

### Ambiguities requiring owner decisions

1. **Meaning of “skill icons”:** a literal catalogue of distinct skill glyphs would require adding or importing symbols not currently rendered in these rows. Recommendation: explain existing status symbols and the distinction between skill identity and outcome, without adding new skill glyphs or a catalogue from another client.
2. **Boundary of the legend:** “sidebar symbols” could include navigation, PR/MR actions, ticket stage tints and provider marks. Recommendation: cover execution/skill status dots and shapes, including free conversation states; exclude unrelated navigation/action icons and stage colors.

### Reversible choices resolved from the code

- Target Tauri Desktop only, matching the implementation context supplied by the ticket.
- Preserve the inspected surface's English wording; no incidental translation.
- Place the help button outside sidebar-scroll so conversation scrolling does not hide it. It is available whenever the project sidebar is shown, including an empty list; no new help entry in Settings or when the sidebar is hidden.
- Recommend a compact dismissible dialog with a bounded scrollable body, explicit close action, Escape dismissal, contained focus and focus restoration to the help button. Do not navigate or mutate executions when opening/closing it.
- Reuse production symbol classes/rendering and reduced-motion behavior; group explanations into ticket skills and conversations so shared visuals are not assigned contradictory universal meanings.
- Keep existing status logic and sidebar appearance unchanged.
- At implementation time update docs/USER_GUIDE.md and add one user-facing Added entry under CHANGELOG.md [Unreleased]. No changelog entry is needed for this clarification alone.

### Dependencies and verification boundary

UI verification should cover keyboard activation, Escape/close/focus return, a narrow viewport, scroll overflow, reduced motion, unchanged selected conversation and an execution continuing while the legend is open.
