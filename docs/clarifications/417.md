## Round 1 (2026-09-23)

### Restated request and scope

The `web/tests/*.browser.mjs` tests must run as documented from a task
worktree whose path holds `#` (`.tasks/worktrees/#<N>`), or the documented
procedure must work end to end from one. Out of scope: making `npm test` run
the browser tests, and installing Playwright into task worktrees.

### Verified findings

- Reproduced from a scratchpad copy under a `#999` directory: Vite's dependency
  scan reports `UNLOADABLE_DEPENDENCY ... Could not load ../..`, and the fixture
  module fails with `PARSE_ERROR Unexpected JSX expression` because Vite cuts
  its id at `#` and loses the `.tsx` extension. The test exits 1.
- Running through a `#`-free symbolic link does not help on its own: Node and
  Vite resolve the real path, `#` included.
- Running with the Vite root set to a `#`-free symbolic link **and**
  `resolve.preserveSymlinks: true` makes `pr-state.browser.mjs` pass from the
  `#999` copy (with `web/node_modules` itself a symbolic link, as in task
  worktrees).
- Task worktree naming (`internal/agent`): nothing derives a directory name
  from the key; `filepath.Join(root, ".tasks", "worktrees", task.Key)` is built
  inline in `agent_config.go:336`, `agent_operations.go:363` and
  `agent_desktop.go:1172`, with a `<key>-<branch>` fallback at
  `agent_config.go:342`. The path is persisted in `tasks.worktree_path`
  (`internal/db/db.go:2101`), exposed to the web and desktop apps, spelled out
  in `docs/ARCHITECTURE.md`, `docs/REIMPLEMENTATION_GUIDE.md`,
  `docs/UX_COMPONENTS.md`, and hard-coded in Go tests with `#` keys.
  Existing worktrees are found by branch first (`worktreeForBranch`), but
  `agent_desktop.go:1172` looks them up by path only.
- Batch worktree names are already `#`-free by construction
  (`web/src/lib/batchPickup.ts`).
- `PLAYWRIGHT_MODULE` given as `../desktop/node_modules/...` resolves from
  `tests/`, and task worktrees have no `desktop/node_modules`, so the
  documented command also needs an absolute path.

### Ambiguities (worst first)

1. **Which option to implement** (the ticket lists three). → Q1.

### Reversible technical choices (settled from the code)

- If option 2 is chosen: one shared helper under `web/tests/` returns the Vite
  root (the checkout itself when its path has no `#`, otherwise a symbolic link
  to the checkout in a fresh temporary directory, so `../../../shared` still
  resolves) and the `preserveSymlinks` setting; every browser test uses it. The
  run instructions name an absolute `PLAYWRIGHT_MODULE`.

### Critical dependencies

Option 1 only: migration of existing worktrees and of recorded
`worktree_path` values, and every tool that computes the path.

### Product questions

1. **Q1 — Which option?** Recommended: **option 2** (harness resolves through a
   `#`-free symbolic link, documented). It fixes every browser test from any
   worktree with a contained, test-only change and no migration. Option 1
   fixes the cause but changes a user-visible path, four Go call sites, the
   persisted `worktree_path` and existing worktrees. Option 3 leaves the tests
   failing by default.

Expected answer from: the owner.

## Round 2 - answers from the owner (2026-09-23)

- **Q1 settled: option 2.** The browser test harness resolves the checkout
  through a `#`-free symbolic link with `resolve.preserveSymlinks`, in one
  helper shared by every `web/tests/*.browser.mjs`, and the run instructions
  are documented (absolute `PLAYWRIGHT_MODULE`).
- Consequences: worktree naming is unchanged, no Go code, no migration, no
  changelog entry (nothing a user sees changes).
- No assumption reversed. No new ambiguity.

### Outcome

Exit condition met: no open product question.
