The incident reports abnormal WebSocket closure at 21:20:18, attempt 27, and a one-minute retry delay. Dependency installations started roughly 28 seconds earlier, but the connection start time is absent: this does not establish the connection lifetime or implicate npm.

Both agent heartbeat and server ping periods are 10 seconds. The server read timeout is 45 seconds and the agent pong write budget is 20 seconds. Existing tests cover earlier keepalive bugs; blindly increasing these values is unsupported by this incident.

Two defects are apparent from the current code, independently of the cause of the transport failure:

1. `logDisconnect` calls any close error with nonempty text a server-directed disconnection. The synthetic abnormal-closure error `1006 / unexpected EOF` meets that condition, although it provides no explicit server close reason. Diagnostics must distinguish absence of a close frame from an intentional close.
2. `connectLoop` resets `attempt` only when `connect` returns nil. A successful connection that later drops returns an error, so repeated losses accumulate attempts even across long healthy sessions. The reported attempt 27 therefore does not prove 27 consecutive connection failures. A recovered connection should not inherit an unrelated history of failures; the precise stability criterion belongs in the later specification.

The server currently waits up to four seconds for a recently disconnected agent when routing an operation. A persistent one-minute client backoff can exceed that grace; widening the server grace is not yet justified.

### Deployment hypothesis and dependencies

The attached infrastructure describes Scaleway Serverless Containers with minimum scale zero and maximum scale one. Its container resource does not explicitly set a request timeout. This is a candidate to investigate, not evidence that the incident used this endpoint or that an ingress timeout caused it.

Scaleway documents a request duration limit of 10 seconds to 60 minutes and defines request timeout as a maximum request lifetime:

- https://www.scaleway.com/en/docs/serverless-containers/reference-content/containers-limitations/
- https://www.scaleway.com/en/docs/serverless-containers/concepts/

These sources do not establish the deployed timeout or this connection's treatment by ingress. Obtain connection timestamps, deployed agent/server builds, and server/container logs around the incident before selecting a root-cause fix. A probe of the default local gateway at `127.0.0.1:8091/health` failed; this does not imply that the actual agent gateway or the exposed Sectile MCP is unavailable.

No migrations or new dependencies are currently indicated. Infrastructure files remain unchanged; any required infrastructure edit needs its own prepared worktree and eventual pull request.
