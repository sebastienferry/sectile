# #115 — Selected task marker full-width highlight

## Request and scope

Extend the selected task highlight background in the desktop application's sidebar so that it spans the full width of the column container (`.local-task`), completely enclosing the task ID (link), task description, and status indicator.
Backend execution orchestration, remote web interface views, task execution queue styling, and modifying child interactive click actions are out of scope.

## Evidence

- Verified GitHub issue #115 (https://github.com/sebastienferry/sectile/issues/115):
  - Component: Desktop app
  - Description: Selected task marker (highlight background) should be the widht of the column, surrounding the task ID (link) + description + status
- Read `desktop/src/main.js`, `desktop/src/style.css`, `desktop/tests/task-order-render.ui.cjs`, and `desktop/tests/console.ui.cjs`.
- Currently, `main.js` marks `.run` with `button.className = 'run ' + (executions.some(...) ? 'selected' : '')` while `.local-task` remains without a `selected` class.
- In `style.css`, `.project-group .local-task .run.selected { background: #203033; }` styles only the inner `.run` button, leaving `.task-number` (task ID link) and trailing controls unhighlighted outside the selected marker.

## Ambiguities and decisions

1. **Class placement and visual container**: Should `.local-task` receive the `.selected` class?
   - Decision: Yes. Marking `.local-task` with `.selected` allows styling the entire row across the full column width with `background: #203033` and `border-radius: 8px`, surrounding task ID, description, and status indicator.
2. **Backward compatibility for tests**: Should `.run` keep the `.selected` class?
   - Decision: Yes. UI tests such as `task-order-render.ui.cjs` assert `page.locator('.run.selected')`. Retaining `.selected` on `.run` while setting `.local-task .run.selected { background: transparent; }` maintains full test compatibility while delegating background styling cleanly to `.local-task.selected`.
3. **Interactive control boundaries**: Does the full-width background alter click targets or event handling?
   - Decision: No. Clicking `.task-number` continues to open the task in TaskFlow; clicking `.run` selects the execution console; clicking `.task-archive` or `.task-menu` continues their respective actions.

## Critical dependencies

None. Changes are isolated to the Electron desktop application (`desktop/src/main.js` and `desktop/src/style.css`).

## Questions

None blocking. Requirements and visual intent are unambiguous.

## Settled assumptions

The selected task row container (`.local-task`) will receive the `selected` class whenever any of its executions is selected. The highlight background (`#203033`) will apply to `.local-task.selected` across the full column width with `border-radius: 8px`. `.run` retains `selected` for locator compatibility with transparent background.
