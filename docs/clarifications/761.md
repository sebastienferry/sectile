# Clarification #761 - Desktop: Open terminal

Ticket: https://github.com/sebastienferry/sectile/issues/761
Branch: `feat/761`

## Round 1 - initial report (2026-10-06)

### Request

Add an entry to the project's "…" menu in the Sectile Desktop sidebar that opens
a terminal on the project's main working directory (the local checkout mapped to
the project on this workstation), so the user can run commands there without
leaving Desktop to find the folder.

Out of scope: terminals on a task worktree or an execution's directory (the
conversation view already has a Terminal button for that), any change to the
web app, and any new terminal setting.

### Code read

- `desktop/src/main.js`: `projectMenu()` (the "…" menu: Open tasks, Show
  execution queue, Group by stage, New task…, Project prompt, Hide from
  sidebar, Project settings…, Remove from desktop); `openAgentConsole()`
  (Project prompt, disabled when the project has no local path); the
  `#detach-terminal` button and `formatTerminalName()`.
- `desktop/src/conversation.js`: the conversation's Terminal button, which
  calls `api.conversationTerminal(runId)`.
- `internal/agent/terminal_directory.go`: `BuildDirectoryTerminal()` and
  `openDirectoryTerminal()`, which open a plain, user-visible terminal window
  on a folder, running the user's own shell, for Ghostty, iTerm, Terminal.app,
  Windows Terminal, cmd, gnome-terminal, kitty, alacritty, x-terminal-emulator
  or a custom command with `{dir}`.
- `internal/agent/agent_discussion_conversation.go`:
  `desktopConversationTerminal()`, the endpoint behind the conversation button.
- `internal/agent/agent_desktop.go`: `resolveTerminalForProject()` (explicit
  agent flag, then the project's terminal setting, then the agent default,
  then detection) and the projects listing, whose `path` comes from
  `localProjectRoot()`.
- `internal/agent/agent_console.go`: `desktopConsole()`, the Project prompt
  endpoint, which resolves the project root the same way.
- `internal/agent/agent_desktop_editor.go`: the open-editor endpoint and its
  capability flag, the pattern for gating a new Desktop action on the agent
  version.

### Ambiguities, worst first

1. **What "side terminal" is.** Two readings lead to different code:
   - (A) a native terminal window (Ghostty, iTerm, Terminal.app, Windows
     Terminal...) opened on the project root, exactly what the conversation's
     Terminal button already does for a run's directory. Small: one agent
     endpoint reusing `openDirectoryTerminal`, one menu item.
   - (B) a shell embedded in Desktop, shown as a new console in the sidebar
     like Project prompt, rendered by the xterm.js view. Larger: a new run kind
     holding a PTY on the user's shell, its lifecycle in the sidebar and the
     history, and Windows hiding rules for the shell it starts.
   Recommended: (A). Product question Q1.

### Dependencies

- A Desktop connected to an older agent must not show an item the agent cannot
  serve: a new capability in `/desktop/status`, as `open-editor` and
  `run-folders-terminals` do.
- None on the server, the database or the trackers.

### Technical choices settled from the code (reversible)

- **Directory:** the project's local root as `localProjectRoot()` resolves it,
  the same folder Project prompt opens in and the menu already shows as
  `project.path`. The agent resolves it from the project ID; the renderer never
  sends a path, following the open-editor rule.
- **Which terminal:** `resolveTerminalForProject()`, so the project's terminal
  setting in Desktop applies, as for the conversation button and "Detach to
  native terminal". No new setting.
- **Availability:** the item is disabled when the project has no local path
  (not cloned, not mapped, or disconnected), like Project prompt, and hidden
  when the connected agent lacks the capability.
- **Placement and label:** right after "Project prompt", labelled
  `Open terminal`, in English like the rest of the menu.
- **Visibility on Windows:** the window is visible on purpose, being a launch
  the user asked to see; the code says so in a comment, as AGENTS.md requires
  for that exception.
- **Failure:** an error (no terminal found, folder gone) is shown with the
  existing Desktop error banner; nothing is retried.
- **Changelog:** user-visible, so one `Added` line under `[Unreleased]`.

### Product questions

- **Q1. Native window or embedded console?** Recommended: (A), a native
  terminal window in the project's configured terminal application, reusing
  the existing launcher. (B), a shell console embedded in Desktop's sidebar,
  is a separate and larger feature that could be a follow-up ticket.
