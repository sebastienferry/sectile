# Clarification: GitHub #676

## Round 1 (2026-10-01)

### Restated request and scope

While talking to Claude in Sectile Desktop, the user can attach another folder of
the workstation without leaving the discussion. The folder joins the project's
attached folders (ADR 0036) and stays there, so this discussion and every later
execution of the project see it.

Out of scope: a server-side folder list (rejected by ADR 0036), the web app (it
has no attached-folder UI and never holds a workstation path, ADR 0003),
detaching a folder from the discussion (the project settings already do it), and
a folder that would only be visible to one discussion.

### Verified findings

- The ticket has a two-line description, no comments and no parent epic.
- "Discussion" names two features in the code:
  - the **ticket discussion**, a per-task PTY session with skill `discuss`
    (`desktop/src/main.js:2620`, native-terminal variant at `main.js:2773`);
  - the experimental **Claude conversation** view without a PTY (ADR 0042,
    `docs/experiments/desktop-conversation.md`), opened per project from
    "Project prompt" when Settings → Appearance → Claude consoles is set to
    Conversation (`internal/agent/agent_console.go:88-104`), or per execution
    from the "Claude chat (test)" button (`main.js:137-150`). Its composer
    (`desktop/src/conversation.js:25-111`) is the only place in Sectile with an
    input box beside the agent's answers.
- Attached folders live on the workstation only, in
  `projectSettings.<projectId>.folders` (`internal/agentconfig/workstation.go:85-98`).
  The agent already attaches and detaches them (`desktopFolders` and
  `attachFolder`, `internal/agent/agent_desktop_repositories.go:138-273`), with
  the right checks (refuses the local checkout, the specifications folder, a
  duplicate; maps a checkout of a declared repository). The project settings
  page offers "Add folder…" with the native directory picker
  (`main.js:2141-2181`, `desktop/electron/main.cjs:354-357, 427-436`).
- **No discussion receives the attached folders today.**
  - The conversation builds `claude -p … [--resume]` with no `--add-dir` and
    no `SECTILE_REPOSITORIES` (`internal/agent/agent_conversation.go:158-176`).
  - The ticket discussion goes through `runner.InteractiveAgentLaunch`
    (`internal/runner/runner.go:1145-1170`), which ignores the `AddDirs`
    computed for it (`internal/agent/agent.go:1188`); it gets only the
    `SECTILE_REPOSITORIES` variable.
  - Free "Project prompt" PTY consoles get neither (`agent_console.go:18-25`).
  - Skill runs do get `--add-dir` (`internal/agent/agent_config.go:474-495, 576-600`).
- Each conversation turn starts a new `claude -p --resume <session>` process
  (`agent_conversation.go:206-324`), so a folder attached between two turns can
  be given to the next turn with no restart. A PTY session would need a
  relaunch, or an interactive `/add-dir` that is not persisted.
- Typing `/add-dir` in the conversation composer does nothing useful: in print
  mode a leading `/` is not a slash command (inference, not tested).

### Ambiguities, worst first

1. **Which discussion.** The conversation view and the ticket PTY discussion
   lead to different code: a composer control read at each turn, versus a
   relaunch of a terminal session. See Q1.
2. **Whether the existing attached folders reach discussions.** Adding a folder
   from a discussion is pointless if that discussion does not receive the
   project's folders at all, which is the case today. See Q2.
3. **How the folder is chosen.** A button with the native picker, drag and drop
   onto the composer, or a typed `/add-dir <path>`. See Q3.

### Resolved technical choices (reversible)

- Persistence reuses the existing agent endpoint (`POST` attached folders) and
  its checks; nothing is added to the server or the database. "Stays" in the
  ticket is read as "written to the project's attached folders", per ADR 0036.
- A conversation re-reads the project's attached folders at each turn and passes
  `--add-dir` for each present one, plus `SECTILE_REPOSITORIES`, as
  `prepare_repository_worktree` already re-reads the settings at each call.
- The composer shows the result of the attach (added, mapped as a repository,
  refused and why) in its status line, in French like the rest of the
  interface. The agent is not sent an extra message: `--add-dir` is enough.
- A folder refused by `attachFolder` (duplicate, the checkout itself, the
  specifications folder) is not attached and the reason is shown.

### Critical dependencies

- Local agent with the `attached-folders` and `claude-conversation`
  capabilities; no migration, no server change, no external service.
- The conversation view is experimental and opt-in (ADR 0042, "Proposed (test
  branch only)"); the feature inherits that status unless Q1 extends it to the
  PTY discussion.
- `feat/676` was created from `feat/desktop-conversation-test`, not from
  `origin/main`, and carries four commits main does not have. The conversation
  files are identical on both; the implementation stage should merge
  `origin/main` first.

### Product questions

1. **Which discussion gets the "Add folder" control?**
   - (a) The Claude conversation view only. **Recommended**: it has a
     composer, and the next turn sees the folder with no restart.
   - (b) The conversation view and the ticket PTY discussion, which would offer
     to relaunch the session so it sees the folder.
   - (c) The ticket PTY discussion only.
2. **Should discussions also receive the folders already attached to the
   project?**
   - (a) Yes, for the conversation view (and for the ticket discussion and free
     consoles at launch). **Recommended**: the settings page says the folders are
     "handed to every execution of this project", and today discussions are the
     exception.
   - (b) No, only the folder added from the discussion.
3. **How is the folder chosen?**
   - (a) A button in the composer that opens the native directory picker, like
     "Add folder…" in the project settings. **Recommended**.
   - (b) The same button, plus drag and drop of a folder onto the composer.
   - (c) A typed `/add-dir <path>` command intercepted by Sectile.

## Round 2 - answers from the owner (2026-10-01)

### Answers

1. **Which discussion:** (b) the Claude conversation view **and** the ticket
   PTY discussion. This reverses the Round 1 recommendation (conversation only).
2. **Folders already attached:** (a) yes, everywhere. The conversation receives
   them at each turn; the ticket discussion and the free "Project prompt"
   consoles receive them at launch, as `--add-dir` (and `SECTILE_REPOSITORIES`
   for the consoles, which lack it today).
3. **How the folder is chosen:** (a) a button that opens the native directory
   picker, like "Add folder…" in the project settings. No drag and drop, no
   intercepted `/add-dir` in the conversation composer.

### Settled decisions

- The conversation composer gets an add-folder button. The folder is attached
  to the project through the existing agent endpoint and is given to the next
  turn with `--add-dir`; no restart.
- The ticket PTY discussion gets the same button, in its execution toolbar
  since it has no composer.
- Every launch of a ticket discussion and of a free console passes `--add-dir`
  for the project's present attached folders, for engines that accept it
  (Claude Code and Codex, `internal/agent/agent_config.go:474-495`).
- The settled scope and out-of-scope list of Round 1 still hold, except that
  the PTY discussion is now in scope.

### New ambiguity

A PTY session is already running when the folder is added, and its command line
cannot change. How the running session learns about the folder leads to
different code. See Q4.

### Product questions

4. **What happens to a running ticket discussion when a folder is added from
   it?**
   - (a) Sectile types `/add-dir <path>` into the session for the user, so
     Claude sees the folder at once without restarting; the folder is also
     attached to the project for later launches. **Recommended**: no lost
     context. It needs Claude to be at its prompt, and works only for an engine
     with an interactive `/add-dir` (Claude Code); for another engine the
     folder is attached and the status says it applies at the next launch.
   - (b) Sectile offers to relaunch the discussion so it starts with the new
     `--add-dir`; the conversation in progress is lost unless the engine can
     resume it.
   - (c) The folder is attached only; the status line says it will be seen at
     the next launch of the discussion.

## Round 3 - answers from the owner (2026-10-01)

### Answers

4. **Running ticket discussion:** (a) when a folder is added from a running
   PTY discussion, Sectile types `/add-dir <path>` into the session, so Claude
   sees the folder at once and keeps its context. The folder is also attached
   to the project for later launches.

The owner confirmed that the clarification is satisfactory. No product question
remains open.

### Settled decisions

- The `/add-dir` line is written to the PTY only for Claude Code. For another
  engine the folder is attached and the status says it applies at the next
  launch of the discussion.
- Claude must be at its prompt to read the line. How Sectile detects that, or
  whether it simply writes the line and lets Claude queue it, is a reversible
  technical choice left to the specification.
- A path with spaces or special characters is quoted for the Claude prompt;
  the exact quoting is a specification detail.
- If attaching fails (duplicate, the checkout itself, the specifications
  folder), nothing is typed into the session and the reason is shown.

### Settled scope

- **Conversation view:** an add-folder button in the composer opens the native
  directory picker, attaches the folder to the project through the existing
  agent endpoint, and the next turn runs with `--add-dir` for every present
  attached folder plus `SECTILE_REPOSITORIES`.
- **Ticket PTY discussion:** the same button in its execution toolbar attaches
  the folder and, for Claude Code, types `/add-dir <path>` into the session.
- **Launches:** ticket discussions and free "Project prompt" consoles start
  with `--add-dir` for the project's present attached folders, for engines that
  accept it (Claude Code, Codex), and free consoles get `SECTILE_REPOSITORIES`.
- **Out of scope:** a server-side folder list, the web app, detaching from a
  discussion, a folder visible to one discussion only, drag and drop, and an
  intercepted `/add-dir` in the conversation composer.
- **Changelog:** the change is visible to users, so the pull request adds a line
  under `## [Unreleased]`.
