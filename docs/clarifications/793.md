# Clarification Report — #793: Refresh the open board and list after a project's trackers or label change

## 1. Request Restatement & Scope

When saving a project in `ProjectModal` (`PUT /api/projects/:id`), changes to the project's trackers (added, removed, or reordered) or its label change which tickets belong to the project (#741), so the open board, list, and filter facets must immediately refresh without requiring a full page reload. Unrelated project mutations that do not alter ticket membership (such as sprint metadata edits from `SprintTimelineView`) and server-side membership queries (which already return the updated ticket list and count) are out of scope.

- `web/src/context/AppContext.tsx` (`updateProject`, `deleteProject`, `toggleProjectBookmark`, `updateBoardView`, `fetchTasks`, `fetchTaskFacets`, `filteredTasks`)
- `web/src/components/ProjectModal.tsx` (`handleSubmit`)

- `web/tests/projectTrackers.test.mjs` and `web/tests/taskIdentity.test.mjs`

## 3. Ambiguities

None that require product input.

## 4. Critical Dependencies

None. `GET /api/tasks` and `GET /api/tasks/facets` already reflect the updated project tracker and label selection as soon as `PUT /api/projects/:id` commits.

## 5. Settled Technical Decisions

1. **Refresh trigger in `updateProject`**: When `updateProject` completes `PUT /api/projects/:id` and `fetchProjects()`, if the payload carries `trackers` or `label` and the updated project is part of the active board scope (the selected project, the `'all'` scope, or the active saved board view's `projectIds`), call `fetchTasks()` and `fetchTaskFacets()`.
2. **Multi-project membership in `tasksInProject`**: Ensure `tasksInProject` (`web/src/lib/taskIdentity.ts`) checks `task.projectIds` (falling back to `[task.projectId]`) so tickets belonging to multiple projects are retained in both single-project and bookmarked `'all'` scopes.
