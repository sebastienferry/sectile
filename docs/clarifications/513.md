## Round 1 (2026-09-26)

### Restated request and scope

In the Sectile Desktop sidebar, each local task row ends with a `…` button that
opens a dialog of actions; replace it with a single pencil button that renames
the task locally, since the other actions are already reachable elsewhere. The
project-level `…` menu, the `…` menu of the ticket list in the main panel, the
row's archive button and the rename semantics (a local, per-workstation name
that the tracker title never overwrites) are out of scope.

### Files read

- `desktop/src/main.js`: the sidebar task row (around line 544, `.task-menu`),
  `taskMenu()` (around line 2433), `requestArchive()`, the toolbar wiring of
  `#rerun` and `#detach-terminal` (lines 579-584 and 649-665), the ticket-list
  `…` menu (`.ticket-more`, around line 2188).
- `desktop/src/style.css`: `.task-menu` and `.task-archive` hover rules
  (lines 174-184).
- Tests that drive the task menu: `desktop/tests/task-header.ui.cjs`,
  `desktop/tests/console.ui.cjs`, `desktop/tests/pr-display.ui.cjs`; tests that
  click a *Relaunch* button: `skill-mode.ui.cjs`, `free-console.ui.cjs`,
  `console.ui.cjs`.

### Verified findings

The `…` dialog of a task row (`taskMenu`) offers four actions. Each is checked
against the rest of the interface:

| Action in the `…` dialog | Available elsewhere | Where |
| --- | --- | --- |
| Relaunch | yes | `#rerun` in the main panel toolbar, for the selected task, shown once its execution has finished |
| Detach to native terminal | yes | `#detach-terminal` in the toolbar, for the selected running execution |
| Archive | yes | the archive button already on the row (`.task-archive`) |
| Rename locally | **no** | only in this dialog |

The ticket's premise holds: renaming is the only action the dialog alone
provides. One behavioural consequence: *Relaunch* and *Detach* from the dialog
act on a row without selecting it; after the change the task must be selected
first, then the toolbar button is used. This is the intent of the ticket ("the
rest is available on the main content panel").

The rename stores `localTasks[taskKey].name` (max 120 characters, empty value
refused) and re-renders; the tracker title never overrides it
(`task-header.ui.cjs` checks this). This behaviour is kept as is.

### Ambiguities (worst first)

1. **How the pencil renames.** Inline editing in the sidebar row, or a dialog
   holding only the name field. The two lead to different code and different
   tests. Product question Q1 below.
2. **Which rows get the pencil.** Today every row, including free consoles and
   macro runs, has the `…` button, and the rename works on all of them.

### Dependencies

None: no server, API, migration or tracker change. The change is contained in
the desktop renderer, its stylesheet and its UI tests.

### Reversible choices settled from the code

- **Every row keeps a rename entry**, free consoles and macro runs included,
  as the `…` button does today.
- **The pencil follows the row's other buttons**: hidden until the row is
  hovered or focused, always visible on touch (`@media(hover:none)`), placed
  where `…` sits now (after the archive button), with an accessible name
  `Rename <task name>` and a line icon drawn like the archive icon.
- **The rename rules are unchanged**: 120 characters max, an empty value is
  refused, the name is stored locally only. Resetting to the tracker title is
  not added.
- **`taskMenu()` and its dialog are removed**, together with the dialog's
  *Relaunch*, *Detach* and *Archive* buttons. The UI tests that go through
  `Actions for …` are rewritten against the pencil; those that click
  *Relaunch* are pointed at the toolbar's `#rerun`.
- **Changelog**: the change is visible to users, so a `Changed` line goes under
  `## [Unreleased]`.

### Product questions

- **Q1. How should the pencil rename the task?**
  - *(Recommended)* **Inline in the row**: the title becomes a text field in
    place, Enter or leaving the field saves, Escape cancels. Fewest clicks,
    and consistent with the ticket's wish to lighten the row.
  - **Dialog**: the pencil opens the existing dialog, reduced to the name
    field and its *Rename locally* button.
