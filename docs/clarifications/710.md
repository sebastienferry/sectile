# Clarification #710 - Desktop: pick the changed file from a drop-down

## Round 1 (2026-10-02)

### Restatement

In Sectile Desktop's **Changes** panel, the changed files of the selected
execution are shown as a vertical stack of buttons (`.diff-files`), beside the
diff in the full view and above it, capped at 150 px, in the split view. The
change replaces that stack with a single drop-down that lists the same files
and selects the one whose diff is shown, so the diff gets the panel's full
width and no longer competes with a long file list for height.

Out of scope: the content and order of the file list returned by the agent
(`api.gitDiff`), the diff and Markdown rendering of the selected file, the
console/changes split, the web app (it has no Changes panel), and new
navigation such as previous/next file buttons or a file filter.

### Code read

- `desktop/src/gitDiff.js:12`: the panel markup, with
  `<nav class="diff-files" aria-label="Changed files">` beside `.diff-detail`
  inside `.diff-body`.
- `desktop/src/gitDiff.js:32-48`: `showFile` marks the selected button with
  `aria-pressed`; `render` builds one button per file, labelled
  `[oldPath → ]path · status`, and keeps the selection across a refresh when
  the path still exists, else falls back to the first file.
- `desktop/src/gitDiff.js:19,94`: `clear` and `select` empty the list when the
  result goes away or another execution is selected.
- `desktop/src/style.css:276-287`: `.diff-body` is a two-column grid
  (`minmax(150px,25%)` for the list), collapsed to a block in `.split` and
  below 750 px; `.diff-files` scrolls at `65vh` or `150px`.
- `desktop/src/main.js:55,726`: `#execution-history`, the toolbar's existing
  native `<select>`, the precedent for a drop-down in this window.
- `desktop/tests/git-diff.ui.cjs:52-54` and
  `desktop/tests/markdown-view.ui.cjs:74,130`: the UI tests select files
  through `.diff-files button` and the button role; they move to the
  drop-down.

### Ambiguities (worst first)

1. **Drop-down everywhere, or only where the list is cramped (split view,
   narrow window).** Two readings give different layouts. Settled: everywhere.
   The ticket asks for a drop-down "rather than a list", and one control keeps
   a single code path and a single set of tests; the two-column grid of
   `.diff-body` goes away.
2. **Native `<select>` or a custom popover.** A native select is keyboard and
   screen-reader accessible for free, matches `#execution-history`, and is what
   Electron draws natively on each OS. Settled: native `<select>`, labelled
   "Changed file".
3. **What an option says.** Settled: the same text as today's button,
   `[oldPath → ]path · status`, so nothing a user reads changes. Line counts
   stay in `.diff-file-info` under it.
4. **Where it sits.** Settled: on its own row between `.diff-summary` and the
   diff, full width, the long paths truncated by the select itself; the
   `Rendered` toggle stays with the diff.

### Dependencies

None: no agent, API or migration change. Desktop only.

### Settled technical choices

- Selection behaviour is unchanged: first file by default, kept across
  **Refresh** while the path still exists, reset when another execution is
  selected; `change` on the select calls `showFile`.
- With no changed files (clean worktree, error), the select is hidden rather
  than shown empty, as the list is empty today.
- The tests in `git-diff.ui.cjs` and `markdown-view.ui.cjs` select through
  the drop-down (`selectOption`) and assert its value instead of
  `aria-pressed`.
- `CHANGELOG.md` gets a `Changed` line under `[Unreleased]`: the change is
  visible to users.
