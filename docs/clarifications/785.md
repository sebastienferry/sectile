## Round 1 (2026-10-07)

### Restated request and scope

The ticket, titled "Desktop Claude Chat", asks to remove the **Claude chat (test)** button of the Desktop execution toolbar when the selected execution is a terminal session running Claude. The conversation view itself, the Codex conversation flow, the Appearance setting and the agent are out of scope: only when the button is offered changes.

### Files read and existing behavior

- `desktop/src/main.js:180-193`: the button is created once, placed before **Save log**, and calls `api.createConversation(selected)` to start an independent conversation in the selected execution's directory.
- `desktop/src/main.js:819-820`: its label is **Codex chat (test)** when the selected run's provider is `codex`, **Claude chat (test)** otherwise. It is shown only when the console view setting is `conversation`, the selected run has a `directory`, the run is not itself a conversation, and the local agent is connected. Run status is not considered, so it is shown on a running PTY session as well as on a finished one, including a run detached to the native terminal (`externalTerminal`).
- `desktop/src/main.js:854-868`: the detach button and the "Active in <terminal>" badge, the existing pattern that already distinguishes running and detached terminal sessions.
- `desktop/tests/conversation.ui.cjs:55` and `desktop/tests/console.ui.cjs:63`: assert the button is absent in their scenarios; no test asserts when it is present.
- `README.md:216-221`, `desktop/README.md:7-9`, `docs/experiments/desktop-conversation.md:20-21`: document the button as appearing "for an execution with a local directory".
- History: introduced by #650 (opt-in conversation view), relabelled per provider by #783, touched by #771.

### Ambiguities, worst first

1. **Which terminal sessions lose the button.** The button already never appears on a conversation, so it only ever appears on terminal (PTY) executions. Three readings give different code:
   - (a) hide it while the selected terminal execution is **running** (live or detached to the native terminal), and keep it once the run has ended, to follow up in the same directory;
   - (b) hide it on every terminal execution whose engine is **Claude**, running or not (it would remain only on non-Claude terminal runs);
   - (c) remove the button altogether, together with its documentation.
2. **Codex.** Whether a running Codex terminal session (**Codex chat (test)**) follows the same rule as a Claude one, or the ticket is strictly about Claude.

### Critical dependencies

None: the change is confined to the Desktop renderer (`desktop/src/main.js`), its UI tests and the three documentation passages above. No agent capability, API, migration or tracker change is involved. Desktop UI tests need `npx vite build` first and run unsandboxed.

### Reversible technical choices from conventions

- "Running" means `status==='running'`, which covers a run waiting for its owner and a run detached to the native terminal; a `queued` run has no session yet and is treated as not running unless the owner says otherwise.
- The rule is added to the existing `conversationButton.hidden` expression, recomputed on every `render()`, so the button reappears without reselection when the run ends.
- A UI test asserts the button is hidden on a running terminal execution and, if reading (a) is chosen, shown again once it has finished.
- The README passages are updated to say when the button appears; a CHANGELOG line goes under `## [Unreleased]` since the change is visible.

### Product questions

1. **Scope of "terminal session".** Recommended: (a), hide the button while the selected terminal execution is running and keep it on a finished one. Starting a second agent in a worktree where Claude is still working risks concurrent edits, while a finished run is where a follow-up chat is useful.
2. **Engines.** Recommended: apply the rule to every running terminal session, Codex included, since the concurrent-edit concern does not depend on the engine.
