## Restated request and scope

Show the changes in the task's current local worktree or branch against an identifiable baseline inside TaskFlow. Treat this as a read-only inspection feature; editing, staging, committing, merging, and a general Git history browser are outside the assumed scope.

## Verified findings

- The ticket has a short description, no comments, and no parent epic returned by TaskFlow.
- Accepted ADR 0003 explicitly removes local branch, diff, worktree, and editor controls from the web app. Desktop is the established home for this feature.
- Desktop already selects executions, displays their actual directory, and calls the authenticated local agent through a narrow Electron IPC bridge. It has no diff control in the inspected renderer or bridge.
- The local agent records execution directories. Worktree preparation can reuse the main checkout when the assigned branch is already there, so a viewer must not assume every task lives under `.tasks/worktrees/<key>`.
- The legacy server endpoint `GET /api/tasks/{id}/git-diff` invokes server-side repository resolution. It does not inspect a separate agent's local checkout.
- The existing runner chooses local `main`, then `master`, then `HEAD~1`. It concatenates committed and working-tree patches, which can duplicate a file and misrepresent net changes and totals. Empty comparisons fall back to a two-dot comparison and finally the last commit, so an unchanged task can display unrelated changes. Untracked files are omitted; whitespace splitting also makes unusual paths problematic.
- Older UX documentation describes a GitDiffModal, but no current source file with that name was found. ADR 0003 takes precedence over that historical description.

## Resolved decisions

1. **Baseline:** The user confirmed the common ancestor of the task branch and the repository default branch. Compare against that ancestor to show the task's contribution.
2. **Contents:** The user confirmed inclusion of committed, staged, unstaged, and non-ignored untracked files. Show the current net worktree state against the baseline, representing untracked files as additions.
3. **App location:** TaskFlow Desktop, following accepted ADR 0003 and the scope communicated to the user.

## Questions

None remain. The user answered “1. common ancestor. 2. yes” to the two outstanding questions.

## Settled scope and explicit assumptions

- Reuse the assigned worktree and branch. This clarification does not modify production code or begin specification.
- Default to a Desktop entry point for the selected task/execution and read-only local-agent access, following existing IPC and authentication boundaries.
- Show the actual branch, baseline, changed files, additions/deletions, and a selectable unified textual diff. This presentation follows the historical inspector convention and is reversible.
- Read the actual assigned checkout without creating a worktree, switching branches, or changing files. Missing directories, branch mismatches, or unavailable baselines should produce an explicit unavailable state instead of inspecting an unrelated checkout.
- An empty comparison should remain empty. Compute one coherent comparison rather than concatenating overlapping patches.
- Assume refresh on opening and an explicit Refresh action for the initial version. Continuous polling and side-by-side display can be decided during specification as reversible presentation choices.
- Assume local Git refs suffice without automatic network fetching. Resolve the repository's configured default branch where available, display the resolved baseline, and report unavailable refs clearly. Exact ref precedence remains a specification detail using the confirmed common-ancestor semantics.
- Binary files and oversized diffs should be identified explicitly rather than silently omitted; limits and presentation can be specified later.

## Critical dependencies

- The local agent, Git executable, mapped repository, existing task checkout, and an available baseline/history are required. A stopped execution can still be inspected if its directory remains available.
- Desktop IPC and a local-agent read endpoint are needed; the legacy server endpoint alone cannot satisfy local execution semantics.
- No external team, service addition, or database migration is identified for the recommended Desktop scope.
- No product decisions block specification. Tests were not run because this stage only inspected code and wrote this report.
