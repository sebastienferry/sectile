# Clarification #915 - Tauri: circular context usage meter in the conversation composer toolbar

Ticket: https://github.com/sebastienferry/sectile/issues/915
Branch: `feat/915`

## Round 1 - initial analysis (2026-11-17)

### Restatement

Show in the Sectile Desktop (Tauri) conversation composer a compact 240° arc
gauge with a percentage label, beside the model selector, that reflects how
much of the model's context window the active conversation uses, with a warning
state and a `/compact` hint above 80%. Out of scope: the Electron desktop app
(`desktop/`), which already has its own ring, the web app, any automatic
compaction, and persisting context usage across agent restarts.

### What the code already does (files read)

- `internal/agent/agent_conversation.go:345` - `GET /desktop/conversation`
  already returns `"context": {"used": <n>, "window": <n>}` whenever the
  conversation's `contextWindow > 0`. The ticket's premise that the payload
  does not expose it is outdated.
- `internal/agent/agent_conversation_test.go:360` - already asserts
  `"context":{"used":42100,"window":200000}` in the snapshot body.
- `internal/agent/agent_conversation.go:791-807` - Claude: `used` comes from
  each main-thread assistant message, `window` from the `result` frame's
  `modelUsage` (so it is known only after the first turn ends).
- `internal/agent/agent_codex_conversation.go:693-694` - Codex: both come from
  `thread/tokenUsage/updated` (`modelContextWindow`).
- `internal/agent/agent_agy_conversation.go:344,399,794` - Antigravity: `used`
  is tracked, the window never is, so no `context` is ever emitted.
- `desktop-tauri/src-tauri/src/agent.rs:1012` - `read_conversation` returns the
  agent JSON as an untyped `Value`: nothing to change on the Rust side.
- `desktop-tauri/src/lib/conversation.ts:20` - `ConversationSnapshot` lacks the
  `context` field.
- `desktop-tauri/src/components/ProjectPrompt.tsx:531` and
  `TurnSettings.tsx` - the composer footer, where the model selector lives.
- `desktop/src/conversation.js:38-47` - the Electron app's existing full-circle
  ring (neighbouring feature: hidden when `!context.window`, warning at `>= 80`).
- `/Users/sferry/Sources/claudian/src/features/chat/composer/toolbar/ContextUsageMeter.ts`
  - visual reference: 16×16 SVG, stroke 2, arc from 150° to 390°, dash offset
  fill, `role="progressbar"`.

### Ambiguities (worst first)

1. **Payload shape.** The ticket asks for flat `contextUsed` / `contextWindow`
   fields; the agent already sends a nested `context: {used, window}` that the
   Electron app consumes. Adding flat duplicates or renaming lead to different
   code.
2. **Window unknown.** The ticket shows the gauge "whenever `contextUsed > 0`",
   but a percentage needs a window. It is unknown for Antigravity always, and
   for Claude during the first turn.
3. **Threshold.** The ticket says "exceeds 80%" (`> 80`); the Electron ring
   uses `>= 80`.
4. **Number format** in the tooltip (`36k / 200k` vs `36,000 / 200,000`).

### Critical dependencies

None: no migration, no new service, no Rust change. Context usage lives only in
the agent's memory, so a restored (read-only after restart) conversation has no
`conversation` object and shows no gauge.

### Settled technical choices (reversible)

- **D1 - Reuse the existing `context: {used, window}` object** rather than add
  flat fields: it is already emitted, tested, and consumed by Electron. The
  TypeScript `ConversationSnapshot` gains `context?: { used: number; window: number }`.
  Acceptance criterion 1 is therefore already met on the Go side; the Go test
  at `agent_conversation_test.go:360` covers serialization, and a Codex-path
  assertion is added if missing. *(Reverses the ticket's literal field names.)*
- **D2 - No Rust change**: `read_conversation` passes the JSON through.
- **D3 - New component** `desktop-tauri/src/components/ContextUsageMeter.tsx`,
  rendered in the composer footer right after the model selector of
  `TurnSettings` (compact mode).
- **D4 - Geometry** copied from the reference: 16×16 viewBox, stroke width 2,
  round caps, 240° arc from 150° to 390°, fill via `stroke-dashoffset`;
  `role="progressbar"` with `aria-valuenow/min/max`.
- **D5 - Percentage** = `round(used * 100 / window)`, clamped to `[0, 100]`.
- **D6 - Warning** when percentage `> 80`, as the ticket states (the Electron
  `>= 80` is left untouched).
- **D7 - Tooltip / accessible label**: `<pct>% · <used> / <window>` with
  `toLocaleString("en-US")` grouping (as in Electron), plus
  ` · Consider /compact` above 80%. English, like the rest of the Tauri UI.
- **D8 - Electron app unchanged.**
- **Tests**: Vitest/Testing Library unit tests for hidden/visible, arc fill and
  the warning state; the existing Go serialization test is kept.
- **Changelog**: one `Added` line under `[Unreleased]` (user-visible).

### Open product question

- **Q1 - When the window is unknown** (Antigravity always, Claude during the
  very first turn), what does the toolbar show?
  - **(Recommended) A** - nothing: the gauge only appears once a window is
    known, as the Electron ring does. Simple, never shows a misleading arc.
  - B - the used token count alone (e.g. `12,400 tokens`) without an arc.
  - C - require the agent to infer a window from a known-model table (adds a
    Go table to maintain per model).

Also to confirm: the reversal of the payload field names (D1).

## Round 2 - answers from the owner (2026-11-17)

Answered interactively by the owner.

### Settled decisions

- **Q1 → A.** When the context window is unknown (Antigravity always, Claude
  during its first turn), the composer shows nothing. The gauge appears only
  when the snapshot carries `context` with `window > 0` and `used > 0`.
- **D1 confirmed.** The existing `context: {used, window}` object of
  `GET /desktop/conversation` is reused; no flat `contextUsed` /
  `contextWindow` fields are added and the Go payload is unchanged.

### Reversed assumptions

- The ticket's premise that the Go payload does not expose context usage is
  dropped: it already does (`agent_conversation.go:345`).
- Acceptance criterion 1 is reworded: *Tauri's `ConversationSnapshot` types the
  existing `context: {used, window}` field, and Go tests keep asserting its
  serialization for the Claude and Codex providers.*
- Acceptance criterion 2 is reworded: *the gauge renders when `context.used > 0`
  and `context.window > 0`, and stays hidden otherwise.*

### Settled scope (final)

Round 1 decisions D2-D8 stand unchanged: Tauri-only `ContextUsageMeter`
component beside the model selector, 16×16 240° arc, rounded and clamped
percentage, warning above 80%, tooltip/accessible label
`<pct>% · <used> / <window>` with a `/compact` hint above 80%, Electron app
untouched, Vitest tests for visibility, fill and warning state, one `Added`
changelog line.

None. The owner confirmed the clarification; the exit condition is met.
