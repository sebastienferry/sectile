# #344 — Technical plan

Behaviour and acceptance criteria live in [`spec.md`](./spec.md). This file records the
implementation choices only.

## Stack and constraints

- Frontend only: React 19 + TypeScript under `web/src`, built by `tsc -b && vite build`,
  linted by `oxlint`, tested by `node --test tests/*.test.mjs`.
- `tsconfig.app.json` runs with `verbatimModuleSyntax`, `noUnusedLocals`,
  `noUnusedParameters` and `erasableSyntaxOnly` — a type-only import must say `import type`.
- No Go code, no database migration, no HTTP route, no shared type.
- `web/package-lock.json` is regenerated with `npm install`, never hand-edited, and its
  `version` field stays `0.1.0` (AGENTS.md §4).
- The `web/tests` suites run **without a build step**: they read source files as text and
  assert on them. The new suite follows that convention.

## Shape of the change

web/package.json            [A] drop "@lobehub/icons": "^5.18.0"

## Decisions

### D1 — One file per mark, not one file holding four

`web/src/components/icons/<Name>.tsx`. Each mark is an independent component with its own
`<title>` and its own path; putting four unrelated brand paths in one module would make
every future addition or removal touch a file four callers import. The directory matches
the flat `web/src/components/` convention already used for every other component.

Rejected: a single `brandIcons.tsx`, and a data-driven `<BrandIcon name="claude" />` taking
the path from a lookup table. The second changes the call sites (`<Claude size={12} />`
becomes `<BrandIcon name="claude" size={12} />`), which FR5 forbids.

### D2 — The props type is shared, the rendering is repeated

`types.ts` exports:

```ts
export type BrandIconProps = Omit<SVGProps<SVGSVGElement>, 'size'> & { size?: string | number }
```

`@lobehub/icons` types its icons as a `ForwardRefExoticComponent` over a hand-picked `Pick`
of ~400 `SVGProps` keys plus `color`, `size` and `title`. That enumeration exists to
generate `.d.ts` files, not to constrain callers; `SVGProps<SVGSVGElement>` is the same
surface, minus the maintenance. `size` is added because SVG has no `size` attribute.

The four components each spell out their own `<svg>` rather than sharing a wrapper
component. A shared wrapper would be one indirection for four call sites and would make the
"copied verbatim from the package" claim harder to check against the source: as written,
each file is readable next to the `Mono.js` it came from.

Rejected: `forwardRef`. React 19 passes `ref` through as a normal prop, no call site takes a
ref to these icons, and `forwardRef` is deprecated in 19.

### D3 — The path data is copied byte for byte

Each `d` attribute, the `viewBox`, `fill`, `fillRule` and the `<title>` text come from
`@lobehub/icons@5.18.0`'s `es/<Name>/components/Mono.js` and `es/<Name>/style.js`
(`TITLE`), read from the installed package. No re-drawing, no minification, no
`svgo` pass — question 5 settled on exact marks, and a byte-identical path is the only
form of that claim a reviewer can verify.

The `xmlns` attribute is kept even though React does not need it for inline SVG: it is in
the package output, and keeping it makes a copied node paste correctly into a standalone
`.svg` file.

### D4 — `style` spreads last, `size` drives both dimensions

```tsx
style={{ flex: 'none', lineHeight: 1, ...style }}
```

verbatim from the package: a caller's `style` wins over the two defaults. `width` and
`height` are both `size`, defaulting to `'1em'`, so an icon with no `size` inherits the
font size — which is what `ProfileModal.tsx` and `ProjectModal.tsx` rely on when they pass
`size={16}` and what the CSS around the other call sites assumes.

`memo` wraps each component, as the package does. These icons render inside `.map()` over
engine lists, so the wrapper is not ceremonial.

### D5 — Call sites change their import line and nothing else

```diff
-import { Antigravity, Claude, OpenAI, Cursor } from '@lobehub/icons'
+import { Antigravity, Claude, OpenAI, Cursor } from './icons'
```

All four files live in `web/src/components/`, so the specifier is `'./icons'` in each. The
named-import shape is preserved exactly, so no JSX moves and the diff on those four files
is one line each.

### D6 — The barrel is `index.ts`, not `index.tsx`

It contains re-exports only, no JSX. `oxlint`'s `react/only-export-components` rule fires on
modules mixing components with other exports; a pure re-export module avoids the question.
`BrandIconProps` is re-exported with `export type` because of `verbatimModuleSyntax`.

### D7 — The test pins the contract as source text

`web/tests/brandIcons.test.mjs`, in the style of `aiModels.short.test.mjs`: it reads the
component sources and the manifests with `readFile` and asserts on them. It covers

1. `web/package.json` no longer declares `@lobehub/icons`;
2. `web/package-lock.json` mentions neither `@lobehub/icons`, `@lobehub/ui`,
   `@emoji-mart/react` nor `antd` — this is the regression guard for the ERESOLVE block,
   since the warning cannot come back while those packages are out of the lockfile;
3. each of the four components carries the `viewBox`, `fill`, `fillRule`, the `'1em'`
   default, the `flex: 'none'` style spread and its own `<title>`;
4. the four call sites import from `./icons` and no file under `web/src` mentions
   `@lobehub`.

Rejected: a DOM rendering test. `web/` has no jsdom, no react testing library and no
browser runner wired into `npm test` (`condensed-card.browser.mjs` is not in the
`tests/*.test.mjs` glob's default run path for assertions of this kind), and adding one
to prove an SVG has a `viewBox` would cost more dependency surface than the ticket removes.
The path data is verified by comparison against the package output at implementation time
and pinned by the text assertions afterwards.

### D8 — The lockfile is regenerated, not surgically edited

`cd web && npm install` after editing `package.json`, then verify `version` is still
`0.1.0` and that the removed packages are gone. `npm ci` is then re-run from a deleted
`node_modules` to produce the acceptance evidence for US1.

### D9 — No `CHANGELOG.md` entry

`CHANGELOG.md` says of itself that it is "written for the people who use Sectile, not for
the people who wrote it", and AGENTS.md §3 excludes anything a user cannot see. This change
removes a warning from a developer's build log and swaps the provenance of four icons that
render identically: nobody using Sectile can observe it. The file stays untouched, and the
pull request says so rather than leaving the omission to be guessed.

## Verification commands

```bash
cd web && rm -rf node_modules && npm ci   # US1: no ERESOLVE line, exit 0
cd web && npm run build                   # NFR1
cd web && npm run lint                    # NFR2
cd web && npm test                        # NFR3
make build                                # US1, second criterion
```

## Risks

- **A mark renders differently.** Mitigated by D3: the path is copied, not redrawn. The
  residual risk is a typo in the copy, which the test's `viewBox`/`title` assertions do not
  catch — the implementation checks each `d` against the package output before committing.
- **`npm install` bumps unrelated packages.** The lockfile diff is read before committing;
  anything beyond the removal of the `@lobehub` subtree and its peers is reverted.
- **A future contributor reinstalls `@lobehub/icons`.** The lockfile assertion in the test
  suite fails if they do, which is the intent.
