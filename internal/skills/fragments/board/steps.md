1. **Follow the host's publishing rules first.** In the Claude app the page is published with the Artifact tool: do what that tool requires before a publish (loading its design and capabilities guidance, for example), but change nothing in the page beyond its configuration.
2. **Pick the connector.** The board reads Jira with the `searchJiraIssuesUsingJql` tool of the user's Atlassian connector, and moves a ticket to another stage by rewriting its stage label with `editJiraIssue`. Take that connector's display name exactly as the host lists it for pages (in the Claude app, the capabilities guidance maps each connector to its name), never an internal id. No such connector: stop and say the user has to add the Atlassian connector in claude.ai first, and that `/sectile-lite:setup` checks the rest.
3. **Pick the Jira site.** The `site` of `config.json` when it is one the connector reaches. Otherwise list the Atlassian sites the connector reaches. With one Jira site, use its hostname (`example.atlassian.net`). With several, ask which one, once.
4. **Pick the opening query.** The argument when there is one; otherwise the `team.jql` of `config.json` when it exists, which the user may swap for their own tickets; otherwise `assignee = currentUser() AND statusCategory != Done ORDER BY Rank ASC`. The user can change it in the page at any time.
5. **Find the Sprint field.** Jira keeps sprints in a custom field whose id differs per site (`customfield_10020`, `customfield_10181`, ...). Read one issue the query returns, asking the connector for its custom fields, and keep the id of the field named `Sprint`. With none, leave it out: the board then filters on active sprints only.
6. **Fill in the page.** Copy `board.html` to the session's scratch directory and replace `__BOARD_CONFIG__` with one JSON object, `{"connector": "<name>", "site": "<hostname>", "jql": "<query>", "sprintField": "<field id>", "url": "<board link>"}` (without `sprintField` when there is none, and without `url` until the board has one), written with `<` escaped as `<`. Touch nothing else.
7. **Publish, or update.** List the user's artifacts. When one of theirs is titled `Sectile Board`, read it, then publish the filled-in page, with that link as `url`, to its URL so the link stays the same. Otherwise publish a new one, with the icon `board`, then set `url` to the link it got and publish it once more to that link: the page cannot read its own link, and its bookmarks need it. Declare its capabilities as `{"mcp": {"servers": [{"server": "<name>", "tools": ["searchJiraIssuesUsingJql", "editJiraIssue"]}]}, "room": {}, "user": {"scopes": ["profile"]}}`.
8. **Hand it over.** Give the link, and say: the first opening asks to allow the connector; the query field changes what the board shows; to start work from a card, keep a Claude Code session running `/sectile-lite:dispatch` open beside it.
