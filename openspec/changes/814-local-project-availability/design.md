# Technical design

## Existing behavior
`internal/agent/agent.go` discovers projects for all-project mode but only logs local availability. `internal/agent/agent_config.go` supplies `discoverProjects` and `localProjectRoot`; the latter handles local mappings, implicit current-repository fallback, disconnected projects and Git accessibility. `internal/agent/agent_desktop.go` persists mapping/disconnect changes. `internal/handlers/agent_dispatcher.go` currently keeps one connection per user/project slot and replaces it on registration. Pending operations and launch confirmations already retain an `AgentConn` owner. After rebasing the specification onto origin/main, the same project-slot replacement also exists in `agent_cluster.go` and `internal/db/presence.go`; cluster routing and build/operation announcements must be preserved.

## Inventory protocol
Add `project_inventory` to `internal/agentprotocol/message.go`. Payload: `{ "schemaVersion": 1, "projectIds": ["project-id"] }`; `projectIds` is required and an empty array is meaningful. No paths, credentials, command templates, OS or provider metadata. Use authenticated connection user and device identity, never payload-supplied identity. Deduplicate IDs and sort agent output. Limit to 4096 IDs and 1 MiB per inventory message; reject malformed, missing/null arrays and unsupported versions without changing the accepted snapshot or disconnecting the healthy relay. Enforce project visibility using the same server authorization/project discovery rules as the authenticated project list. Reject the complete snapshot if any ID is unauthorized or unknown; report an error without echoing sensitive values. Subsequent valid inventories can recover.

The agent computes the inventory in every connection mode from authorized discovered projects, honoring any explicit project connection scope. All/default modes may report all locally available authorized projects; a concrete project connection reports only that project. Reuse `localProjectRoot` without `allowUninitialized`. Omit individually unavailable projects. If discovery/settings reading fails globally, do not send a partial snapshot: withdraw availability with a valid empty inventory and log locally; retry on the next refresh. Availability is advisory, not an execution guarantee.

Send once after WebSocket registration and before advertising readiness; serialize through the existing link writer. Recompute after successful Desktop mapping/disconnect writes and every 30 seconds to catch external settings edits, folder disappearance and project visibility changes. Coalesce configuration events; do not run Git checks inside the heartbeat writer. Resend the complete inventory each refresh, even unchanged, so it can recover from server rejection. Bound one computation to 10 seconds with context cancellation; abandon work for a closed connection and never write a result through a replacement connection. Reconnection starts with unknown inventory until its first accepted snapshot. Existing heartbeat/keepalive timing stays intact.

## Live registry and compatibility
Separate presence from routing. Store all live connections by authenticated user/device/project connection scope, replacing only the same identity slot. Distinct device IDs coexist. The existing missing-device `unknown` sentinel retains slot replacement semantics for legacy clients. Inventory is stored on each connection, with received/unknown state and acceptance time. An internal `AvailableWorkstations(userID, projectID)` helper returns the deduplicated device set represented by currently registered connections with accepted inventory containing that project. If a device has several connection scopes, availability is the union of its live snapshots; disconnect removes only that connection. Guard updates and removals by exact connection identity. Single-instance inventory stays in memory. Shared-server deployments require an ephemeral presence directory described below; it is not offline history.

Maintain a compatibility routing slot per user/project scope, choosing the most recently registered connection as today. On disconnect of that route, fall back to the newest remaining connection in that slot. Retain exact-project before default/all lookup order. This view must not consult inventory, compare capabilities or choose an agent by advertised availability. Document that legacy dispatch may still fail local validation even when another device appears available. Within one operation resolve once and send to that exact connection; audit `CallOperation`, `Route`, `DispatchAndWait` and forwarded internal requests for lookup-again patterns that could switch devices mid-launch. Pending results, cancellation, PTY and status messages remain bound to their originating connection/run. Presence snapshots and task reconciliation iterate all live connections.

Legacy agents without `project_inventory` remain connected and dispatch-compatible, with inventory unknown. Neither concrete nor wildcard registration is evidence of verified local availability. Old servers ignore the additive message using their existing unknown-message handling; ordinary heartbeat/launch behavior continues.

## Query contract
Extend existing authenticated `GET /api/agent/status` with optional `projectId`. Unfiltered responses retain the existing `agents` shape/fields, restricted to the requesting user, and add per-connection `inventoryState` (`unknown` or `reported`), `availableProjectIds` (empty for unknown) and `inventoryUpdatedAt` (omitted for unknown). With `projectId`, validate project visibility (403 for inaccessible/unknown), return the user's connected agents advertising that project, and add `availableWorkstations`: deduplicated `{deviceId, connectedAt, lastPingAt}` entries sorted by deviceId. Aggregate timestamps as earliest live connect and latest live ping for that device. No cross-user query parameter; derive identity from the existing request auth context, respecting the repository's implicit-user deployment mode. Authorized projects with no availability return empty arrays. Keep consumers tolerant of added fields and never return local paths. Preserve existing build/version/operation announcement fields. Use `webPrincipal(r)` for caller identity and existing project-access helpers; anonymous requests return 401 even if a surrounding middleware is relaxed.

## Shared-server deployments
The current `agent_presence` table has a user/project primary key and represents the compatibility route, not all devices. Keep it for legacy routing and credential-presence consumers; add a migrated `agent_workstation_presence` table for live sessions: connection_id primary key (server-generated UUID), user_id, device_id, project_scope, instance_id, connected_at, last_ping_at, inventory_state, inventory_updated_at, and inventory_json (project IDs only). Add a unique user/device/project_scope identity index and user/instance lookup indexes. Register with an atomic upsert that returns the former session token; close only that replaced session, including on another replica. Never close a distinct device merely because the compatibility route changed. Updates and disconnects compare connection_id and instance_id, so late teardown is harmless.

Write an accepted authorized inventory atomically to this row before exposing it from shared queries; on directory write failure log and keep the prior published state, retrying on refresh. Queries join the existing live `server_instances` cutoff and exclude unregistered or stale sessions; crashed instances are hidden at the existing instance-dead threshold and removed by the existing reaper. Extend single-process/instance cleanup, and credential unlock/presence consumers, so other live devices are not forgotten when one compatibility route ends. No offline availability result or permanent inventory history is introduced. Shared status queries aggregate these rows across instances without forwarding queries through arbitrary project routes. Heartbeats update last_ping_at using existing batching/cadence patterns; do not add a DB write for every relay frame.

Refresh the compatibility `agent_presence` route from the latest registered live session in the project slot. Retain the current local-first `Route` behavior and exact/default/all/empty scope precedence rather than changing workstation selection policy. On route disconnect select the latest remaining slot session; forwarded dispatch must carry its selected connection_id and refuse a replaced session instead of retargeting. Internal rebind/cancel/pull requests address exact session identity. Include connection_id in new internal payloads; legacy requests retain existing slot compatibility. A rolling deployment with old server replicas cannot guarantee simultaneous device retention: document that all replicas must run the new server version before claiming this acceptance criterion; agents can be upgraded independently.

Use the project's next migration version, not a hardcoded number. Cover SQLite migrations and PostgreSQL integration, fake directory interfaces, two-instance rebind/query tests and stale-instance expiry. This technical migration is necessary for existing replicated deployment support and does not expand product scope.

## Target files
- `internal/agentprotocol/message.go`: payload and version definitions.
- `internal/agent/agent.go`, `agent_config.go`, `agent_desktop.go`: collection, per-connection refresh lifecycle and settings events.
- `internal/handlers/agent_dispatcher.go`, `agent_operations.go`, `handlers.go`: separate live/routing registries, exact-connection dispatch and status filtering.
- `internal/handlers/agent_cluster.go`, `internal/db/presence.go`, `migrations.go`, `instances.go`, `credentialunlocks.go`: shared live inventory, route preservation, guarded cleanup and migration.
- Existing agent configuration, disconnect, keepalive, dispatcher, operation, launch, auth and reconnect tests, plus focused inventory tests.
- `docs/contracts/server-agent-v1.md`: protocol, freshness, compatibility and status contract.

## Rejected alternatives
Paths in query strings contradict the local-path contract. Full readiness probing widens the owner's agreed scope. Inventory-based launch selection belongs to another ticket. A database registry unnecessarily persists offline availability. Keeping a single user/project connection cannot represent multiple devices. Reusing wildcard registration as availability produces false positives.

## Risks and validation
Audit every dispatcher consumer because routing and presence now differ. Race-test stale unregister/update and concurrent snapshots. Test real WebSocket interleavings for launch ownership, status isolation and reconnect. Do not infer task readiness from this inventory. No unresolved design or product decisions.
