## Why
Clarification reports must be readable on the ticket before their branch is published. Projects also need an optional way to publish clarification and specification commits.

## What Changes
- Post each clarification round in full, retaining Markdown history.
- Add a default-off pushStageCommits project setting for clarify and specify.
- Preserve managed-run reporting and avoid duplicate final comments.

## Impact
Project persistence, API models, agent configuration and MCP context, project workflow UI, generated skills, documentation and changelog. Other stages and comment headers are out of scope.
